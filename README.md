# どうぶつボンバー — TypeScript 版

動物同士が爆弾で戦う対戦ゲームの TypeScript 実装。家族で遊ぶために作った
ブラウザゲームを、設計から作り直したものです。

**現在の状態：設計完了・実装未着手**（このリポジトリは設計に基づく実装の置き場です）

---

## Why — なぜ作り直すのか

原型はブラウザで動く単一 HTML ファイル（約 4,500 行）です。動くものを最短で
作ることを優先した結果、次の3つが1つの関数の中で混ざっています。

- ゲームのルール（爆弾が何秒で爆発するか、どのマスが壊れるか）
- 画面の描画（Canvas への線と色）
- 実時間（フレーム間の経過ミリ秒）

混ざっていること自体はすぐには困りません。困るのは、後から
「対戦相手を別の端末にしたい」「AI の強さを1万試合で測りたい」と思ったときです。
ルールだけを取り出して動かす方法がないため、どちらも画面と実時間を巻き込んだ
大改造になります。

この版は**同じゲームを、境界を引き直して作る**ことを目的にしています。

## Design Choice — 採用する設計と、その理由

### 1. 7層構造（依存の向きを一方向に固定する）

```text
app          … 配線だけ
platform     … キーボード・フレームループ（ブラウザ API を触ってよい唯一の層）
presentation … 描画・音・HUD
net          … 通信対戦
ai           … CPU の思考
content      … 動物などのデータ
domain       … ゲームのルール（純粋。ブラウザにも実時間にも依存しない）
```

依存は必ず上から下に向かい、逆流させません。

### 2. 境界を「約束」ではなく「コンパイルエラー」にする

`domain/` 専用の TypeScript 設定から DOM の型定義を外します。これにより
`domain/` の中に `document.getElementById(...)` と書くと、レビューを待たずに
その場で型エラーになります。規約を人が守る仕組みではなく、破れない仕組みにする、
という考え方です。

### 3. シミュレーションを決定的にする

同じ初期値と同じ入力列を与えたら、必ず同じ結果になるようにします。
そのために乱数を「ゲームの結果に影響するもの」と「見た目だけのもの」に型で分け、
時間の進み方を固定間隔（1/60秒）に統一します。

決定的であることの見返りは、あとから3つまとめて手に入ります。

- リプレイ（入力列を保存するだけで再現できる）
- 通信対戦（盤面ではなく入力だけを送れば同期する）
- バランス検証（画面を描かずに1万試合を高速で回せる）

### 4. 入力の出どころを1つの窓口にまとめる

人間のキーボード操作も、CPU の判断も、通信で届いた操作も、すべて
「行動の意思（Intent）」という同じ形にしてからゲーム本体に渡します。
ゲーム本体は、その意思が誰から来たのかを知りません。

この窓口があると、将来 CPU の中身を機械学習や強化学習に差し替えるときにも、
ゲーム本体を変更せずに済みます。

## How-to — 動かし方

実装着手後に記載します。予定しているコマンドは以下のとおりです。

```sh
npm install
npm run dev      # 開発サーバ（Vite）
npm run verify   # 型チェック + 層の依存検査 + テスト（Vitest）
npm run build    # 静的ファイルの出力
```
