# 絵と音

この段階の主題は、**移植でよい所と、設計し直す所を分ける**ことです。

原型の絵と音は、手で描いた 1,000 行ほどの canvas の命令と、200 行ほどの Web Audio の命令で
できています。どちらも「どう見えるか・どう聞こえるか」を何度も試して決めた結果なので、
数値を読み解いて設計し直しても、良くなる見込みはありません。中身はほぼそのまま持ってきました。

設計し直したのは、その周り、つまり**いつ・何を・どこへ描くか、いつ鳴らすか**です。

---

## 描く側は、試合の状態を読むだけ

原型の `update()` は、試合を進める処理の途中で音を鳴らし、粒子を出し、画面の札を書き換えていました。
この版では、試合を1 tick 進めると「起きたイベント」の配列が返ってきます。音と粒子は、
それを受け取った側（`Presenter` と `Renderer`）が決めます。

```text
ルールの層  ──イベント──▶  Presenter（音）
            ──状態────▶  Renderer（絵・粒子）
```

描く側が状態を書き換えていないことは、テストで確かめています。CPU どうしの試合を決着まで
毎 tick 描き、描く前後で状態の要約（ハッシュ）が変わらないことを見ます
（`tests/presentation/renderer.test.ts`）。

## 動物の絵は、体型の数字と頭だけ

原型の体の絵は1つの関数が全動物を描き、頭だけが動物ごとに違いました。この形はそのまま使い、
体型（頭・胴・脚の大きさの比、尻尾の形、足先の大きさ）を `src/content/animals.ts` のデータに
移しました。原型にあった「かえるかもぐらなら足先を大きく」という名前での分岐は、
データの `bigFeet` に置き換えています。

6匹目を足すときに書くのは、頭の描き方1つと、体型の数字だけです。

## 見た目の時間は、試合の時刻から作る

点滅や脈打ちの位相は、実時間ではなく試合の tick 数から作ります。止めれば止まり、
倍速にすれば速くなります。

原型から持ってきた計算のうち1つは、この段階で直しました。爆弾の脈打ちが、ラウンドの
経過時間に「爆発が近づくほど上がる周波数」を掛けていたため、経過時間が長いほど1 tick ごとの
位相の飛びが大きくなり、10 秒を過ぎたあたりから脈打ちがばらばらに跳ねていました。
いまは、置いてからの時間で位相を作っています。

## 決着の場面を見せる

ラウンドが決まった tick のうちに次の盤面を作ると、決着をつけた爆発も、倒れる瞬間も、
1度も描かれません。ラウンドが決まったら、前の盤面を止めたまま2秒待ってから次の盤面を
作ります（`GameSession` の `ROUND_INTERMISSION`）。

## ブラウザを開かずに、ブラウザで落ちる誤りを探す

描画のテストは node で走ります。node には canvas が無いので、呼ばれた命令を数えるだけの
偽物（`tests/presentation/fakeCanvas.ts`）を使います。

ただし、何でも受け付ける偽物では、本物のブラウザが例外を出す呼び方を見逃します。
半径が負の円や、0〜1 の外の色の区切りは、ブラウザでは描画の途中で例外になり、画面では
「ある瞬間だけ固まる」形で現れます。偽物にも同じ条件で例外を出させ、そのうえで CPU どうしの
試合を毎 tick 描いています。

音も同じで、Web Audio の偽物は、音量を 0 以下へ指数的に下げる呼び方で例外を出します
（ブラウザと同じ）。

## この段階で残し、あとの段階で足したこと

- 体力や勝ち数の表示（HUD）は、段階10で足しました（[06-画面と設定](06-画面と設定.md)）
- この段階で鳴らしていなかった原型の音のうち、サドンデスの合図は段階8で、残り時間の秒読みは
  段階10で足しました。秒読みはイベントを足さず、残り時間を盤面から計算して鳴らしています
