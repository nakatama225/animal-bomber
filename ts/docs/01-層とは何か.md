# 層とは何か

原型では、ゲームのルール・画面の描画・実時間の3つが1つの関数の中で混ざっていました。
この版では7つの層に分け、**依存を一方向に固定**しています。

```text
app          … 配線だけ。判断を持たない
platform     … キーボード・フレームループ（ブラウザ API を触ってよい唯一の層）
presentation … 描画・音・HUD
net          … 通信対戦
ai           … CPU の思考
content      … 動物などのデータ
domain       … ゲームのルール（何にも依存しない）
```

上の層は下の層を使えます。逆はできません。

---

## なぜ一方向なのか

「整理のため」ではありません。**依存の向きが、その層を単独で動かせるかどうかを決める**からです。

`domain/` が `presentation/` を知らなければ、画面を用意せずに `domain/` を動かせます。
これは次の3つを同時に可能にします。

- 1万試合を画面なしで回してバランスを測る
- 入力の列だけを保存して試合を再現する
- 盤面ではなく操作だけを送って通信対戦する

逆に、ルールの中から描画を1回でも呼んでいると、この3つはすべて
「画面を巻き込んだまま実時間で回す」ことになります。原型がそうでした。

## 層の切り方は「変更理由が2つあるか」で決める

行数では決めていません。300 行を超えたら、まずこの順で疑います。

1. **変更理由が2つあるか** → 分ける
2. 理由は1つなのに長い。データが混ざっていないか → `rules/` か `content/` へ出す
3. 手続きが長いだけ → **ファイルは分けず**、private なメソッドに割る

ファイルを細かく割ること自体は目的ではありません。20 行のファイルが 60 個ある状態は、
6,000 行が1つある状態と同じくらい読めません。

例外にしているのは**手で描いた絵と音の合成**だけです。分けても読みやすさが
増えないためで、この2つは 300 行を超えても1ファイルに置きます。

## 境界を、規約ではなく仕組みにする

「気をつける」形にすると、忙しいときに破られます。破った側に悪意はなく、
たいてい「今だけ」のつもりです。そして残ります。

この実装では3つの仕組みを重ねています。役割が少しずつ違います。

### 1. 型検査 — ブラウザ API を止める

[`tsconfig.domain.json`](../tsconfig.domain.json) は `src/domain` だけを対象にし、
`lib` から `DOM` を外して `types` を空にしてあります。

```jsonc
"lib": ["ES2022"],
"types": [],
```

これで `domain/` の中に `document.getElementById(...)` と書くと、
レビューを待たずに**その場で型エラー**になります。設定ファイル1つで済み、
新しく覚える記法もありません。

⚠️ 止められるのはここまでです。`Math.random()` と `Date.now()` は ES2022 の
一部なので、この設定では通ってしまいます。

### 2. lint — 決定性を壊す呼び出しを止める

[`eslint.config.js`](../eslint.config.js) が `src/domain/**` にだけ
`no-restricted-properties` を当てています。

| 禁止 | 理由 |
|---|---|
| `Math.random` | 乱数は引数で受け取る。見た目だけの乱数は presentation 層にある |
| `Date.now` / `performance.now` | 時間は tick の回数で数える |
| `Math.sin` / `cos` / `tan` / `atan2` / `exp` / `log` / `pow` | 結果が実行環境で食い違うことが規格上許されている |
| `for...in` | 列挙の順序が保証されない |

`Math.sqrt` と四則演算は**禁じていません**。こちらは正確な丸めが規格で
要求されているため、同じ入力なら環境をまたいでも同じ値になります。

ここを区別せずに「浮動小数点は危ないから固定小数点にする」と進むと、
必要のない大きな複雑さを抱えることになります。

### 3. 依存の検査 — 層の逆流を止める

[`.dependency-cruiser.cjs`](../.dependency-cruiser.cjs) の `forbidden` 配列が、
そのままルール表として読めるようにしてあります。

```js
forbidUpward('domain', ['content', 'ai', 'net', 'presentation', 'platform', 'app']),
forbidUpward('content', ['ai', 'net', 'presentation', 'platform', 'app']),
forbidUpward('ai',      ['net', 'presentation', 'platform', 'app']),
```

型検査が止められるのは「domain がブラウザ API を使うこと」までで、
「domain が ai を import すること」は止められません。そちらをここで止めます。

ESLint の層プラグインを使わなかったのは、独自の記法を1つ覚える対象が
増えるためです。この配列は JavaScript の見た目のまま読めます。

## 依存の向きを図で見る

```sh
npm run graph   # Graphviz が要る
```

`docs/layers.svg` が出ます。矢印がすべて `domain` へ向かっていれば正しい状態です。
設計の説明を文章で書くより、この図を1枚見せるほうが早いことがあります。
