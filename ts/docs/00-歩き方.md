# 歩き方

原型は「動くもの」を最短で作りました。この版は**同じゲームを、境界を引き直して
作り直したもの**です。移植ではありません。

境界を引くと何が起きるかは、あとの段階になって現れます。通信対戦を作る段になって、
すでに書いてある `IntentSource` という1つの窓口に、ネットワークから届いた操作を
流し込むだけで済む。CPU の強さを1万試合で測る段になって、画面を描く部分を
差し替えるだけで済む。

**設計とは、未来の作業量を先に減らしておくことです。** この docs は、
どの判断がどの作業を減らしたのかを、順を追って残すものです。

## 段階ごとの主題

実装は段階に分けて進めています。各段階には**その段階で身につく判断が1つ**あり、
それが次の段階の作業を減らします。

| 段階 | 動くもの | その段階の主題 |
|---|---|---|
| 0 | 骨組み | 境界を、規約ではなく検査で守る |
| 1 | 1人が歩く・直前を再生できる | 固定間隔の時間と、注入された乱数 |
| 2 | 爆弾・誘爆・ブロック破壊 | System への分業。`step()` が順序の一覧になる |
| 3 | アイテム・被弾 | 起きたイベントを戻り値で返す（音と画面を呼ばない） |
| 4 | 2人で遊べる | 操作の出どころを1つの窓口にまとめる |
| 5 | 5匹の動物 | 拡張に開いた形（Strategy）。ぞうの突進で正しさを判定する |
| 6 | CPU | 判断を順序つきの独立した規則に分ける |
| 7 | 絵と音 | 移植でよい所と、設計し直す所の区別 |
| 8 | 葱ボン | 状態を型で表す |
| 9 | 通信対戦 | ロックステップ。窓口を差し替えるだけで済むことの確認 |
| 10 | タイトル・設定 | いちばん面白くないので最後 |

## この実装での約束

3つあります。いずれも**人が気をつけて守る形にしていません**。破ると検査が落ちます。

### ルールの層はブラウザを知らない

`src/domain/` には `document` も `window` も `canvas` も出てきません。
書くと型エラーになります（`tsconfig.domain.json` から DOM の型定義を外してある）。

### ルールの層と CPU は実時間と乱数を自前で取らない

`Math.random()` も `Date.now()` も使いません。書くと lint が落ちます。
乱数は引数として受け取り、時間は tick の回数で数えます。

CPU の思考（`src/ai/`）も同じ検査の対象です。CPU の判断も種から決まる必要があります。
通信対戦では各端末が同じ CPU を動かすので、1台だけ違う乱数を引くと、その端末でだけ
CPU が別の手を指して試合がずれます。

### 依存は逆流しない

下の層が上の層を import すると、依存の検査が落ちます。
ルール表は [`.dependency-cruiser.cjs`](../.dependency-cruiser.cjs) にそのまま書いてあります。

## 検査が効いていることを、どう確かめているか

設定を書いただけでは、それが効いているかは分かりません。設定の書き方を
間違えていても、違反が無ければ検査は緑のまま通ります。**緑のまま通る検査は
何も守っていません。**

そのため [`tests/boundary/guards.test.ts`](../tests/boundary/guards.test.ts) は、
テストの中で次の4つを順に行います。

1. 禁じた書き方を1行だけ含む使い捨てのファイルを、`src/` の下に実際に書き出す
2. 本物の検査コマンド（`tsc` / `eslint` / `depcruise`）を実行する
3. コマンドがエラーで終わること、出力に違反した規則の名前が出ることを確かめる
4. 書き出したファイルを消す

| テスト | 書き出すファイルと中身 | 実行するコマンド | 出力に出るはずの語 |
|---|---|---|---|
| ルールの層でブラウザ API を使うと型検査が落ちる | `src/domain/core/__boundary_probe__.ts` に `document.body.clientWidth` | `tsc -p tsconfig.domain.json` | `document` |
| ルールの層で Math.random を呼ぶと lint が落ちる | 同じファイルに `Math.random()` | `eslint` | `no-restricted-properties` |
| CPU の思考の層で Math.random を呼ぶと lint が落ちる | `src/ai/__boundary_probe__.ts` に `Math.random()` | `eslint` | `no-restricted-properties` |
| CPU の思考の層でブラウザ API を使うと型検査が落ちる | 同じファイルに `window.innerWidth` | `tsc -p tsconfig.domain.json` | `window` |
| ルールの層から上の層を import すると依存の検査が落ちる | `src/domain/core/…` に描画の層を import する1行 | `depcruise` | `domain-は-上の層を使わない` |
| CPU の思考の層から上の層を import すると依存の検査が落ちる | `src/ai/…` に描画の層を import する1行 | `depcruise` | `ai-は-上の層を使わない` |

最初のテストだけは何も書き出さず、同じ3つのコマンドが**エラーなく終わる**ことを
確かめます。これが無いと、上の表のテストが落ちたとき、原因が書き出したファイルなのか、
もともとコードにあった別の違反なのかを区別できません。

## 動かし方

```sh
npm install
npm run dev      # 開発サーバ
npm run verify   # 型検査 + 層の検査 + lint + テスト
npm run graph    # docs/layers.svg に層の図を出す（Graphviz が要る）
```
