# 画面と設定

段階10では、タイトル・動物を選ぶ画面・ルールを決める画面・遊び方の説明と、試合の横に出す板
（時計・名札）、ラウンドの間の幕、通信対戦のロビーを足しました。そのあと、画面を原型（`legacy/animal-bomber.html`。
v4.3.0）に合わせました。起動の幕・タイトル・キャラ選び・ルール・設定とマニュアルと更新履歴・LAN の画面・ロビー・
確認の画面と、試合の画面の横の板（時計・ゲーム速度のつまみ・名札・キーの案内・ツールバー）、ラウンドの幕と優勝の幕、
ポーズの幕、画面の上の通知です。

この段階の主題は**画面に何を出すかと、どう写すかを分けること**です。

原型に合わせるのが方針です（下の「原型に合わせない所」に書いたもののほかは、原型の文・見た目・動きに合わせる）。
画面に出す文の正は Python 版（[py/docs/11-画面と設定](../../py/docs/11-画面と設定.md)）で、Python 版はリポジトリの
文の決まりで書かない語を原型から言い換えてあります。

## 画面の流れ

```text
起動の幕（クリックか、なにかキー。3.2 秒で消える）
  └ タイトル
      ├ 1人 vs CPU×3 ／ 2人 vs CPU×2 ／ 2人タイマン → キャラ選び → ルール →「はじめる」→ 試合
      ├ LAN対戦 → LAN の画面 →「たてる」／「さんかする」→ つなぐ（接続しています…）→ ロビー
      │                                                         └ ホストの「はじめる ▶」→ 試合（全員）
      └ 設定・マニュアル・更新履歴

試合 → 決着で幕
  1台：「つぎのラウンド ▶」→ 次のラウンド ／ 優勝のあと「もういっかい」→ 同じ設定・新しい種の試合
       「⚙ 設定をやりなおす」→ タイトル
  通信対戦：ラウンドの幕は 2 秒で消える ／ 優勝のあと、ホストの「もういっかい」→ 次の試合

URL に ?relay を付けて開く → 起動の幕を出さずに LAN の画面 → すぐつなぐ
```

ページは開き直しません。通信対戦へ移るときも、抜けるときも、同じページのまま画面を替えます（原型と同じ）。

| どこで | 何を | 行き先 |
|---|---|---|
| どの画面でも | 戻る（Escape・Backspace・パッドの B・「← もどる」） | 1つ前の画面（原型の `MENU_BACK`）。タイトルと試合の画面では何もしない |
| ロビー・つないでいる最中の LAN の画面 | 戻る・「← せつぞくを切る」・「← もどる」 | 「せつぞくを切ります。よいですか？」→「せつぞくを切る」で接続を閉じてタイトル。ゲストのロビーにはカーソルで選べる項目が無いので、キーとパッドの B では何も起きない（「← せつぞくを切る」をマウスで押す） |
| LAN の画面 | 「たてる」・「さんかする」 | どちらもページを配った中継（`?relay=名前` で開いたページなら、その中継）につなぐ。番号を受け取るとロビー |
| LAN の画面 | ロビーへ移る前に止まった（断られた・中継に届かなかった） | LAN の画面に留まり、「接続しています…」の行に理由を出す（また押せる） |
| ロビー・通信対戦の試合 | 中継との接続が切れた | タイトルへ戻って「サーバとの接続が切れました」 |
| ロビー（ゲスト） | ホストが抜けた | タイトルへ戻って「ホストとの接続が切れました」 |
| 試合（1台） | P・パッドの Start・「⏸ ポーズ」 | ポーズ（もう一度でやめる） |
| 試合 | ポーズ中（通信対戦ではいつでも）のパッドの Select | 「設定へもどりますか？」→ タイトル |
| 試合 | 横の板の「設定へ」 | タイトル（確認の画面を出さない。原型の注記 L3377-3380）。通信対戦は接続を閉じる |

## 原型に合わせない所

| 所 | 原型 | この版 | 理由 |
|---|---|---|---|
| 通信対戦のラウンドの幕 | ホストがボタンで送る。ゲストには幕が出ない | 全員に幕を出し、決着のあとの待ち（`ROUND_INTERMISSION`＝2 秒）で消える。ボタンは無い | ロックステップでは全端末が同じ tick に次のラウンドへ進む必要がある。ボタンで送ると、押したことを全員に配る約束（中継と Python 版も）を足す必要がある。原型のゲストに幕が出ないのは、ゲストが盤面を進めないホスト権威の作りの結果。1台の試合の幕は原型どおりボタンで送る |
| 通信対戦の優勝の幕のボタン | ホストに「もういっかい」と「⚙ 設定をやりなおす」。ゲストには幕が出ない | ホストに「もういっかい」（ずれたら消す）、全員に「⚙ 設定をやりなおす」 | 全員に幕を出すので、ゲストにも抜ける道を出す（横の板の「設定へ」と同じくタイトルへ戻る） |
| 通信対戦のポーズ・ゲーム速度 | ホストが止める・速める | 出さない（曲も等倍。Python 版と同じ） | 止めたこと・速さを全員へ同じ tick で配る約束が無い。この端末だけ止めると、ほかの端末は入力を待って止まる |
| 通信対戦のキーの案内の「P ポーズ」の行 | 役割を見ずに出す（L5608）。ゲストにも出るが、ゲストが押しても止まらない（L4214） | どの端末にも出さない（1台の試合は原型と同じく出す。`keyHelp.ts`） | 通信対戦ではだれも止められないので、押しても何も起きない行を出さない（原型の `applyRoleUI` の注記と同じ考え。L4196-4199。Python 版と同じ）。パッドの Select の行は、ポーズできない端末として、どの端末にもいつも出す（原型はゲストにだけいつも出し、ホストにはポーズ中だけ出す。L5612） |
| 通信対戦の画面の揺れ | ホストの画面だけ揺れる | 全端末が揺れる | ロックステップでは全員が手元で試合を進めるので、揺れも全員が同じ値で数えられる。原型のゲストが揺れないのは、ホスト権威の作りの結果 |
| ロビーの「人間の人数」 | ホストが 1〜4 を選ぶ | 選ばない。始めた時点でつながっている端末が人間、残りが CPU | 人数を設定に足すと、中継と Python 版の約束も変わる。つながっているのに CPU になる端末の扱いも要る |
| ロビーの CPU の強さの行 | CPU の枠だけ。枠の見出しは「CPU」「🤖」 | いまつながっていない枠（始めたら CPU になる枠）だけ。その枠の見出しは「3P」「⚪ 空き・待機中」のまま（ゲストの読むだけの行も、強さはその枠だけ） | 人間の人数を選ばないので、CPU の枠は「つながっていない枠」で決まる。あとから誰かがつながれば人間になる |
| ロビーと1台のルールの画面の設定 | 同じ設定（勝ち数・時間・サドンデス・CPU の強さ）を2つの画面で分け合う | 分ける（1台は `MenuFlow`、ロビーは `LobbyChoices`） | ロビーの CPU の強さは枠ごと、1台は「CPU の何体目」で、数え方が違う |
| 途中で抜けたプレイヤーの名札と強さ | 「CPU1・（1体目の CPU の強さ）」 | 番号は原型と同じ「CPU1」、強さは試合で実際に使う強さ（枠ごとの強さ）。引き継いだ通知の呼び方は原型と同じく動物の名前 | この版は枠ごとの強さで CPU を動かしている。名札は動きに合わせる |
| ホストが試合の最中に抜けたとき | ゲストは「ホストとの接続が切れました」でタイトルへ戻る | CPU がホストの枠を引き継いで続く（「ホストとの接続が切れました」はロビーで抜けたときだけ）。次の試合は始められない（案内の帯に出す） | ロックステップでは全員が手元で試合を進めるので、ホストが抜けても続けられる |
| CPU の動物の選び方 | 残りの動物から `Math.random` で | 残りの動物から、試合の種から作った乱数で | 同じ種で同じ顔ぶれになり、テストできる（Python 版と同じ） |
| 原型の文の一部の語 | リポジトリの文の決まりで書かない語を含む | Python 版の言い換えに合わせる | リポジトリの文の決まり |
| ロビーへ移る前に止まったとき（断られた・中継に届かなかった） | 何も出さずにタイトルへ戻る（「接続しています…」が残る） | LAN の画面に留まり、「接続しています…」の行に理由を出す（また押せる）。断られた：「前の試合が続いているか、定員いっぱいで入れなかった」。中継に一度もつながらずに閉じた：「中継（ホスト名:ポート）につなげなかった」 | ロックステップの中継には、原型の中継に無い「試合中だから断る」がある。理由を出さないと、断られた端末は押し続ける。文は Python 版の `app/lan.py` と同じ（中継に届かなかったときに Python 版が末尾に添える詳しい理由は、ブラウザの WebSocket が知らせないので添えない） |
| つないでいる最中の LAN の画面 | 中継につながった時点（番号を受け取る前）でロビーへ移る（L3733）。それまでは「たてる」「さんかする」を出したままで、押すたびにもう1本つなぐ（前の接続を閉じない） | 番号を受け取ってからロビーへ移る（それまでは LAN の画面）。「たてる」「さんかする」は出さない（「接続しています…」と「← もどる」だけ）。戻る・パッドの B・「← もどる」は、原型と同じく「せつぞくを切ります。よいですか？」を開く | 中継との接続（`LanMatch`）は1本しか持たない。原型の動きは前の接続が残る不具合。押しても反応しないボタンは出さない（原型の `applyRoleUI` の注記と同じ考え。L4196-4199）。ロビーへ移る時は Python 版と同じ（番号を受け取るまでは、この端末がホストかゲストかが決まらない） |
| タイトルへ戻ったあとの「接続しています…」 | 残る（次に LAN の画面を開いても出ている） | タイトルへ戻るときに消す | 原型の表示の不具合。残すと、つないでいないのに接続中と出る |
| URL の `?relay` | 無い（開いたページのアドレスにつなぐだけ） | 起動の幕を出さずに LAN の画面を開いてすぐつなぐ。`?relay=名前` で開いたページでは「たてる」「さんかする」もその中継へ。値が読めないときは理由を出して止める | 中継が別の Mac にある開発の形を残す（Python 版の `--relay` と同じ、起動してすぐつなぐ口） |
| 通信対戦の案内の帯（入力の待ち・ずれ・試合が終わった） | 無い（ホスト権威なので待ちもずれも無い） | 盤面の下の端に重ね、幕より上に出す（文は Python 版の `lan_status.py`）。窓が低いと（1024×768 など）幕のカードの下の「⚙ 設定をやりなおす」の上半分に帯がかかるが、帯は押したことを受けず（`pointer-events:none`）、下のボタンへ届ける。字は本文の色で 14px に固定し、1行に収まらない狭い盤面では折り返す（Python 版は黄の字で、大きさを盤面の高さに合わせ、1行で切る） | 原型に無いもの。置き場所と文は Python 版に合わせ、幕の間も「もういっかい」の案内を読めるようにした。字の大きさを盤面に合わせるのは、pygame で盤面に描く Python 版の都合 |
| 盤面の canvas の包み | canvas を直に横の板と並べる。並びが `#app` の幅からはみ出す窓（1440×900 など）では、canvas が縦横比から決まる最小の幅まで 2px 縮む（1115px が 1113px） | 案内の帯を重ねるための包み（`.board`）に入れる。縮まず、横の板が 1px 右にずれる。包みに z-index は付けない | 帯を盤面の下の端に重ねるには、盤面と同じ大きさの包みが要る。z-index を付けると包みが重なりの文脈を作り、帯が幕と比べられなくなって幕の下に隠れる |
| 押してすぐ離したキー | 押した瞬間（`pressed`）を毎フレーム忘れる | 入力を tick へ取り込んだあと（通信対戦では送ったあと）にだけ忘れる。1台の試合を止めている間（ポーズ・ラウンドの幕・決まった試合）と試合の外は、原型と同じく毎フレーム忘れる（下の「押してすぐ離したキー」） | この版は1フレームに 0 回以上の tick を進める（0.5 倍・通信対戦の待ち）。毎フレーム忘れると、進めなかったフレームの押しが消える |
| ポーズ中に押し、押したまま再開した爆弾のキー | 置かない（押した瞬間 `pressed` だけを見て、止めている間も毎フレーム忘れる。L3065-3068・L4277） | 再開した最初の tick に置く（押してすぐ離した押しは、止めている間に忘れるので置かない） | 入力は tick ごとにどのボタンを押しているかだけを持つ（操作の記録と通信対戦も同じ形。[04-葱ボンと延長戦](04-葱ボンと延長戦.md) の「葱を撃つボタン」）ので、押した瞬間は試合の側が前の tick と比べて作る。止めている間は tick を進めないので、前の tick は押す前のまま |
| 同じ役のキーを2つ重ねて押したとき | 2つ目でも葱を撃ち、爆弾を置き、技を出す（keydown ごとに押した瞬間をためる） | 2つ目では撃たず、置かず、出さない | 上の行と同じく、入力は tick ごとにどのボタンを押しているかだけを持つ（[04-葱ボンと延長戦](04-葱ボンと延長戦.md) の「葱を撃つボタン」） |
| メニューのキーと P の押した瞬間 | 押していなかったキーで、繰り返しでない keydown（L3065） | 繰り返しでない keydown（押していなかったかは見ない） | 差が出るのは、離したことが届かなかったキーをもう一度押したときだけ（下の「キーボードとゲームパッドでメニューを動かす」の「キーから操作への翻訳」） |
| Option・Command を離したとき | ほかの押しているキーを捨て、キーの繰り返しで押し直させる（L3093-3098） | 同じく捨てる。ただし捨てたキーは、繰り返しで戻っても、もう一度押す（`repeat` でない keydown）まで爆弾と技に数えない。向きは繰り返しで戻す | この版は押した瞬間を試合の側が前の tick と比べて作るので、戻ったキーをそのまま押していることにすると、爆弾を置いたり技を出したりする。原型の注記の2つの狙い（押したままの向きは戻す・勝手に技や爆弾を出さない）を両方満たす |
| ラウンドの始まりに押しているキー | ラウンドを始めるたびに押しているキーを捨て、向きはキーの繰り返しで戻す（`startRound` の `keys.clear`。L4143-4146） | 捨てない。向きのキーを押したまま幕を送ると、次のラウンドの最初の tick から歩く（原型は繰り返しが始まるまで止まっている）。爆弾と技は、押したまま始まっても開始位置で出ない | 写すには、試合を始めるたびにキーボードの状態を変える口が要り、幕を送るときだけでなく「はじめる」にも関わる。Python 版も写していない |
| 幕のボタンの枠が出始めるフレーム | 枠を出したまま幕が出たときは、十字で動かすかマウスを動かすまで幕のボタンに枠を付けない。枠を出していなかったときは、幕を表示した次のフレームから付ける（L4477・L4509・L3637） | パッドを試合に繋ぐ遊び方では、幕が出たフレームから1つ目のボタンに枠を付ける | 見た目だけの違いで、パッドの A とキーの Space・Enter が1つ目のボタンを押すことは変わらない |
| 音の解錠 | 操作の音を鳴らすボタンの中と、試合を始めるとき（`startGame`）に解錠する（`A.init(); A.resume();`） | 操作の音を鳴らす所で解錠するのに加え、キーとクリックのたびにも解錠する。試合を始めるときには解錠しない | 解錠は何度呼んでもよい。試合を始める口（1台の「はじめる」・幕の「もういっかい」・通信対戦の中継からの合図）ごとに呼ぶより、操作の入口でまとめて呼ぶほうが漏れない。パッドだけで遊んでも、ふつうは試合を始めるまでに操作の音を鳴らす項目（タイトルの項目・「さんかする」など）を押すので、解錠してある。例外は URL の `?relay` で開いたゲストで、タイトルも LAN の画面の項目も通らず、ロビーにもパッドで選べる項目が無いので、キーかクリックに触れるまで解錠しない |

### 決めたこと（原型の動きから決めた所と、原型にも設計にも答えが無かった所）

- **通信対戦の接続の段階**：原型と同じ所は、ロビーへ移ったあとに切れたら（試合の最中も）通知を出してタイトルへ戻ること、
  ロビーでホストが抜けたらゲストもタイトルへ戻ることです。この版で決めた所は見分け方です。`LanMatch.stage` が
  「つないでいる・ロビー・試合・ロビーへ移る前に止まった・ロビーへ移ったあとに止まった」を返し、`Shell` が描くたびに見て
  画面を替えます。ロビーへ移ったか（中継から番号を受け取ったか）と、ロビーでホストを見たかは、中継から1通届くたびに控えます
  （番号を受け取った直後に、同じフレームの中で切れても、ロビーへ移ったあととして扱う）。ホストより先に入ったゲストは、
  ホストを見るまで、ホストがいなくても戻しません。`Shell` は、いま持っている接続の段階だけを見ます。抜けたあとの接続から
  閉じたことが遅れて届いても、次につないだ接続や1台の試合に触りません（原型が `NET.disconnect` で `onclose` を外して
  防いでいたこと）
- **中継に届かなかったかの見分け**：WebSocket の `open` が一度も届かずに閉じたら「中継（ホスト名:ポート）につなげなかった」、
  つながったあとに閉じたら「中継との接続が切れた」を出します（`WebSocketLink` が `onClose` に、つながったかを添える）
- **ロビーで選んだもの**：接続をまたいで持ちます（切ってつなぎ直しても、前に選んだ動物とルールのまま）。原型も `CFG` に持ち、
  `backToSetup` で消しません。`Shell` が `LobbyChoices` を1つ持ち、接続ごとに作る `LanMatch` に渡します
- **「せつぞくを切ります。よいですか？」の枠**：キーかパッドで開いたときだけ枠を出し、「やめる」を指します。マウスで
  「← せつぞくを切る」「← もどる」を押したときは出しません（原型の `askDisconnect` は `MENU.on` を立てない。L3381-3383。
  キーとパッドの B は、原型の `MENU.nav` が枠を出してから開く）。「設定へもどりますか？」は原型と同じく、開くといつも枠を出します
- **つないでいる最中に開いた確認の画面**：ロビーへ移ったら畳みます（原型の `showScreen('lobby')` の `closeDialog`）。
  ロビーへ移る前に止まったときも、接続を手放すので畳みます（原型にこの道は無い。タイトルへ戻るので、同じく畳まれる）
- **ページの先頭へ戻す時**：画面を替えたとき（`MenuView.render`）・ロビーへ移ったとき・試合を始めたとき（1台の「はじめる」と
  「もういっかい」、通信対戦の試合が始まったときと次の試合）です（原型の `showScreen` の `window.scrollTo(0,0)`）。「たてる」
  「さんかする」でつなぎ始めたときは戻しません（原型の `joinLan` は画面を替えない）
- **1台の試合を始めたときの曲の速さ**：始めるたびに、曲の速さをいまのゲームの速さ（つまみの倍率）に合わせます。通信対戦は
  曲を等倍にするので、合わせないと、そのあとの1台の試合で盤面はつまみの倍率なのに曲は等倍のまま鳴ります（Python 版と同じ）
- **抜けたプレイヤーを CPU が引き継いだ通知**：名札の一覧で人間から CPU に替わった tick に、「（動物の名前） の回線が切れた
  → CPU が引き継ぐ」を出し、名札をすぐ作り直します（原型 L3793。Python 版の `_watch_roster` と同じ見分け方）

## 何を出すかは純粋な関数、写すのは薄い層

| | 置き場所 | 中身 | 確認の方法 |
|---|---|---|---|
| 何を出すか | `src/presentation/hud/`・`src/presentation/menu/` | 試合の状態から文と値を作る関数と、画面の流れを持つクラス | node のテスト |
| どう写すか | `src/platform/ui/` | 値を要素に写し、押されたら上を呼ぶ。固定の文言と、どの行を並べるか | 代わりの DOM（happy-dom）のテスト |
| どこに置くか | `index.html`・`src/style.css` | 要素の並びと見た目 | 目で見る（原型と並べて見比べる） |

たとえば名札の中身（「❤️❤️🖤」「★☆☆」「CPU1・ふつう」）は `describePlayers` が作ります。
盤面・勝ち数・設定・誰が操作しているかを受け取って、文を返すだけです。要素に写すのは
`SidePanel` で、いつ作り直すかは `PanelRefresh`（`src/presentation/hud/panelRefresh.ts`）が決めます
（下の「試合の画面」）。中身が前と同じなら要素に触れません。

画面の流れ（タイトル → 動物 → ルール、LAN の画面、もどる）も `MenuFlow` が持ち、画面には何も書きません。
写す側（`MenuView`）は、押されたら `MenuFlow` を呼んで写し直すだけです。

分けてあるので、表示の誤り（ハートの数・勝ち星・ラウンドの番号）はブラウザを開かずに見つかります。

### ブラウザを開かずに、画面を押してみる

写す側も、代わりの DOM（happy-dom）の上で組み立てて、クリックを発生させて確認しています。
タイトルで「2人 vs CPU×2」を押し、2P の動物を選び、勝ち数を変えて「はじめる」を押すと、
選んだとおりの設定が届く、というところまでがテストになっています（`tests/ui/`）。通信対戦も、偽の中継を差して、
タイトルの「LAN対戦」→「たてる」→ ロビー → 試合 →「設定へ」でタイトル → もう一度つなぐ、までを同じページの上で通します。

テストのファイルの先頭に `// @vitest-environment happy-dom` と書いたものだけが、代わりの DOM の上で
走ります。ほかのテストは node のままです。

⚠️ 代わりの DOM で確認できるのは、要素ができること・押したら呼ばれることまでです。
見た目（CSS の適用・並び・文字のはみ出し）は確認できません。

## キーボードとゲームパッドでメニューを動かす

タイトル・キャラ選び・ルールを決める画面・設定とマニュアルと更新履歴・LAN の画面・通信対戦のロビー・確認の画面は、
キーボードとゲームパッドでも動かせます（原型と同じ）。ラウンドの幕と優勝の幕のボタンは、パッドで動かせます
（キーボードは Space・Enter で1つ目のボタンを押すだけ。下の「ラウンドの幕と優勝の幕」）。

- キーボード：矢印で動かし、Enter か Space で決め、Escape か Backspace で1つ前の画面へ戻ります
- ゲームパッド：十字キーか左スティックで動かし、A で決め、B で戻ります。試合の前の画面とロビーでは、Start・Select と
  ほかのボタン（X・Y・L1・R1・L2・R2）は、枠を出すだけです（原型と同じ。原型はパッドのどのボタンの押し始めも
  カーソルへ渡します。ほかのボタンの押し始めはボタンごとに見ます）。幕の Start は、カーソルの位置によらず1つ目の
  ボタンを押します（原型と同じ）

| | 置き場所 | 中身 |
|---|---|---|
| どの項目を指しているか | `src/presentation/menu/MenuCursor.ts` | グループと項目の番号、カーソルの枠（指している項目を囲む印）を出しているか。画面には触れない |
| 画面の項目の並び | `src/platform/ui/MenuNavigator.ts` | `data-nav`（グループの名前）の付いた要素を、操作のたびに画面から集め直す |
| キーから操作への翻訳 | `src/platform/Keyboard.ts` の `navCommandOf` | 押し続けたときの繰り返しは数えない。修飾キー（Command・Ctrl・Option）は見ない（原型と同じ）。原型の押した瞬間の条件のうち「押していなかったキー」は写していない。差が出るのは、離したことが届かなかったキーをもう一度押したときだけ（P のポーズも同じ） |
| パッドから操作への翻訳 | `src/platform/GamepadInput.ts` の `PadMenuInput` | 描くたびに読み、前回読んだときとの差分で押した瞬間を作る。1回に押し始めた操作は、まとめてカーソルへ渡す。スティックの読み方は試合の操作と同じ。つかむパッド（`PadChoice`）は試合の操作と1つを分け合う |

- パッドは1回の読み取りで、押し始めたボタンをまとめて渡します。カーソルは原型の `MENU.nav` と同じ順に見ます。
  枠が出ていなければ枠を出し、決定（A）が含まれていれば同じ回の移動ごと飲み込みます。続けて、戻るがあれば
  戻るだけ、なければ決定があれば決定だけ、なければ上下を動かしてから左右を動かします（上下と左右は同じ回に
  両方動きます）。キーボードは1回に1つを渡します

- カーソルは2段です。上下でグループを移り、左右でグループの中を移ります。縦に並ぶボタン（タイトルの一覧・LAN の画面の
  「たてる」「さんかする」）は1つずつ別のグループに、横に並ぶもの（動物の一覧・選択肢の1行）は1つのグループにします。
  画面の座標では動かしません（動物の一覧は画面の幅で列の数が変わるため）
- 画面は選ぶたびに丸ごと組み直すので、要素を覚えておくと古くなります。項目の並びは、操作のたびに画面から集め直します
- 枠は、キーを触るまで出しません。枠が出ていないときの最初の決定は、枠を出すだけです（どこを指しているか
  見えないまま決めないため）。移動と戻るは、枠を出したうえで反映します。マウスを動かすと枠を消します。
  試合や通信対戦からタイトルへ戻ったときも枠を消します（原型と同じ。触っていないのにタイトルで枠が光らないように）
- 幕のカーソルの扱いは、下の「ラウンドの幕と優勝の幕」
- ⚠️ つかむパッドは、メニュー・ロビー・試合で1つを分け合います（`PadChoice`、原型と同じ）。読む側ごとに
  覚えると、メニューで1番をつかんだあとに別のパッドが0番で点いたとき、試合の側が0番をつかみ、手元の1番で
  操作できなくなります
- パッドの読み取りが例外を投げたとき（gamepad を許していない別オリジンの iframe など）は、パッドが無いものとして
  扱います（`readBrowserGamepads`。原型も握りつぶしていました）。描くたびに読むので、投げたままにすると描画の
  ループが止まります
- 画面が替わったら、カーソルは先頭へ戻ります。枠が消えている間にマウスで画面を移ったときも、描くたびに
  画面の替わりを見ているので戻ります
- 設定とマニュアルと更新履歴の画面でカーソルに載るのは、上の音の設定の1行だけです。マニュアルと更新履歴は、
  高さの決まった箱の中をホイールで読みます（原型と同じ）。矢印と Space は、ほかの画面と同じくページを動かしません
- カーソルを動かしても、指す項目が見える所までページを動かしません（原型と同じ）。ページの先頭へ戻すのは、上の
  「決めたこと」の「ページの先頭へ戻す時」だけです。窓より縦に長い画面では、窓の外の項目はホイールで動かしたときに見えます
- 「← もどる」「← せつぞくを切る」にはカーソルを乗せません。戻るは Escape です
- 試合の最中（幕が出ていない間）は、矢印や Enter を押しても何も起きません
- ⚠️ パッドの前回の状態は、画面が替わっても消しません。消すと、A で「つぎへ」を押したまま次の画面へ移ったとき、
  押したままの A が新しい押下に見えて、次の画面の項目まで押してしまいます（原型も同じ決まり）
- 通信対戦のロビーでは、ホスト（1P）だけが動かせます。プレイヤーの枠ごとの行は、その枠の動物・CPU の強さ・体力の順です
  （原型と同じ。CPU の強さは、いまつながっていない枠だけ）。ゲストには動かすものがありません（ホストが選んでいるものは、
  カーソルに載らない読むだけの1行ずつで出ます）
- ロビーと、つないでいる最中の LAN の画面では、戻る（Escape・B）で「せつぞくを切ります。よいですか？」を開きます（原型と同じ。
  押し間違えて試合ごと抜けないように、切る前に確認する）。つないでいる最中の LAN の画面はカーソルの項目が無いので、
  カーソルは戻るを返しませんが、それでも開きます

### 決定のキーは爆弾のキーでもある

Enter と Space は爆弾のキーです（パッドの A も）。決定で「はじめる」を押すと、押したまま試合が始まります。
それでも開始位置に爆弾は置かれません。押したまま始まったボタンは、一度離して押し直すまで無効です。
無効にする仕組みは、ボタンごとに違います。

- 押した瞬間に出るもの（爆弾・通常技）：ラウンドの始まりは、爆弾と技のボタンを「前の tick に押していた」
  扱いにします（`WorldState.ts` の `HELD_AT_ROUND_START`）。決着のあとの待ちの間も
  キーを押し続けていた場合も、これで次のラウンドの開始位置に爆弾を置かず、技も出しません
- 押し続けて出るもの（とくぎ）：ラウンドの始まりは「この押し方のとくぎは出し終えた」扱い
  （`actionFired` の true）にしておき、一度離すまで出しません（原型の startRound と同じ）。とくぎは押し続けた
  長さで出るので、「前の tick に押していた」扱いでは防げません
- 通信対戦では、入力が 3 tick 遅れて反映されます。最初の 3 tick ぶんは、試合が始まった時点で押している
  内容で埋めます（`LockstepDriver.start`）。何も押していない入力で埋めると、tick 0 に「離した」が届いて
  上の2つが外れ、1ラウンド目だけ開始位置に爆弾を置きます

### ブラウザのクリックは、マウスのものだけを受け付ける

画面のボタンは全部 `pointerButton` で作り、キーボードで起きたクリック（`detail` が 0）を捨てます。
マウスで押したボタンにはフォーカスが残ることがあり、そのあと試合中に Space や Enter を押すと、ブラウザが
そのボタンをもう一度押すためです（ポーズ・もういっかい、など）。Tab でフォーカスもさせません。

キーボードでメニューを動かすときは、ブラウザのクリックを通さず、カーソルが同じ中身を直接呼びます
（`dom.ts` の `activate`）。クリックを偽って発生させると、上の、キーボードで起きたクリックを捨てる仕組みを
すり抜ける形になります。

### ブラウザの既定の動きを止めるキー

Space・矢印・Enter・Slash の7つは、どの画面でも、修飾キーと一緒でも、押し続けたときの繰り返しでも、
ブラウザの既定の動きを止めます（原型と同じ。`Keyboard.ts` の `PREVENTED_KEYS`）。止めないと、画面が縦に
収まらないときに、キーを押すたびにページが動いて盤面がずれます。

## 押してすぐ離したキー

押してから離すまでが 1 tick より短いと、押されているキーだけを見る形では、押したこと自体が消えます。
キーボードとパッドは押した瞬間（原型の `pressed`）を残し、爆弾と技は、離していても押していたことにします
（`KeyboardWatcher` の `buttonAnyOf`、`PadChoice` の `tapped`）。向きは押されているキーだけで見ます（原型と同じ）。
パッドはメニューの操作が描くたびに読むので、そこで押した瞬間を残します。

残した押した瞬間をいつ忘れるかは、画面の流れ（`Shell`）が決めます。

- 入力を tick へ取り込んだあと（通信対戦では送ったあと）。倍速でも、1回の押しは 1 tick ぶんです
- 進めなかった回（0.5 倍で進まない回・通信対戦で入力を待っている間）は忘れません。忘れると、押したことが
  読まれないまま消えます
- 1台の試合を止めている間（ポーズ・ラウンドの幕・決まった試合。`MatchRunner.stopped`）と試合の外（LAN の画面と
  通信対戦のロビーも）は、原型と同じく描くたびに忘れます。忘れないと、ポーズ中に押してすぐ離した爆弾のキーで、再開した
  最初の tick に爆弾を置きます（押したまま再開したときは置きます。上の「原型に合わせない所」）

### Option・Command を離したとき

macOS は Option・Command を押している間、ほかのキーを離したことを送らないことがあります。原型と同じく、
Option か Command を離したら、ほかの押しているキーを捨て、押したままのキーはブラウザのキーの繰り返しで戻します。
この版は押した瞬間を試合の側が前の tick と比べて作るので、戻ったキーをそのまま押していることにすると、爆弾を
置いたり技を出したりします。捨てたキーは、繰り返しで戻っても、もう一度押すまで爆弾と技には数えません。
向きは繰り返しで戻します（原型の注記の2つの狙い：押したままの向きは戻す・勝手に技や爆弾を出さない）。
Option は技のキーの1つ（従のキー）としても割り当てています（原型の `CONTROLS`）。

## LAN の画面と、通信対戦のつなぎ方

タイトルの「LAN対戦」で、同じページの LAN の画面へ移ります（原型と同じ。`MenuFlow` の `lan`）。注記・「たてる」
「さんかする」・つないでいる様子の1行を、原型と同じ要素とクラス名で並べます（`MenuView` の `#lan`）。

- 「たてる」も「さんかする」も、同じ中継につなぎます（`Shell.startLan`。原型の `joinLan`）。つなぐのは、起動の入口が
  渡した中継の場所（`ShellTools.relayAddress`）で、ページを配った端末の中継か、`?relay=名前` で開いたページならその中継です。
  ホストかゲストかは中継が決めます（中継は 1P を、中継と同じ Mac からの接続に空けておく）
- つないでいる間は「たてる」「さんかする」を隠して「接続しています…」を出し、中継から番号を受け取ったらロビーへ移ります
  （`LanMatch` がロビーを写す）
- ロビーへ移る前に止まったら、LAN の画面に留まって理由を出します。ロビーへ移ったあとに止まったら、通知を出してタイトルへ
  戻ります（上の「原型に合わせない所」と「決めたこと」）
- 抜けるとき（「← せつぞくを切る」の確認・横の板の「設定へ」・幕の「⚙ 設定をやりなおす」・「設定へもどる」）は、どれも
  `Shell.showMenu`（原型の `backToSetup`）を通ります。接続を閉じ、案内の帯を空にして隠し、確認の画面を畳み、枠を消して
  タイトルを出します。中継は、閉じた接続を抜けたものとして扱い、残りの端末の試合は CPU が引き継ぎます
- もう一度つなぐときは、`LanMatch` を作り直します（前の接続の段階・試合・案内の帯の文を持ち越さない）。ロビーで選んだものは
  持ち越します（上の「決めたこと」）
- 音の設定（BGM + 効果音・効果音だけ・無音）は、原型と同じく起動の間だけ持ち、ブラウザには残しません。ページを開き直さない
  ので、通信対戦へ移って戻っても、選んだ設定は消えません

## ラウンドの幕と優勝の幕

ラウンドが決まると、勝った動物と勝ち数の幕を出します（`src/platform/ui/BannerOverlay.ts`。中身は
`src/presentation/hud/RoundBanner.ts`）。要素の並びと見た目は原型の `#banner`・`.bcard` を写しました。幕は `#app` の外に
置き、窓の全体を暗くぼかして覆います（`backdrop-filter`）。幕が出ている間は、横の板のボタンもつまみも押せません（原型と同じ）。

ボタンは縦に2つです。1つ目はラウンドの幕で「つぎのラウンド ▶」、優勝の幕で「もういっかい」、2つ目はどちらも
「⚙ 設定をやりなおす」（タイトルへ戻る）です。どちらも画面の操作の音を鳴らしません（原型と同じ）。

| | 1台の試合 | 通信対戦 |
|---|---|---|
| ラウンドの幕 | 送るまで出し続け、その間は試合を進めない。2つのボタン | 決着のあとの待ち（`ROUND_INTERMISSION`、試合の時間で2秒）で消える。ボタンは無い |
| 優勝の幕 | 「もういっかい」（同じ設定・新しい種で次の試合）と「⚙ 設定をやりなおす」 | ホストで次の試合を始められるときだけ「もういっかい」、全員に「⚙ 設定をやりなおす」（押すと接続を閉じてタイトルへ） |

- 1台の試合は、原型と同じくボタンで送ります。幕が出ている間（決着のあとの待ち）は tick を進めず（`LocalMatch.ready`）、
  送ると待ちを切り上げて次のラウンドの盤面を作ります（`GameSession.startNextRound`）。押してすぐ離したキーは、幕の間も
  ポーズと同じく毎フレーム忘れます
- 通信対戦の幕はボタンで送りません。送る操作があると、「誰の操作で次へ進むか」を全員で揃える約束（中継と Python 版も）が
  要ります。待ちの長さは試合の側が tick で数えているので、全員の端末で同じ tick に次へ進みます。原型のゲストには幕が
  出ませんが（ホストだけが試合を進める作りによる）、この版は全員に出すので、ゲストにも抜ける道（「⚙ 設定をやりなおす」）を出します
- 送り方：キーボードの Space・Enter は、カーソルの位置によらず1つ目のボタンを押します。矢印と Escape は何もしません
  （原型と同じ。キーボードでは「⚙ 設定をやりなおす」を選べず、マウスかパッドで押します）。パッドの Start も1つ目のボタンを押す
  近道です。パッドの十字と A はカーソルで動かします
- パッドを試合に繋ぐ遊び方（1人で遊ぶときと通信対戦）では、ボタンのある幕の間は毎フレーム枠を出します（原型と同じ。
  パッドを押さなくても、パッドが無くても出ます。マウスを動かして消しても、次のフレームで出し直します）。パッドの操作を
  カーソルへ渡す前にも枠を出すので、パッドの1回目の A は枠を出すだけにならず、そのまま押します（マウスで枠を消した直後の
  フレームでも。原型の L3637 と L3639 の順）。1台で2人で遊ぶときは、幕でパッドを受け付けず、枠も出しません（メニューで
  出した枠も試合へ持ち越しません。机に置いたパッドに肘が当たっただけで次へ進まないように。原型と同じ）。キーボードは受け付けます
- 幕が出るたびに、カーソルは1つ目のボタンへ戻ります（原型の `endGame` の `MENU.reset`）。前の幕で「⚙ 設定をやりなおす」を
  指したままでも、次の幕の1回目の A で見えないまま抜けることはありません
- ラウンドが決まったら曲を止め、次のラウンドの頭で鳴らし直します（原型と同じ。通信対戦の待ちの間も止めます）。
  ⏸ ポーズと P は、幕の間は何もしません（原型の `togglePause` も、ラウンドの最中でなければ何もしない）
- 押したまま送っても、次のラウンドの開始位置に爆弾は置かれません（上の「決定のキーは爆弾のキーでもある」）

誰が勝ったかは、決まった tick のイベント（`roundEnded`）にしか載っていません。試合の状態には
勝ち数しか残らないので、幕はイベントから作ります（`RoundBanner`）。

窓の全体を暗くして、真ん中に文と2つのボタン（「やめる」と、種類ごとの文）を出します（原型の `askConfirm`。
`src/platform/ui/ConfirmDialog.ts`）。ブラウザの `confirm()` を使わないのは、OS の確認はパッドで操作できないためです（原型の注記）。

| 種類 | 文 | 右のボタン | 入口 |

  1台では止めてから開きます（原型の注記）。幕が出ている間は、Select でも開きません（幕の間のパッドは幕を動かす。原型・Python 版と同じ）

  よいですか？」です（上の「決めたこと」）
- 開いている間、キーとパッドは確認の画面を動かします。P とパッドの Start では止めも再開もせず、キーの Space・Enter で
  幕を送ることもありません（原型と同じ）。ただし、開いたまま幕が出たとき（通信対戦で、開いたまま試合が決まったとき）の
  パッドは、幕の扱いが先です。Start は確認の画面が開いていても幕を送り（原型 L3631）、ボタンの無い幕（通信対戦の

- 開いている間も、試合への入力は止めません（原型と同じ。通信対戦では、確認の画面を動かす十字と A がそのまま自分の

  （原型の `showScreen`。ロビーで開いたままホストが試合を始めたとき、盤面が確認の画面に覆われたままにならないように）
- 文は Python 版と同じで、`src/presentation/menu/menuText.ts` の `DIALOG_TEXTS` にあります

## 設定が盤面に届いていなかった

試合の設定（`MatchConfig`）には、段階4から初期の体力（`startingHp`）がありました。ところが盤面を
作る処理（`createWorld`）はそれを受け取っておらず、体力は 6（と動物ごとの上乗せ）で固定されていました。
設定の画面を作る前の下調べで見つけました。

体力は1人ずつ持つ形（プレイヤー番号の順の配列）にして、盤面まで通しました。ハンデをつけるためです。
テストは「設定した体力で始まる」だけでなく「**次のラウンドも**設定した体力で始まる」も見ています。
原型のコメントにも、1ラウンド目だけ正しくなる形の誤りへの注意が書かれています。

## 秒読みはイベントを足さずに鳴らす

残り10秒から0秒まで、1秒ごとに短い音を鳴らします（`Countdown`。原型と同じ）。試合の側にこのためのイベントは無く、
残り時間を盤面から計算して、秒の境目を数えます。残り時間は盤面から決まるので、イベントを足すと
同じことを2か所で持ちます。

0秒の tick にはラウンドが決まるか延長戦に入り、その音も同じ tick に鳴ります（原型も重ねて鳴らします）。
延長戦に入る tick は、試合の側が同じ tick のうちに時間切れの時刻を延ばすので、延ばしたあとの時刻で
数えると0秒を鳴らしません。そこで、前の tick に見た時間切れの時刻で、その tick の残りを数えます
（原型は延長戦に入る前に0秒を鳴らします）。予約の順は原型と逆で、延長戦の音を秒読みより先に予約します
（同じ時刻に鳴るので、聞こえ方は同じ。上の「原型に合わせない所」）。

## 通信対戦のロビー

要素と文と並びは原型と同じです（`src/platform/ui/LobbyView.ts`。文は Python 版の `lobby_view` と同じで `menuText.ts` に
あります）。冒頭に「あなたは 1P（ホスト）」、枠ごとに見出し（「1P（あなた）」「🟢 接続済み」「⚪ 空き・待機中」）、最後に
ルール、下に「はじめる ▶」（ホスト）か待ちの文（ゲスト）を並べます。

ホスト（1P）が、4つの枠それぞれの動物・体力と、ルール（何勝先取・じかん・サドンデス）を決めます。始まった時点で
人間がつながっていない枠は CPU が受け持ちます。CPU の強さの行は、いまつながっていない枠（始めたら CPU になる枠）にだけ
出します（Python 版と同じ。上の「原型に合わせない所」）。人間の枠でも、その端末が途中で抜けたら、その枠の強さの CPU に
替わります（つながる前に選んだ強さのまま）。

ゲストは決めません。ゲストが手元で選んでも、試合はホストが配った設定から作るので、
「選んだのに反映されない」になります。

ホストが選んでいるものは、始まる前からゲストの画面に、読むだけの1行ずつで出ます（「🐰うさぎ ／ ふつう ／ たいりょく 1回」
の形。原型と同じ）。ホストの設定がまだ届いていなければ、既定の値を出します（原型と同じ）。選ぶボタンの形にはしません。
押せる形にすると、押しても試合に使われないのに、使われるように見えます。
どう届けるかは [05-通信対戦](05-通信対戦.md) の「始まる前に、ホストの設定をゲストへ見せる」。
⚠️ 試合を作るのは、これまでどおり、試合が始まるときに `start` の中で全員へ届く設定です。

画面の操作の音は、原型と同じ所で鳴らします。チップ全部・「← せつぞくを切る」・「はじめる ▶」で鳴らし、動物のカードでは
鳴らしません（原型 L5843。キャラ選びのカードと違うのも原型のまま）。B で確認の画面を開いたときも鳴らしません（原型の
`MENU.back` は `SE.ui` を呼ばない）。

## ゲームパッドを試合に繋いだ

ゲームパッドの窓口（`GamepadInputSource`）は段階4からありましたが、起動の入口がどこにも
繋いでいませんでした。1人で遊ぶときと通信対戦の自分の操作に、キーボードと並べて繋ぎました。

同じプレイヤーに窓口を2つ繋ぐと、後に繋いだほうが前のほうを置き換えます。そこで、ボタンごとに
OR をとってまとめる窓口（`CombinedInputSource`）を1つ置き、試合の側からは窓口1つに見えるようにしました。
2人で1台を使うときはパッドを繋ぎません（どちらのプレイヤーのパッドか決められないため）。

## 止める

1台で遊ぶときは、P キー・横の板の「⏸ ポーズ」・パッドの Start で止められます（原型と同じ）。止められるのは
ラウンドの最中だけで、ラウンドの幕が出ている間と、試合が決まったあとは何もしません（原型の
`togglePause` も、ラウンドの最中でなければ何もしない。幕の間のパッドの Start は幕を送ります）。止めている間は tick を進めず、曲も止め、盤面の上に
ポーズの幕（盤面を暗くして「PAUSE」と「P で再開」）を描き、ボタンの字を「▶ 再開」にします（原型と同じく canvas に
描きます。`Renderer.draw` の `paused`）。

- パッドの Start で止めるのは、1人で遊ぶとき（パッドを試合に繋ぐとき）だけです。2人で遊ぶときは受け付けません。
  机に置いたパッドに肘が当たってポーズ、が起きないようにするためです（原型と同じ）
- 横の板の「設定へ」は、確認を出さずにタイトルへ戻ります（原型と同じ。マウスで押しに行くこと自体が、戻るつもりで
  押したことを示すため）。「⏸ ポーズ」と「設定へ」は、画面の操作の音を鳴らしません（原型と同じ）
- ポーズ中にパッドの Select を押すと、「設定へもどりますか？」の確認の画面を出します（上の「確認の画面」。パッドから
  タイトルへ戻る入口）

通信対戦では止められません。1台だけ止めると、ほかの全端末がその端末の入力を待って止まるためです。横の板には
つまみも「⏸ ポーズ」も出さず、「設定へ」だけを出します（原型のゲストと同じ形）。押すと接続を閉じてタイトルへ戻ります。
パッドの Select は、止めずにいつでも確認の画面を出します。

| 幕 | `index.html` の `#banner`・`src/platform/ui/BannerOverlay.ts` | `#app` の外。窓の全体を覆う（上の「ラウンドの幕と優勝の幕」） |
| 確認の画面 | `index.html` の `#cfmWrap`・`src/platform/ui/ConfirmDialog.ts` | `#app` の外。窓の全体を覆う（上の「確認の画面」） |
| 通信対戦の案内の帯 | `index.html` の `#lan-status`・`LanMatch` | 盤面の下の端に重ねる |

- 時計・つまみ・ツールバーは、試合を始めたときに1回だけ作り、字と印だけを替えます（原型も固定の要素です）。時計の要素を
  作り直すと、残り 30 秒からの数字の明滅（CSS のアニメーション）が頭に戻ります
- 名札と時計は、原型と同じく試合の時間で 0.25 秒ごとにだけ作り直します（原型の `G.elapsed%0.25<dt`）。被弾・外周へ回った・
  入れ替わった・延長戦・決着などの場面では、待たずに作り直します。ポーズの間と幕の間は盤面の時刻が進まないので、作り直しません。
  キーの案内とポーズのボタンの字は、替わったらすぐ替えます（原型の案内は、名札の作り直しとポーズの切り替えのときだけ
  替わります。上の「原型に合わせない所」）
- キーの案内のキーは小さいキーの形（`.k`）、行は `.r` で、葱ボンの段の下は破線で区切ります（原型と同じ組み方）
- 通知は `#app` の外に1つだけ置き、どの画面の上にも出します。画面を替えても消さず、時間でだけ消えます（原型と同じ）。
  パッドを初めて見つけたとき（「🎮 コントローラーを認識しました」）と、標準の並びでない機器を見つけたとき（名前を添えて
  「対応していません」）は、メニューの間も含めて、起動の間に1回ずつ出します。出すのはこの端末のパッドのことだけです（上の
  「原型に合わせない所」）
- 通信対戦の案内（入力の待ち・ずれ・試合が終わった）は、盤面の下の端に帯で重ねます（原型に無いもの。Python 版と同じ
  置き場所と地の色です）。幕より上に出すので、試合が決まった幕の間も「もういっかい」の案内を読めます。出す文が無い間は
  隠します。字の大きさと折り返しは上の「原型に合わせない所」。中継との接続が切れたときは、帯には出さずにタイトルへ戻ります

## キーの案内とマニュアルは原型の固定の文

キャラ選びの1行・横の板のキーの案内は、原型と同じ固定の文です（`src/presentation/menu/keyHints.ts`・
`src/presentation/hud/keyHelp.ts`）。原型の案内は、割り当てた全部のキーを書きません（J と Option は書かない）。
割り当ての表から作ると、原型と違う文になります。横の板の技の行の頭は動物ごとの呼び方（「とぶ」「した」など）で、
パッドの段はパッドを認識しているときだけ出します。

試合の外の画面（起動の幕・タイトル・キャラ選び・ルール・設定とマニュアルと更新履歴・LAN の画面・ロビー）と確認の画面の文は、
Python 版の文にそろえています（`src/presentation/menu/menuText.ts`、動物の説明は `src/content/animals.ts`）。Python 版は原型の
文を写し、リポジトリの文の決まりで書かない語に当たる所だけを言い換えています（LAN の画面の注記の2文目だけは、原型の文に
戻しています。上の「原型の答えが1つに決まらない所の決め」）。LAN の画面の様子の行に出す、つなげなかった理由（断られた・
中継に届かなかった・切れた）は、Python 版と同じく接続を扱う側に置いています（`src/app/LanMatch.ts` の `REFUSED`・`unreachable`、
`src/net/LockstepClient.ts` の既定の文）。`?relay` の値が読めないときの文は起動の入口（`src/app/main.ts`）にあります。マニュアルの 46 行と更新履歴の
49 項目（`src/presentation/menu/manual.ts`）は、Python 版の `manual.py` から機械的に書き出したもので、手では
修正しません。書き出すのは `tools/gen_manual.py` です（リポジトリのいちばん上で
`uv --directory py run python ../ts/tools/gen_manual.py`）。写し違いは、Python 版の文から計算した SHA-256 の値と
比べて見つけます（`tests/presentation/manual.test.ts`。値は書き出しの台本が標準出力に書きます）。
マニュアルには、この版に当てはまらない説明も原型のまま残ります（ブラウザがコントローラーを見つける仕組みなど）。

## 起動の幕と、画面の操作の音

ページを開くと、ロゴと版の行（`VERSION v4.3.0`。原型の版）を全面に出します（`src/platform/ui/Splash.ts`）。
クリックかどれかのキーで消え始め、何もしなくても 3.2 秒で消え始めます。パッドのボタンでは消えません（原型と同じ）。
幕を消したキーは、下のタイトルにも届きます（原型と同じ）。URL に `?relay` を付けて開いたときは出さずに、LAN の画面から
始めます。通信対戦から抜けるときもページを開き直さないので、幕は起動したときの1回だけです（原型と同じ）。

試合の前の画面（タイトル・キャラ選び・ルール・設定・LAN の画面）とロビーの操作の音（`ui`）は、原型と同じ所で鳴らします。
タイトルの5つ・「← もどる」・「つぎへ ▶」・チップ全部・キャラ選びの動物のカード・「たてる」「さんかする」・B で1つ前の画面へ
戻ったとき、ロビーのチップ・「← せつぞくを切る」・「はじめる ▶」です。ルールの「はじめる」・タイトルの B・ロビーの動物の
カードと B では鳴らしません。鳴らす前に、ブラウザの音の解錠も呼びます（パッドだけで遊ぶと、キーとクリックの
解錠が一度も起きないため）。

音のチップでは、選んだあとの設定で聞こえ方が決まります（原型と同じ）。原型は操作の音を予約してから、同じ処理の
中で効果音の音量を変えるので、「無音」を選んだ音はほとんど聞こえず、「無音」から戻した音は聞こえます。この版は
効果音を切っている間は音の部品を作らない（`WebAudioSoundBank`）ので、「無音」は鳴らしてから切り、音を戻す向きは
設定を変えてから鳴らします。

## ゲームの速さ

1台で遊ぶときは、横の板のつまみ（時計と名札の間）でゲームの速さを 0.5〜3 倍（0.25 刻み）に変えられます（原型と同じ）。
CPU どうしの試合を眺めるのが退屈なときに上げます。

速くするとき、経過時間を伸ばしてはいません。1 tick ぶんの時間が経つたびに、倍率ぶんの tick を進めます
（`GameSpeed`。0.5 倍なら2回に1回、1.5 倍なら 1 tick と 2 tick を交互）。1 tick の中身はどの速さでも同じなので、
速さを変えても同じ操作は同じ結果になります。原型は経過時間に倍率を掛けていたため、倍速にすると1回のキーの
押し下げが2〜3回に数えられる不具合が出ました。

- 曲も速くします（2倍まで。上げ過ぎると耳障りになる）。1台の試合を始めるたびに、曲をいまの倍率に合わせます
- 速さは試合をまたいで保ちます。「もういっかい」で等倍に戻しません。通信対戦から戻ったあとの1台の試合も、前の倍率のままです
- 通信対戦には出しません。全員の端末が同じ速さで進める必要があり、1台だけ速くしても、ほかの端末の入力を
  待って止まるだけになります
- つまみはキーボードで動かしません。矢印は移動のキーなので、Tab でフォーカスさせず、動かし終えたらフォーカスを外します
- 目盛りは等間隔に並べず、つまみの中心が来る位置に置きます。等間隔だと「1×」の目盛りに合わせたつまみが
  1.33 倍を指します（原型で実際に起きました）
- ラウンドの幕は送るまで出ているので、速さに左右されません（原型と同じ。幕の間は tick を進めず、倍率ぶんの tick を
  数えるのも止めます）
- 1 倍より遅いときも位置が滑らかに動くよう、描く側へ渡す補間の進み具合を、試合の時間の進み具合に換えます
  （`GameSpeed.progress`）。画面のループの進み具合（実時間）をそのまま渡すと、tick を進めなかった回に
  位置が1つ前の tick の側へ戻ります。1.5 倍のように1回に進む tick の数が変わる倍率では、動きの幅が
  そろいません（描く側が1つ前の tick の位置しか覚えていないため）
- 1台の試合を止めている間（ポーズ・ラウンドの幕・決まった試合）は、進み具合を 1 にして、いまの tick の位置に描きます。
  tick を進めないので1つ前の tick の位置の控えが取り直されず、進み具合を渡し続けると、止めた tick に歩いていた
  プレイヤーが前後に揺れて見えます（原型は止めている間、いまの位置に描きます）
- 幕を送った直後に、次のラウンドの盤面を tick を進める前に描くとき（パッドで送ったフレーム・0.5 倍で tick を進めない
  フレーム）も、前のラウンドの粒子と画面の揺れは描きません（描く側が盤面の替わりを描くときにも見る。`ParticleField.enter`。
  原型の startRound は、その場で粒子と揺れを捨てます）
