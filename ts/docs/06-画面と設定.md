# 画面と設定

段階10では、タイトル・動物を選ぶ画面・ルールを決める画面・遊び方の説明と、試合の横に出す板
（時計・名札）、ラウンドの間の幕、通信対戦のロビーを足しました。

この段階の主題は**画面に何を出すかと、どう写すかを分けること**です。

## 何を出すかは純粋な関数、写すのは薄い層

| | 置き場所 | 中身 | 確かめ方 |
|---|---|---|---|
| 何を出すか | `src/presentation/hud/`・`src/presentation/menu/` | 試合の状態から文と値を作る関数と、画面の流れを持つクラス | node のテスト |
| どう写すか | `src/platform/ui/` | 値を要素に写し、押されたら上を呼ぶ。固定の文言と、どの行を並べるか | 代わりの DOM（happy-dom）のテスト |
| どこに置くか | `index.html`・`src/style.css` | 要素の並びと見た目 | 目で見る |

たとえば名札の中身（「❤️❤️🖤」「★☆☆」「CPU・ふつう」）は `describePlayers` が作ります。
盤面・勝ち数・設定・誰が操作しているかを受け取って、文を返すだけです。要素に写すのは
`SidePanel` で、中身が前と同じなら要素に触れません。

画面の流れ（タイトル → 動物 → ルール、もどる）も `MenuFlow` が持ち、画面には何も書きません。
写す側（`MenuView`）は、押されたら `MenuFlow` を呼んで写し直すだけです。

分けてあるので、表示の誤り（ハートの数・勝ち星・ラウンドの番号）はブラウザを開かずに見つかります。

### ブラウザを開かずに、画面を押してみる

写す側も、代わりの DOM（happy-dom）の上で組み立てて、クリックを流して確かめています。
タイトルで「2人 vs CPU×2」を押し、2P の動物を選び、勝ち数を変えて「はじめる」を押すと、
選んだとおりの設定が届く、というところまでがテストになっています（`tests/ui/`）。

テストのファイルの先頭に `// @vitest-environment happy-dom` と書いたものだけが、代わりの DOM の上で
走ります。ほかのテストは node のままです。

⚠️ 代わりの DOM で確かめられるのは、要素ができること・押したら呼ばれることまでです。
見た目（CSS の効き・並び・文字のはみ出し）は確かめられません。

## キーボードとゲームパッドでメニューを動かす

タイトル・動物を選ぶ画面・ルールを決める画面・設定・遊び方・通信対戦のロビーと、試合が決まった幕のボタンは、
キーボードとゲームパッドでも動かせます（原型と同じ）。試合が決まった幕は、試合が終わったときに盤面へ重ねる表示で、
優勝した動物か「引き分け」を出します。1台で遊ぶときは、下に「もういっかい」「タイトルへ」を並べます。

- キーボード：矢印で動かし、Enter か Space で決め、Escape か Backspace で1つ前の画面へ戻ります
- ゲームパッド：十字キーか左スティックで動かし、A で決め、B で戻ります

| | 置き場所 | 中身 |
|---|---|---|
| どの項目を指しているか | `src/presentation/menu/MenuCursor.ts` | グループと項目の番号、カーソルの枠（指している項目を囲む印）を出しているか。画面には触れない |
| 画面の項目の並び | `src/platform/ui/MenuNavigator.ts` | `data-nav`（グループの名前）の付いた要素を、操作のたびに画面から集め直す |
| キーから操作への翻訳 | `src/platform/Keyboard.ts` の `navCommandOf` | 押し続けたときの繰り返しと、Command・Ctrl・Option と一緒のときは数えない |
| パッドから操作への翻訳 | `src/platform/GamepadInput.ts` の `PadMenuInput` | 描くたびに読み、前回読んだときとの差分で押した瞬間を作る。スティックの読み方は試合の操作と同じ。つかむパッド（`PadChoice`）は試合の操作と1つを分け合う |

- カーソルは2段です。上下でグループを移り、左右でグループの中を移ります。縦に並ぶボタン（タイトルの一覧）は
  1つずつ別のグループに、横に並ぶもの（動物の一覧・選択肢の1行）は1つのグループにします。画面の座標では
  動かしません（動物の一覧は画面の幅で列の数が変わるため）
- 画面は選ぶたびに丸ごと組み直すので、要素を覚えておくと古くなります。項目の並びは、操作のたびに画面から集め直します
- 枠は、キーを触るまで出しません。枠が出ていないときの最初の決定は、枠を出すだけです（どこを指しているか
  見えないまま決めないため）。移動と戻るは、枠を出したうえで効かせます。マウスを動かすと枠を消します
- ⚠️ 試合が決まった幕だけは、枠が出ていなくても最初の決定をそのまま効かせます（原型と同じ）。幕でする操作は
  ほぼ「もういっかい」だけで、1回目を飲み込むと「決定が効かない」としか見えません。原型もキーボードの
  Space・Enter でそのまま次へ進め、パッドの A も1回目を飲み込みませんでした。見えないまま「タイトルへ」が
  効かないよう、試合が決まった幕が出るたびにカーソルを「もういっかい」へ戻します（原型も試合が決まるたびに戻していました）
- ⚠️ 1台で2人で遊ぶときは、試合が決まった幕でパッドを受け付けません（原型と同じ）。2人のときはパッドを試合に
  繋がないので、机に置いたパッドに肘が当たっただけで次の試合が始まらないようにします。キーボードは効きます。
  メニューとロビーでは、どの遊び方でもパッドが効きます
- 通信対戦では、試合が決まった幕の「もういっかい」はホストにだけ出ます（原型と同じ。押すと全員の次の試合が
  始まる。[05-通信対戦](05-通信対戦.md) の「同じ接続での次の試合（再戦）」）。この幕ではパッドも効き、1台で
  遊ぶときと同じく、枠が出ていなくても最初の決定（Enter・Space・A）がそのまま効きます
- ⚠️ つかむパッドは、メニュー・ロビー・試合で1つを分け合います（`PadChoice`、原型と同じ）。読む側ごとに
  覚えると、メニューで1番をつかんだあとに別のパッドが0番で点いたとき、試合の側が0番をつかみ、手元の1番で
  操作できなくなります
- パッドの読み取りが例外を投げたとき（gamepad を許していない別オリジンの iframe など）は、パッドが無いものとして
  扱います（`readBrowserGamepads`。原型も握りつぶしていました）。描くたびに読むので、投げたままにすると描画の
  ループが止まります
- 試合が決まった幕では、矢印でも「タイトルへ」を選べます。原型では、幕でカーソルを動かせたのはパッドだけで、キーボードは
  Space・Enter で次へ進むだけでした。この版はキーとパッドを同じ操作に翻訳してから、意味を1か所で決めています
  （原型もメニューと確認の画面では同じ形でした）。Space・Enter だけを押す人には、原型と同じ動きになります
- 画面が替わったら、カーソルは先頭へ戻ります。枠が消えている間にマウスで画面を移ったときも、描くたびに
  画面の替わりを見ているので戻ります
- 遊び方の画面でカーソルに載るのは、上の音の設定の1行だけです。矢印と Space は、ほかの画面と同じくページを
  動かしません（原型も同じ）。下の説明は PageDown・End かホイールで読みます。カーソルが指す項目が替わらない
  ↑↓では、ページを音の設定の行まで引き戻しません
- 「← もどる」にはカーソルを乗せません。戻るは Escape です
- 試合の最中は、矢印や Enter を押しても何も起きません（幕にボタンが無いので、並びが空になる）
- ⚠️ パッドの前回の状態は、画面が替わっても消しません。消すと、A で「つぎへ」を押したまま次の画面へ移ったとき、
  押したままの A が新しい押下に見えて、次の画面の項目まで押してしまいます（原型も同じ決まり）
- 通信対戦のロビーでは、ホスト（1P）だけが動かせます。プレイヤーの枠ごとの行は、その枠の動物・CPU の強さ・体力の順です
  （原型と同じ）。ゲストには動かすものがありません（ホストが選んでいるものは、カーソルに載らない読むだけの表で出ます）
- ⚠️ ロビーでは、戻る（Escape・B）で何もしません。ぬけるとページを開き直すので、押し間違えると試合ごと
  抜けてしまいます。ぬけるときは「← ぬける」をマウスで押します（原型は確認の画面を挟んでいました）

### 決定のキーは爆弾のキーでもある

Enter と Space は爆弾のキーです（パッドの A も）。決定で「はじめる」を押すと、押したまま試合が始まります。
それでも開始位置に爆弾は置かれません。押したまま始まったボタンは、一度離して押し直すまで効きません。
効かなくする仕組みは、ボタンごとに違います。

- 爆弾のボタン：ラウンドの始まりは、爆弾のボタンを「前の tick に押していた」扱いにします
  （`WorldState.ts` の `HELD_AT_ROUND_START`）。決着のあとの待ちの間も
  爆弾のキーを押し続けていた場合も、これで次のラウンドの開始位置に爆弾を置きません
- 技のボタン：押し続けた長さ（`actionHeld`）を、ラウンドの始まりだけ -1 にしておき、一度離すまで
  数え始めません（前からあります）。技を出すかどうかは押し続けた長さで決まるので、「前の tick に
  押していた」扱いでは防げません
- 通信対戦では、入力が 3 tick 遅れて効きます。最初の 3 tick ぶんは、試合が始まった時点で押している
  内容で埋めます（`LockstepDriver.start`）。何もしない意思で埋めると、tick 0 に「離した」が届いて
  上の2つが外れ、1ラウンド目だけ開始位置に爆弾を置きます

### ブラウザのクリックは、マウスのものだけを受け付ける

画面のボタンは全部 `pointerButton` で作り、キーボードで起きたクリック（`detail` が 0）を捨てます。
マウスで押したボタンにはフォーカスが残ることがあり、そのあと試合中に Space や Enter を押すと、ブラウザが
そのボタンをもう一度押すためです（ポーズ・もういっかい、など）。Tab でフォーカスもさせません。

キーボードでメニューを動かすときは、ブラウザのクリックを通さず、カーソルが同じ中身を直接呼びます
（`dom.ts` の `activate`）。クリックを偽って流すと、上の、キーボードで起きたクリックを捨てる仕組みを
わざとすり抜ける形になります。

## ラウンドの間の幕は、時間で消える

ラウンドが決まると、勝った動物と勝ち数の幕を盤面に重ねます。幕は、試合の側が決着のあとに
盤面を止めて待つ時間（`ROUND_INTERMISSION`、試合の時間で2秒）と重なり、次の盤面に替わったら消えます。
1台で遊ぶときにゲームの速さを変えると、この待ちも倍率に合わせて短く・長くなります（下の「ゲームの速さ」）。

ボタンで次へ送る形にはしていません。送る操作があると、通信対戦では「誰の操作で次へ進むか」を
全員で揃える必要が出てきます。待ちの長さは試合の側が tick で数えているので、全員の端末で同じ tick に
次へ進みます。

誰が勝ったかは、決まった tick のイベント（`roundEnded`）にしか載っていません。試合の状態には
勝ち数しか残らないので、幕はイベントから作ります（`RoundBanner`）。

## 設定が盤面に届いていなかった

試合の設定（`MatchConfig`）には、段階4から初期の体力（`startingHp`）がありました。ところが盤面を
作る処理（`createWorld`）はそれを受け取っておらず、体力は 6（と動物ごとの上乗せ）で固定されていました。
設定の画面を作る前の下調べで見つけました。

体力は1人ずつ持つ形（プレイヤー番号の順の配列）にして、盤面まで通しました。ハンデをつけるためです。
テストは「設定した体力で始まる」だけでなく「**次のラウンドも**設定した体力で始まる」も見ています。
原型のコメントにも、1ラウンド目だけ正しくなる形の誤りへの注意が書かれています。

## 秒読みはイベントを足さずに鳴らす

残り10秒から1秒まで、1秒ごとに短い音を鳴らします（`Countdown`）。試合の側にこのためのイベントは無く、
残り時間を盤面から計算して、秒の境目を数えます。残り時間は盤面から決まるので、イベントを足すと
同じことを2か所で持つことになります。

残り0秒では鳴らしません（原型は鳴らしていました）。0秒の tick にはラウンドが決まるか延長戦に入り、
その音が同じ tick に鳴るためです。

## 通信対戦のロビー

ホスト（1P）が、4つの枠それぞれの動物・体力・CPU の強さと、ルールを決めます。始まった時点で
人間がつながっていない枠は CPU が受け持ちます。人間の枠にも CPU の強さを決めておくのは、
その人が途中で抜けたときに、その強さの CPU に替わるためです。

ゲストは決めません。ゲストが手元で選んでも、試合はホストが配った設定から作るので、
「選んだのに反映されない」になります。

ホストが選んでいるものは、始まる前からゲストの画面に、読むだけの表で出ます（原型と同じ）。
選ぶボタンの形にはしません。押せる形にすると、押しても試合に使われないのに、使われるように見えます。
どう届けるかは [05-通信対戦](05-通信対戦.md) の「始まる前に、ホストの設定をゲストへ見せる」。
⚠️ 試合を作るのは、これまでどおり、試合が始まるときに `start` の中で全員へ届く設定です。

## ゲームパッドを試合に繋いだ

ゲームパッドの窓口（`GamepadIntentSource`）は段階4からありましたが、起動の入口がどこにも
繋いでいませんでした。1人で遊ぶときと通信対戦の自分の操作に、キーボードと並べて繋ぎました。

同じプレイヤーに窓口を2つ繋ぐと、後に繋いだほうが前のほうを置き換えます。そこで、ボタンごとに
OR をとってまとめる窓口（`CombinedIntentSource`）を1つ置き、試合の側からは窓口1つに見えるようにしました。
2人で1台を使うときはパッドを繋ぎません（どちらのプレイヤーのパッドか決められないため）。

## 止める

1台で遊ぶときは、P キーか「ポーズ」ボタンで止められます。止めている間は tick を進めず、曲も止めます。
通信対戦では止められません。1人だけ止めると、ほかの全員がその人の入力を待って止まるためです。

## ブラウザの都合で足したこと

- 音の設定（曲＋効果音・効果音だけ・無音）はブラウザに残します（`src/platform/preferences.ts`）。
  通信対戦へ移るときと抜けるときはページを開き直すので、残さないとそのたびに既定に戻ります。
  残す場所が使えないとき（プライベートのウィンドウなど）は、既定に戻るだけで遊ぶのは止めません
- 試合の画面の間は、操作に使うキー（矢印・Space など）のブラウザの既定の動きを止めます。
  止めないと、画面が縦に収まらないときに、キーを押すたびにページが動いて盤面がずれます

## 説明は表から作る

横の板のキー配置と、遊び方の説明（キー・とくぎの長押しの長さ・アイテムの一覧）は、
それぞれの表（キー配置・動物の能力・アイテムの定義）から作っています。手で書き写すと、
値を変えたときに説明だけ古いまま残ります。

この2つだけは、写す側（`src/platform/`）に置いています。キー配置の表がブラウザの入力と一緒に
`src/platform/Keyboard.ts` にあり、下の層からは読めないためです。

## ゲームの速さ

1台で遊ぶときは、ツールバーのつまみでゲームの速さを 0.5〜3 倍（0.25 刻み）に変えられます（原型と同じ）。
CPU どうしの試合を眺めるのが退屈なときに上げます。

速くするとき、経過時間を伸ばしてはいません。1 tick ぶんの時間が経つたびに、倍率ぶんの tick を進めます
（`GameSpeed`。0.5 倍なら2回に1回、1.5 倍なら 1 tick と 2 tick を交互）。1 tick の中身はどの速さでも同じなので、
速さを変えても同じ操作は同じ結果になります。原型は経過時間に倍率を掛けていたため、倍速にすると1回のキーの
押し下げが2〜3回に数えられる不具合が出ました。

- 曲も速くします（2倍まで。上げ過ぎると耳障りになる）
- 速さは試合をまたいで保ちます。「もういっかい」で等倍に戻しません
- 通信対戦には出しません。全員の端末が同じ速さで進める必要があり、1台だけ速くしても、ほかの人の入力を
  待って止まるだけになります
- つまみはキーボードで動かしません。矢印は移動のキーなので、Tab でフォーカスさせず、動かし終えたらフォーカスを外します
- 目盛りは等間隔に並べず、つまみの中心が来る位置に置きます。等間隔だと「1×」の目盛りに合わせたつまみが
  1.33 倍を指します（原型で実際に起きました）
- 決着のあとの待ちと、ラウンドの間の幕も、倍率に合わせて短く・長くなります（3 倍で約 0.67 秒、0.5 倍で 4 秒）。
  待ちは試合の時間（tick）で数えているためです。原型のラウンドの幕はボタンで送る形だったので、速さに
  左右されませんでした。待ちの間だけ等倍に戻すことはしていません。「1 tick ぶんの時間ごとに、倍率だけで
  進める tick の数を決める」形が崩れ、試合の場面によって速さが変わるためです。試合が決まった幕は消えず、
  勝ち数は横の板にも出ます
- 1 倍より遅いときも位置が滑らかに動くよう、描く側へ渡す補間の進み具合を、試合の時間の進み具合に換えます
  （`GameSpeed.progress`）。画面のループの進み具合（実時間）をそのまま渡すと、tick を進めなかった回に
  位置が1つ前の tick の側へ戻ります。1.5 倍のように1回に進む tick の数が変わる倍率では、動きの幅が
  そろいません（描く側が1つ前の tick の位置しか覚えていないため）
