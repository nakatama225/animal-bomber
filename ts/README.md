# どうぶつボンバー — TypeScript 版

動物同士が爆弾で戦う対戦ゲームの TypeScript 実装。ブラウザで動きます。

**現在の状態：段階 10 完了**（タイトル・設定の画面・試合の横の板・LAN の通信対戦のロビーまで）。段階ごとの主題は [docs/00-歩き方](docs/00-歩き方.md) にあります。

なぜ同じゲームを2つの言語で作るのか、2本が共有している設計判断は
[リポジトリ全体の README](../README.md) にあります。ここには TypeScript 版に
固有のものだけを書いています。

## Design Choice — この版で採用する設計と、その理由

### 1. 7層構造

```text
app          … 配線だけ
platform     … キーボード・フレームループ（ブラウザ API を触ってよい唯一の層）
presentation … 描画・音・HUD
net          … 通信対戦
ai           … CPU の思考
content      … 動物などのデータ
domain       … ゲームのルール（純粋。ブラウザにも実時間にも依存しない）
```

依存は必ず上から下に向かい、逆流させません。

### 2. 境界を、型定義を外すことで守る

`domain/` 専用の TypeScript 設定から DOM の型定義を外します。これにより
`domain/` の中に `document.getElementById(...)` と書くと、レビューを待たずに
その場で型エラーになります。設定ファイル1つで済み、新しく覚える記法もありません。

### 3. 動物の能力は「拡張に開く」形で表現する

動物ごとの特殊能力を、共通の interface と、それを実装したものを登録する表で表します。
6匹目を追加するときに触るのは、その動物のファイルと登録の1行だけです。
**既存の動物のファイルにも、ゲーム本体にも手を入れません。**

この形が正しく引けているかは、ぞうの突進で判定できます。突進は移動・破壊・取得・被弾の
4つに同時に割り込むので、ここが特別扱いなしで書けたなら、他の4匹は自動的に通ります。
書けなければ抽象の引き方が間違っているので、作り直します。

⚠️ 交換しているもの：追加は楽になりますが、**能力の一覧がコード上のどこにも現れません**。
対応漏れは実行するまで分かりません。同じ問いに対する Python 版の答え
（[py/](../py/) — 閉じた union で網羅性を保証する）と読み比べてください。

### 4. 通信対戦では盤面を送らず、操作だけを送る（ロックステップ）

LAN の対戦では、全員が同じ試合を手元で進め、1 tick ぶんの操作（意思そのものは1人1バイト。
JSON の文字列で送るので1通50バイトほど）だけを送り合います。同じ種と同じ操作からは必ず同じ試合になるように、段階1から作ってあるためです。
試合の側には通信のための分岐が無く、人間のプレイヤーに繋ぐ窓口を1つ差し替えただけです。

⚠️ 交換しているもの：通信量は原型（ホスト権威で盤面を毎フレーム配る）より1桁以上少なく
なりますが、**端末ごとに1ビットでも違う計算をすると試合がずれます**。そのため、ずれを
20 tick（1/3 秒）以内に見つけて止める仕組みを一緒に置いています。
詳しくは [docs/05-通信対戦](docs/05-通信対戦.md)。

### 5. 画面に何を出すかと、どう写すかを分ける

名札・時計・幕の中身と画面の流れは、文と値を返す純粋な関数とクラスで作り
（`presentation/hud/`・`presentation/menu/`）、要素に写す部分（`platform/ui/`）は薄く保ちます。
中身は node のテストで、写す部分は代わりの DOM（happy-dom）の上でクリックを流して確かめます。

⚠️ 交換しているもの：ブラウザを開かずに画面の流れまで確かめられますが、**見た目**
（CSS の効き・並び・文字のはみ出し）は確かめられません。
詳しくは [docs/06-画面と設定](docs/06-画面と設定.md)。

## How-to — 動かし方

```sh
npm install
npm run dev      # 開発サーバ（Vite）
npm run verify   # 型検査 + 層の依存検査 + lint + テスト（Vitest）
npm run graph    # docs/layers.svg に層の図を出す（Graphviz が要る）
npm run build    # 静的ファイルの出力
```

開くとタイトルが出ます。1人で CPU 3体と遊ぶ・2人で CPU 2体と遊ぶ・2人だけで遊ぶ、から選び、
動物とルールを決めて始めます。

LAN の通信対戦は、中継サーバ（[server/](../server/)）と開発サーバを1台の Mac で立て、
タイトルの「通信対戦」を選びます（URL に `?relay` を付けて開くのと同じ）。手順は
[docs/05-通信対戦](docs/05-通信対戦.md) にあります。

`verify` は5つを順に走らせます。

| | 見るもの |
|---|---|
| `tsc --noEmit` | 全体の型 |
| `tsc -p tsconfig.domain.json` | ルールの層がブラウザ API を使っていないこと |
| `eslint .` | ルールの層が乱数・実時間・環境依存の数学関数を呼んでいないこと |
| `depcruise` | 層の依存が逆流していないこと |
| `vitest run` | 振る舞いと、上の検査が実際に違反を落とすこと |
