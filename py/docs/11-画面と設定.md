# 11. 画面と設定（段階 10）

段階 10 で、原型（`legacy/animal-bomber.html`。v4.3.0）の「試合の外」と「盤面の外」を足しました。
起動の幕・タイトル・キャラ選び・ルール・設定とマニュアルと更新履歴・LAN の画面・ロビー・確認の
画面と、試合の画面の盤面の右の横の板（時計・ゲーム速度のつまみ・名札・キーの案内・ツールバー）、
ラウンドの幕と優勝の幕、ポーズの幕、画面の上の通知です。

この章で身につける判断は1つです。**画面に何を出すか（文と値）と、どう写すか（大きさ・位置・色）を
分ける。** 文と値を作る所は試合の状態を読むだけの純粋な関数とクラスにし（`presentation/menu/`・
`presentation/hud/`）、描く所（`presentation/render/`）は受け取った文を並べるだけにしました。
文と値は窓を開かずにテストでき、原型のファイルを読んで逐語で並べる検査も、文の側だけで書けます。
文の側が描く側を import しないことは、import-linter の contract（`pyproject.toml` の「文と値を作る側は
描く側を import しない」）で検査します。両方に出す絵文字は文の側（`presentation/emoji.py`）に置き、
描く側がそれを読みます。

原型に合わせるのが方針です（下の「原型に合わせない所」に書いたもののほかは、原型の文・見た目・
動きに合わせる）。

## 画面の流れ

```text
起動の幕（クリックか、なにかキー。3.2 秒で消える）
  └ タイトル
      ├ 1人 vs CPU×3 ／ 2人 vs CPU×2 ／ 2人タイマン → キャラ選び → ルール →「はじめる」→ 試合
      ├ LAN対戦 → LAN の画面 →「たてる」／「さんかする」→ じゅんびちゅう（5匹）→ つなぐ → ロビー
      │                                                        └ ホストの「はじめる ▶」→ 試合（全員）
      └ 設定・マニュアル・更新履歴

試合 → 決着で幕
  1台：「つぎのラウンド ▶」→ 次のラウンド ／ 優勝のあと「もういっかい」→ 同じ設定・新しい種の試合
       「⚙ 設定をやりなおす」→ タイトル
  通信対戦：ラウンドの幕は 2 秒で消える ／ 優勝のあと、ホストの「もういっかい」→ 次の試合
```

| どこで | 何を | 行き先 |
|---|---|---|
| どの画面でも | 戻る（Esc・Backspace・パッドの B・「← もどる」） | 1つ前の画面（原型の `MENU_BACK`）。タイトルと試合の画面では何もしない。LAN の画面で欄に字を打てる間は、Backspace は欄の字を1つ消すだけ（欄が空でももどらない） |
| ロビー・つないでいる最中の LAN の画面 | 戻る・「← せつぞくを切る」 | 「せつぞくを切ります。よいですか？」→ タイトル。ゲストのロビーにはカーソルで選べる項目が無いので、B・Esc では何も起きない（「← せつぞくを切る」をマウスで押す） |
| 試合（1台） | P・パッドの Start・「⏸ ポーズ」 | ポーズ（もう一度でやめる） |
| 試合 | ポーズ中（通信対戦ではいつでも）のパッドの Select | 「設定へもどりますか？」→ タイトル |
| 試合 | 横の板の「設定へ」 | タイトル（確認の画面を出さない。原型の注記 L3377-3380） |
| 試合 | 窓を閉じる | 終わる（どの画面でも） |

試合へ入るとき、出る動物の絵をまだ描いていなければ「じゅんびちゅう」を出してから描いておきます
（README の Design Choice 1.）。描いた絵はマスの大きさが変わらない限り使い回すので、2試合目からは、
新しい動物が出るときだけ出ます。

## 原型に合わせない所

| 所 | 原型 | この版 | 理由 |
|---|---|---|---|
| 通信対戦のラウンドの幕 | ホストがボタンで送る。ゲストには幕が出ない | 全員に幕を出し、決着のあとの待ち（`ROUND_INTERMISSION`＝2 秒）で消える。ボタンは無い | ロックステップでは全端末が同じ tick に次のラウンドへ進む必要がある。ボタンで送ると、押したことを全員に配る約束（中継と TypeScript 版も）を足すことになる。原型のゲストに幕が出ないのは、ゲストが盤面を進めないホスト権威の作りの結果。1台の試合の幕は原型どおりボタンで送る（待ちは使わない。幕が出ている間は試合を進めず、送ると `GameSession.start_next_round` で待ちを切り上げる） |
| 通信対戦の優勝の幕のボタン | ホストに「もういっかい」と「⚙ 設定をやりなおす」。ゲストには幕が出ない | ホストに「もういっかい」（ずれたら消す）、全員に「⚙ 設定をやりなおす」 | 全員に幕を出すので、ゲストにも抜ける道を出す（ゲストの「⚙ 設定をやりなおす」は、横の板の「設定へ」と同じくタイトルへ戻る） |
| 通信対戦のポーズ・ゲーム速度 | ホストが止める・速める（止めると全員の盤面が止まり、配った盤面でゲストにもポーズの幕が出る） | 出さない（曲も等倍。TypeScript 版と同じ） | 止めたこと・速さを全員へ同じ tick で配る約束が無い（中継と TypeScript 版の約束を変えることになる）。この端末だけ止めると、ほかの端末は入力を待って止まり、ポーズの幕ではなく待ちの帯が出る |
| 通信対戦の画面の揺れ | ホストの画面だけ揺れる。揺れの幅は update の中でしか変わらず（L1713-1714・L4403）、ゲストは update を呼ばず（L4249-4254）、配る盤面にも揺れの幅が無い（L3850-3877。粒子は配る）ので、ゲストの盤面は試合の間も決着のあとも揺れない（ゲストには幕も出ない。上の「通信対戦のラウンドの幕」） | 全端末が揺れる（どの端末も、手元で進めた tick ごとに `SceneTracker` で揺れを数える。幕の下も1台の試合と同じく揺れる） | ロックステップでは全員が手元で試合を進めるので、揺れも全員が同じ値で数えられる。原型のゲストが揺れないのは、ゲストが盤面を進めないホスト権威の作りの結果（配る盤面の項目に、揺れの幅が無い）。上の「通信対戦のラウンドの幕」で、ゲストに幕が出ない形を写さないのと同じ考え |
| ゲーム速度の進め方 | 経過時間に倍率を掛け、細かく刻んで進める（どの倍率でも1フレームの進みが揃う） | 実時間の tick の数に倍率を掛けた回数だけ進める（1回の長さは変えない。端数は持ち越す）。整数でない倍率では、描く値を、1つ前の tick の値と持ち越した端数の割合で混ぜる（1フレームの進みが倍率ぶんで揃う。そのかわり描く位置と時刻はいつも 1 tick 遅れる）。混ぜるのは、盤面にいるプレイヤーの位置と歩いた距離（脚の振り）・舌先までの長さ・外周の鍋の位置（0 の前後の折り返しは短いほうの向きで）・飛ぶ葱の位置（撃った tick は撃った位置と混ぜる。原型も撃った update のうちに進める）・粘膜爆弾の飛ぶ間（「flown − 1 + 割合」。投げた tick も同じ式で、0 より下にしない）・粒子の位置と寿命（生まれた tick は生まれたときの値と混ぜる。原型も出した update のうちに進める）と、時刻で決まる絵（爆弾の脈・アイテムの揺れ・うんこと粘膜爆弾の点滅・炎の揺らぎと跡の薄れ・掘る手の振り・止まっているかの見分け）に渡す描く時刻（`world.now − 1 + 割合`。ラウンドの最初の tick を進める前は 0 より小さい時刻のまま渡す）。残りの tick の数か期限で持つ値（爆弾の導火線・無敵の点滅・落とし穴と掘る身ぶりのゲージ・撒く身ぶりの進み・撃つ間隔の帯・長押しのゲージ）も描く時刻の値にする（残りの数で持つ値は、残りを決めた tick は決めた値のまま。期限で持つ無敵と撃つ間隔は、決めた tick に描く絵で、決めた長さより 1 − 割合 tick だけ長い（被弾の 75 tick は 76 tick まで点滅の濃い側のままで絵は同じ、撃つ間隔の帯は 3 秒の 1/180 まで長い）。外周へ回った tick の撃つ間隔は、回った直後の長さのまま描く。tick のまま残した値は次の行）。炎の位置は混ぜない（原型もマス単位で動く）。整数の倍率では混ぜない。瞬間移動（跳ぶ技・押しのけ・入れ替わり・延長戦）と、1つ前の tick に同じ場所にいなかったとき（盤面と外周の間を移った tick・延長戦で外周が閉じた tick）は混ぜず、ラウンドが替わったら新しい盤面の控えをすぐ取り直す（前のラウンドの位置と混ぜない）。ある tick に起きた変化（物が出る・消える・外周へ回る・残りを決める）は、その tick を進めたフレームから描くので、描く時刻より最大 1 tick 早く見える。外周へ回った鍋と、炎の跡に足したマスは、原型もその update のうちは動かさない・薄めない（外周を動かす negiMove は入力の段で、爆風・炎・葱で倒れて外周へ回すのはそのあとの段。跡は足した次の update から薄める。L2250・L2670-2676）ので、0.5 倍では出てから3フレーム同じ値で、4フレーム目から倍率ぶんずつ進む。突進で倒れたときだけは、原型もこの版も入力の段より前に外周へ回すので、動かす入力があればその update のうちに鍋を動かすが、この版はその tick の鍋を混ぜない（1つ前の外周の位置が無い）ので、0.5 倍では動いたあとの位置で3フレーム止まって見える。止めている間（ポーズ・幕）は端数を進めず、つまみを動かしても混ぜる割合を替えないので、描く位置は動かない（原型も止めている間は位置を動かさない。新しい倍率の割合は次に進めたフレームから使う） | ルールの層に経過時間を渡さない（リポジトリ共通の約束）ので、1回に進める長さを倍率で変えられない。等倍で混ぜないのは、原型と同じく描く位置を遅らせないため（等倍の見た目と描画の重さの場面の描き方も変えない）。このため、試合の最中に整数と整数でない倍率の間でつまみを動かしたフレームだけは、1フレームの進みが倍率ぶんから外れる（最大 1 tick。`shell/loop.py` の `GameSpeed`）。期限で持つ無敵と撃つ間隔を、決めた tick に描く絵だけ決めた長さで止めないのは、期限と描く時刻からは決めた tick を見分けられないため（撃つ間隔は、外周へ回った直後の残りが減って撃つ間隔と同じ長さになった tick と、期限の上では同じ。無敵は、決めた tick に描く絵が点滅の濃い側のままで変わらない。原型は決めた update のうちに描く絵が決めた値ちょうど。`render/views/player.py` の `invulnerable_left`・`render/views/lane.py` の `negibon_look`） |
| ゲーム速度が整数でないときの、絵を tick ごとに取っておく値（爆風の縮み・粘膜爆弾の着地のあとの揺れ・溶けるうんこ・跳び上がりの進み） | 残りを毎フレーム経過時間 × 倍率ずつ減らすので、毎フレーム動く | tick ごとに動く（0.5 倍では2フレームに1回）。ほかの位置・時刻・残りの数は混ぜる（上の行の「ゲーム速度の進め方」） | この4つは絵を tick ごとに取っておく（跳び上がりは進みを段に丸めず、残りの tick の数ごとに体の絵を取っておく。`render/baked/bodies.py`）ので、混ぜるには、取っておく絵の段の決め方から変えることになる |
| 曲の速さを変えたとき | 0.16 秒先まで予約した刻みを前の速さで鳴らしてから間隔が縮む（頭には戻らない。L999-1007） | 頭に戻さず、いまの1周の中の位置から新しい速さで鳴らし続ける（鳴らし始めた時刻から位置を数え、新しい速さの1周をその位置から始まるように回して鳴らす）。7通りの速さの1周は、起動のときに全部焼いておく（1周で約 20 ms、7通りで約 0.15 秒起動が延びる。つまみを動かす間に焼くと、そのぶんフレームが止まる） | ほぼ合わせた。残る違いは2つ：いま鳴っている刻みの残りも新しい速さで鳴る（原型は予約済みの刻みを前の速さで鳴らしきってから縮む。違いは先読みの 0.16 秒と刻み1つより短い）・鳴らし直す所で鳴っていた音符の残りが切れる。どちらも、焼いた1周を繰り返す作りのため（pygame には音を時刻を指定して予約する仕組みが無い。`audio/music.py`） |
| ロビーの「人間の人数」 | ホストが 1〜4 を選ぶ | 選ばない。始めた時点でつながっている端末が人間、残りが CPU | 人数を設定に足すと、中継と TypeScript 版の約束も変わる。つながっているのに CPU になる端末の扱いも要る |
| ロビーの CPU の強さの行 | CPU の枠だけ | いまつながっていない枠（始めたら CPU になる枠）だけ。その枠の見出しは「⚪ 空き・待機中」のまま、その下に CPU の強さの行を出す | 人間の人数を選ばないので、CPU の枠は「つながっていない枠」で決まる |
| 途中で抜けたプレイヤーの名札と強さ | 「CPU1・（1体目の CPU の強さ）」 | 番号は原型と同じ「CPU1」、強さは試合で実際に使う強さ（設定の枠ごとの強さ）。入れ替わりの通知（原型 L2354）の呼び方は、原型と同じく人間だったときの「2P」のまま（`hud/roster.py` の `Cpu.label`） | この版は段階 9 から枠ごとの強さで CPU を動かしている。名札は動きに合わせる |
| ホストが試合の最中に抜けたとき | ゲストは「ホストとの接続が切れました」でタイトルへ戻る | CPU がホストの枠を引き継いで続く（「ホストとの接続が切れました」はロビーで抜けたときだけ出す） | ロックステップでは全員が手元で試合を進めるので、ホストが抜けても続けられる（段階 9 の作り）。次の試合は始められない（案内の帯に出す） |

### 決めたこと（原型の動きから決めた所と、原型にも設計にも答えが無かった所）

項目ごとに、原型と同じ所と、この版で決めた所を分けて書きます。

- **止めている間に押したキーは忘れる**：原型と同じ所は、1台の試合をポーズ・ラウンドの幕・決まった試合で止めている間と、試合の外の画面で、押してすぐ離したキーを毎フレーム忘れること（原型の `loop()` も、止めている間を含めて毎フレーム `pressed.clear()`。L4277-4278）。忘れないと、ポーズ中に押した爆弾のキーで、再開した最初の tick に爆弾を置きます。この版で決めた所は、通信対戦の扱いです。通信対戦は止めないので、入力を待って進めないフレームに押したキーは忘れません（原型の通信対戦に入力を待つフレームは無い。py/AGENTS.md の「通信対戦」）。見分けるのは `MatchRunner.stopped`
- **盤面は盤面の四角で切って描く**：原型と同じ所は、盤面の外を描かないこと（原型の canvas も外を描かない）。この版で決めた所は、その形です。この版は窓の面を盤面と横の板で分け合うので、画面の揺れでずらした盤面と粒子が、盤面の枠と、枠と横の板の間のすき間へはみ出さないように、`Renderer` の前に描く面の切り取り（`set_clip`）を盤面の四角（枠の内側）にし、盤面の左上をそこへずらして描きます（`Renderer.draw` の `origin`）。描画の重さの場面も同じく切ります
- **盤面の枠**：原型と同じ所は、枠の太さ 3px（`var(--line)`）と角丸 14px、盤面の四隅を枠の内側の角丸（11px）で切ること（canvas の CSS。L73-74）、揺れても枠は動かないこと（揺れは canvas の中の translate。L4539-4541）、幕のぼかしが枠の上もぼかすこと（`#banner` の `backdrop-filter`。L139-141）。枠の置き方（原型は盤面の大きさの内側、この版は外側）と盤面の大きさは原型と違います（上の表の「盤面の枠の置き方と盤面の大きさ」）。この版で決めた所は、その描き方です。枠は窓の背景に1回だけ焼いておき、毎フレームは、盤面を描いたあとに、盤面の四隅に内側の角丸の外だけ不透明な小さい絵を4枚貼ります（`render/match_frame.py` の `BoardFrame`。描画の重さの場面も同じく貼る）。盤面の四角に重ねるポーズの幕と通信対戦の案内の帯も、原型の canvas の中身と同じく四隅で切れて見えるように、重ねたあとに四隅を貼り直します。ただし幕を重ねたフレームの案内の帯（通信対戦の決まったあと）は貼り直しません（幕のぼかした絵は枠もぼかしてあり、ぼけていない四隅を貼るとそこだけ浮いて見える。帯はこの版だけのもので、原型に答えが無い）。盤面のぼかした影（`box-shadow:0 18px 50px`）も、枠の下に窓の背景へ1回だけ焼きます（下の「ぼかした影」）
- **幕の間とポーズの間の盤面の揺れ**：原型と同じ所は、盤面を進めない間（ラウンドの幕・優勝の幕・ポーズ）も揺れは減らず、揺れが 0.2 を超えていれば、描くたびに見た目の乱数を横・縦の2つ取り出して盤面を揺らすこと（揺れは update でしか減らない。L4403-4405・L4540-4541。揺れの幅は `SceneTracker` の値）、背景（縦のグラデーション）と盤面の枠と角丸は揺れないこと（L4533-4537・L73-74）、ポーズの幕は揺れの内側で描くので、盤面と同じずれで動き、ずれた側の端の帯は暗くならないこと（L4539-4574。`render/overlay/pause.py`）、乱数を取り出す順（画面の揺れ → 爆風 → 被弾の揺れ。盤面の絵と幕の揺れは同じ1本の見た目の乱数から取り出す。`app/match_view.py`）です。ここで「原型」と比べているのは、1台の試合と、通信対戦のホストの画面です（原型の通信対戦のゲストの画面は揺れない。上の表の「通信対戦の画面の揺れ」）。揺れが 0.2 以下で決まった幕は、原型と同じく揺れず、乱数も取り出しません。時間切れで決まったラウンドも、決まる直前に爆発や被弾などで揺れていれば、その揺れが残ったまま幕の間も揺れます（原型も同じ）。この版で決めた所は、幕の間の揺らし方です。幕を出したフレームは、先に揺れのずれを取り出してから、盤面を揺らさずに描いてぼかします。ずれが (0, 0) でないフレームが来たら、ぼかした絵の盤面の四角を写して取っておき（揺れの無い幕では作らない）、ぼかした絵を貼ってから、盤面の四角に、ぼかして暗くした背景（初めて要るときに1回だけ作る）を貼り、その上にぼかした盤面を取り出したずれだけずらして盤面の四角で切って貼り、盤面の四隅（枠の内側の角丸の外）を、ぼかした絵から切り出した形で貼り直します（`render/overlay/banner.py` の `BannerOverlay.draw`）。原型と違って残る所は2つで、ずらしたぼかした盤面と後ろのぼかした背景の境目と、背景と枠の境目はぼけず、ぼかした盤面の写しの縁の数 px に、ぼかしで混ざった枠の色はずらすと一緒に動きます（原型は揺らした盤面を描いてから窓の全体をぼかすので、境目はぼけ、枠の色は揺れない枠の側に残る）。1024×768 の画面の 9 割で作った窓（マス 26）で、原型の順（揺らして描いてから窓の全体をぼかして暗くする）と比べた差は、幕の暗さを重ねたあとの 0〜255 の段で、揺れのずれ (−3, 3) と (3, −3) のとき盤面の四角の縁から 8px 以内の帯で最大 5〜6 段・それより内側は 2 段以内、ずれ ±5px（揺れの幅の上限 10 のとき。原型 L1546 の `Math.min(10, …)` と L4541）のとき縁から 10px 以内の帯で最大 6 段・それより内側は 2 段以内でした。暗さを重ねる前の段で数えると、縁の帯の最大は 25〜30 段です（同じ箱のぼかしと暗さで、順だけを替えて比べた。2026-10-25）。同じ物差しで並べると、ぼかしを箱のぼかしにしたことで手本のガウスぼかしと既に持つ差（README の Design Choice 1.）は、暗さを重ねる前で p99 8 段・最大 37 段、重ねたあとで p99 約 1.4 段・最大 約 7 段（37 段の 0.18 倍）なので、縁の帯の差の最大は、その最大と同じほどです。合わせていないのは、合わせるには、縁の帯を毎フレームぼかし直すのに加えて、四隅の絵の下に隠れた盤面の絵を別に持つことになるためです（`render/match_frame.py` の `draw_match_frame` は四隅を貼ってから返す。時間は測っていない）。写しを別にぼかし直す形は、写しの縁の枠の色を消しますが、境目がぼけないことは残ります。幕の間に取り出すのは揺れの2つだけで、爆風と被弾の揺れの乱数は取り出しません（上の表の「幕の下のぼかし」。見た目の乱数は試合と同期しないので、取り出す数はほかに作用しない）
- **幕の間の時計の明滅**：原型と同じ所は、残り 30 秒以下で決まったラウンドの幕の間も、時計の数字が 0.7 秒の周期で明滅し、幕の下でぼかして暗くした形で見えることです（原型の明滅は CSS のアニメーションで update を待たずに進み、幕の `backdrop-filter` は毎フレームぼかし直す。L79-80・L5547・L139-141）。この版で決めた所は、描き方です。幕の間は横の板を描かないので、明滅している間だけ、幕を出したフレームに時計の数字の四角のまわり（ぼかしの半径の2倍ずつ広げた四角）をぼかす前の絵として写しておき、幕の間のフレームごとに、その写しにそのフレームの数字を貼ってぼかして暗くし、数字の四角をぼかしの半径ずつ広げた所だけを、ぼかした絵の上（カードの下）に貼ります（`render/overlay/banner.py` の「幕の間の時計の明滅」）。貼る所は写した四角の端からぼかしの半径より内側なので、窓の全体をぼかし直した絵と同じ画素になります。横の板をスクロールして数字の上の端が窓の上の外に出ているときは、写した四角も貼る所も窓の上の端で切れますが、2つのぼかしはどちらも窓の端の画素を延ばすので、そこも同じ画素になります。数字の四角が窓に重ならないほどスクロールしているときは、写さず、貼りません（窓の外の数字は幕の下に見えない。原型もページごとスクロールし、幕の `backdrop-filter` は画面に見えている所だけをぼかす）。数字の位置は、幕を出したフレームに横の板を貼った位置で決めます（幕の下のぼかした板は、幕を出したフレームの位置のまま。幕の間は板をスクロールしない。上の表の「幕の間のホイール」）。幕を出したフレームに板が低くなってスクロールの量を丸めても、丸める前の、板を貼った位置で決めます。1回の時間は約 0.05 ms です（数字の四角 96×37。マス 60 の窓と 1024×768 の画面の 9 割の窓で、300 回の中央値 0.048 ms・最大 0.096 ms。2026-10-25、負荷 2.7）
- **ぼかした影**：原型と同じ所は、ぼかした影の値と重なりの順です（`.card` の `0 18px 50px`（.45）・`.bcard` の `0 24px 70px`（.6）・`.cfmBox` の `0 10px 30px`（.5）・canvas の `0 18px 50px`（.5）・`.go` の `0 12px 30px` の橙（.28）・`.logoPlate` の `0 12px 34px`（.55）と `0 0 0 6px` の輪・`::-webkit-slider-thumb` の `0 2px 7px`（.55）・`.logo` の字の `0 16px 26px`（.6）・`.logoSub` の字の `0 6px 16px`（.5）。値は `render/ui/theme.py`。CSS の並びの1つ目をいちばん上に重ね、影は大きさとスクロールの範囲に数えない）と、字の影は、ぼかさない影もぼかした影も字の形を影の色1色で塗ること（CSS の `text-shadow` の決まり。題の 🐰💣🐘 のような色の絵文字も、色つきの写しではなく形だけが影になる。`render/ui/typeset.py` の `TextPainter.shadowed` と `shapes.py` の `text_shadow`）です。この版で決めた所は、描き方とぼかし方です。影は箱・項目・字の絵を作るときに1回だけ同じ絵に焼き込み（`render/ui/shapes.py` の `shadowed_box`・`beneath`・`text_shadow`。形と色と影ごとに取っておく）、盤面の影は枠と一緒に窓の背景に焼くので、毎フレーム貼る絵の数は増えません。ぼかしは pygame の箱のぼかし（`box_blur`）を同じ半径で3回かけ、半径は、3回かけた標準偏差 √(r(r+1)) が CSS のぼかしの半径の半分（CSS の決まりでガウスのぼかしの標準偏差）にいちばん近い整数にしました。numpy で作った本物のガウスのぼかしと比べた差の平均は、不透明度 0.45 の影の 0〜255 の段で 0.35〜1.0 段（いちばん大きい差は 4.4 段）で、時間は半径によらず箱の大きさで決まります（画面のカードの影 1290×1000 で約 22 ms。描くのは画面を置き直すときだけ）。pygame の `gaussian_blur` は 12〜28 倍の時間がかかり、半径を標準偏差に合わせても差の平均が 0.8〜1.5 段、箱のぼかし1回は 1.3〜3.3 段でした（大きさ 1140×900・1000×60・400×160・480×380 の角丸の影で比べた）。もう1つ決めた所は、半透明の絵どうしの重ね方です。pygame の `blit` は下の画素が半透明のとき下の不透明度を数えずに混ぜるので、銘板の赤い輪の上に黒い影を重ねると、輪の赤が CSS の約 2 倍に出ます。影を重ねる所は、下の不透明度を数えて重ねます（`shapes.py` の `over`。下が全部透明か全部不透明の所は `blit` と同じ）
- **マウスが乗ったとき・押しているとき**：原型と同じ所は、`:hover` と `.go:active` の変化の前とあとの値（`.chip`・`.mbtn` は縁を `var(--accent)` にして 1px、`.acard` は 2px 上へ。`.go` は 2px 上へずらして影を `0 8px 0`・`0 16px 34px`（.34）に、押している間は 3px 下へずらして `0 2px 0` だけに。`.backb`・`.tbtn` は縁だけ）と、変化の長さ（`.chip`・`.acard`・`.mbtn` は 0.12 秒、`.go` は 0.1 秒、`.backb`・`.tbtn` はすぐ）と速さの変わり方（CSS の既定の `ease`。変化の途中の値は整数の px に丸める。上の表の「マウスが乗ったとき・押しているとき・カーソルの白い枠が出たときの、変化の途中の値」）、選ばれたチップとカードの縁は黄色のまま（`.on` の決まりがあとに書いてあるので勝つ）、項目は左のボタンを離したときに、押したときと同じ項目の上なら決まること（原型の `onclick`。押したときに決めると `.go:active` の沈みが見えない）、起動の幕も押して離したときに消え始めること（原型の `sp.onclick`。L5758。押している間に 3.2 秒が来て消え始めたら、離しても下の項目は決まらない。押したまま窓の外へ動かして離したら、項目と同じく何もしない。ブラウザの click は押した要素と離した要素に共通の祖先へ届くので、窓の外で離すと幕の `onclick` は呼ばれない。⚠️ ブラウザでは確認していない）、ゲーム速度のつまみは押したときに動くこと（原型の `<input type=range>`）、重なりの順（`transform` を持つ要素は積層文脈を作り、位置を指定していない兄弟より上に描かれる。変化の途中で値が 0px に近くても同じ。見た目に出るのは幕で、乗った「つぎのラウンド ▶」「もういっかい」の光が下の「⚙ 設定をやりなおす」にかかる。`render/ui/widgets.py` の `Widgets.paint_all`）、マウスの形（押せる物とゲーム速度のつまみの上で指になる。`cursor:pointer`。形を替えるのは `app/main.py` の `point`。SDL の dummy では形を作れないので替えない。文の上の形は上の表の「文の上のマウスの形」）です。この版で決めた所は次の5つです（当たりの四角は上の表の「マウスの当たりの四角」）。①押せない項目（欄の名前が読めない間の「さんかする」）は、乗っても押しても見た目を替えず、マウスの形も矢印のまま（押しても何も起きないので浮かせない。原型には押せないボタンが無い）。②押している見た目は、押した項目にマウスが乗っている間だけ（押したまま外へ動かすと戻る。外で離しても決まらないので、決まらない所では沈めない）。押している間に窓から離れたら、押した項目と、起動の幕の上で押したことを忘れる（戻って離しても決まらない。ブラウザの窓が離れたあとの click は原型に答えが無い）。③変化の途中で向きが替わったら、通知と同じく CSS の向きの替わった変化を縮める決まりで戻す（`presentation/menu/hover.py`）。④チップや動物のカードを押して選び直しても、同じ項目とみなして乗った見た目を続ける（原型は押すたびに項目を作り直し、作り直した項目には変化が始まらず、すぐ乗った見た目になる）。どの項目に乗っているかは、前のフレームに描いた四角で決めます（`app/shell.py`）。試合の横の板のツールバーは、板の絵を作り直さず、乗っているボタンの絵を1枚足して貼ります（マウスが乗っていないときは、試合の毎フレームの描き方は変わらない）。⑤試合の外の画面・幕・確認の画面は、項目を画面の絵に焼かずに、取っておいた項目の絵を毎フレーム貼ります（いちばん多いのはホストだけがつながったロビーで 68 枚、ルールは遊び方により 24〜38 枚。窓 1714×1100 で数えた）。描画の重さの場面と合格基準は試合の画面だけが対象ですが、この形の1フレームの描く時間も窓 1714×1100 で測り、いちばん項目の多いロビーでも p99 は 3.34 ms 以下でした（README の Design Choice 1.）

- **ゲーム速度で描く位置を混ぜる形と、TypeScript 版との違い**（この版で決めた所）：TypeScript 版（`GameSpeed.progress`・
  `Renderer` の `#viewOf`・`PositionHistory`）と同じく、1つ前の tick の位置と混ぜます
  （`shell/loop.py` の `GameSpeed.blend`・`render/views/player.py` の `drawn_position`・1つ前の位置は
  `render/scene/motion.py` が `TrackedMotion.previous` に持たせる）。違いは7つです。
  ① 等倍（整数の倍率）では混ぜない（TypeScript 版は描く時刻が tick の境目からずれるので、等倍でも
  実時間の端数で混ぜる。この版は境目に合わせて描く）。
  ② 割合は持ち越した端数だけ（TypeScript 版は実時間の端数も足し、上限 1 で止めるので、1.5 倍では
  1フレームの進みが揃わないまま残る。この版はどの倍率でも揃う）。
  ③ 瞬間移動は位置の差（縦か横に 0.5 マス以上）で見分けて混ぜない（TypeScript 版は延長戦と入れ替わりの
  イベントで1つ前の位置を捨てるだけで、跳ぶ技と押しのけは混ぜる）。この版も延長戦で開始位置へ
  移った tick と、1つ前の tick に盤面にいなかった（外周から戻った）ときは混ぜない。ラウンドが
  替わったフレームは、どちらも混ぜない（TypeScript 版は描く盤面と控えの盤面が違えば前の位置を

  ④ 時刻も混ぜるが向きが違う：TypeScript 版は `world.now + alpha` で先へ、この版は

  混ぜるのと同じ向きにそろえる）。
  ⑤ 通信対戦では混ぜない（TypeScript 版は通信対戦でも実時間の端数で混ぜる。この版の通信対戦は
  等倍なので、①と同じく境目に合わせて描く）。
  ⑥ 外周の鍋・飛ぶ葱・粘膜爆弾の飛ぶ間も混ぜる（TypeScript 版は混ぜず、外周の位置・葱の位置・飛んで

  どれも毎フレーム経過時間 × 倍率で進めるので、この版は原型に合わせる（1つ前の値は
  `TrackedMotion.previous_along`・`SceneTracker` の `leek_before` と `flown_before`）。
  ⑦ 残りの tick の数か期限で持つ値（爆弾の導火線・無敵の点滅・落とし穴と掘る身ぶりのゲージ・撒く
  身ぶりの進み・撃つ間隔の帯・長押しのゲージ）と舌先までの長さも、描く時刻の値にする（TypeScript 版は
  無敵と撃つ間隔を盤面の時刻で出す。`Renderer.ts` の `isInvulnerable(player, world.now)`・
  `drawNegibon`）。原型はどれも毎フレーム経過時間 × 倍率ずつ減らす・伸ばす（L4297・L4313・L4334・
  L4376・L4116）。期限で持つ無敵と撃つ間隔は期限と描く時刻から出し（`render/views/player.py` の
  `invulnerable_left`・`render/views/lane.py` の `negibon_look`）、残りの数で持つ値には `1 − 割合` を

  決めた値のまま）
- **横の板をすぐ作り直す場面**：原型と同じ所は、原型が 4 Hz を待たずに `renderCards` を呼ぶ場面で
  すぐ作り直すこと。この版で決めた所は、その場面の見分け方です。イベントで分かるもの（被弾・
  やられた・外周へ回った・入れ替わった・外周が閉じた・舌が焼き切れた・穴を掘り終えた・落とし穴に
  はまった・とくぎを使った・舌が戻った・延長戦・決着）は `presentation/hud/scoreboard.py` の

  ゲーム速度では、原型と同じく名札と時計を作り直さず、ポーズはキーの案内とポーズのボタンの字だけ

  区切りのあとに替わった名札の値（アイテムを拾ったあとの 💣🔥👟・落とし穴の残り秒・状態の行など）は、
  ポーズの間ずっと区切りの値のまま出ます（原型もポーズの間は update を呼ばない。L4256）。
  すぐ作り直さないときの間隔は、原型と同じく試合の時間の 0.25 秒（盤面の時刻の 15 tick。
  `G.elapsed%0.25<dt`。L4406）ごとで、区切りを越えたら中身が前と同じでも受け取ったことにします
  （`render/panel/side_panel.py` の `SidePanel.show`）。すぐ作り直しても区切りは動かしません（原型の
  すぐ作り直す呼び出しも、盤面の時刻で決まる区切りを動かさない）。実時間でなく盤面の時刻で数えるので、ゲーム
  速度で実時間の間隔が変わり、落とし穴の残り秒の刻み（と、そのときの時計の間隔）が倍率で変わります

  一部だけ替える印は受け取る）。幕の間（幕を出した次のフレームから）は横の板を描かないので、印も
  受け取らずに捨て、幕を外すフレームは描く盤面が替わるので作り直します
- **ページのスクロール**：原型と同じ所は、ページが縦に流れること（ブラウザがスクロールする）と、

## 窓の寸法

原型の `fitBoard`（L591-606）の式で1マスの大きさを決めます。窓の幅から横の板などの分（板 238・
すき間 16・余白 32・枠 6・スクロールバー 20 の 312px）、高さから 56px を引き、盤面とまわりの帯が
入るいちばん大きいマス（26〜60px。上限は描画の重さで決めた 60 のまま）。このうち窓が持つのは板・
すき間・枠で、画面のまわりの余白とスクロールバーは持ちません（窓は流れないので、はみ出した横の板
だけを窓の中でスクロールする）が、1マスの大きさを原型と同じにするため、原型と同じ幅を引きます。
窓の大きさとして、画面の 9 割を原型のブラウザの窓の大きさとみなして渡します（`app/main.py` の
`window_layout`）。

窓は、盤面のまわりに枠（3px・角丸 14px。原型の canvas の CSS。L73-74）を付けて左上に置き、枠の
右の外側からすき間 16px をあけて右に幅 238px の横の板を並べた大きさ（幅は盤面より 3px×2＋16＋238
広い）で、高さは枠を付けた盤面（盤面より 6px 高い）と横の板の高いほうを画面の 9 割で頭打ちに
したもの（上の表の「窓の高さと横の板」）。原型は枠を盤面の大きさの内側に描くので、原型の `.stage` の
幅は盤面より 16＋238 だけ広く、この版の窓は原型より 6px 広い（盤面のほうが横の板より高いときは
高さも 6px 高い。マス 60 で、原型は 1708×1094、この版は 1714×1100。上の表の「盤面の枠の置き方と
盤面の大きさ」）。盤面は枠の太さだけ内側（窓の左上から 3px 右・3px 下）に
描きます（`layout.WindowLayout.board_rect`）。窓は起動のときに1回だけ開くので、横の板の高さは、
いちばん行の多い形（1人で CPU 3体と遊ぶ試合の始まりの、名札4枚・つまみ・パッドの段・ポーズ中の

1行）は、横の板に置き換えて外しました。

  乗せた項目だけ縁が橙になって 0.12 秒で替わりきり（途中は `ease` の値）、外れると戻る。大きいボタンは
  押している間だけ 3px 沈み、押したまま外へ動かすと戻る。ツールバーのボタンは縁だけすぐ替わる。
  窓の外へ出たときと、起動の幕がクリックを受ける間は、どれにも乗らない。起動の幕は押して離したときに
  消え始め（押したまま窓の外で離したら消えない）、押している間に自動で消え始めたら、離しても下の項目を
  決めない。確認の画面と幕が出ている間は、
  つまみの位置を押しても倍率を変えない。窓から離れたら押した項目（起動の幕の上で押したことも）を忘れる。乗った大きいボタンの光は、
  幕の下のボタンにかかる。マウスの形は押せる物の上だけ指になり、形が替わるフレームにだけ替える。
  盤面の影は横の板の箱の間にも出る
- 窓を閉じたら終わる。試合の最中の Esc は何もしない
