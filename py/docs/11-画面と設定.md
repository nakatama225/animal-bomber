# 11. 画面と設定（段階 10）

段階 10 で、原型（`legacy/animal-bomber.html`。v4.3.0）の「試合の外」と「盤面の外」を足しました。
起動の幕・タイトル・キャラ選び・ルール・設定とマニュアルと更新履歴・LAN の画面・ロビー・確認の
画面と、試合の画面の盤面の右の横の板（時計・ゲーム速度のつまみ・名札・キーの案内・ツールバー）、
ラウンドの幕と優勝の幕、ポーズの幕、画面の上の通知です。

この章で身につける判断は1つです。**画面に何を出すか（文と値）と、どう写すか（大きさ・位置・色）を
分ける。** 文と値を作る所は試合の状態を読むだけの純粋な関数とクラスにし（`presentation/menu/`・
`presentation/hud/`）、描く所（`presentation/render/`）は受け取った文を並べるだけにしました。
文と値は窓を開かずにテストでき、原型のファイルを読んで逐語で並べる検査も、文の側だけで書けます。
文の側が描く側を import しないことは、import-linter の contract（`pyproject.toml` の「文と値を作る側は
描く側を import しない」）で検査します。両方に出す絵文字は文の側（`presentation/emoji.py`）に置き、
描く側がそれを読みます。

原型に合わせるのが方針です（下の「原型に合わせない所」に書いたもののほかは、原型の文・見た目・
動きに合わせる。合わせる作業が残っている所は、同じ節の「原型に合わせる作業が残っている所」に
並べた）。

## 画面の流れ

```text
起動の幕（クリックか、なにかキー。3.2 秒で消える）
  └ タイトル
      ├ 1人 vs CPU×3 ／ 2人 vs CPU×2 ／ 2人タイマン → キャラ選び → ルール →「はじめる」→ 試合
      ├ LAN対戦 → LAN の画面 →「たてる」／「さんかする」→ じゅんびちゅう（5匹）→ つなぐ → ロビー
      │                                                        └ ホストの「はじめる ▶」→ 試合（全員）
      └ 設定・マニュアル・更新履歴

試合 → 決着で幕
  1台：「つぎのラウンド ▶」→ 次のラウンド ／ 優勝のあと「もういっかい」→ 同じ設定・新しい種の試合
       「⚙ 設定をやりなおす」→ タイトル
  通信対戦：ラウンドの幕は 2 秒で消える ／ 優勝のあと、ホストの「もういっかい」→ 次の試合
```

| どこで | 何を | 行き先 |
|---|---|---|
| どの画面でも | 戻る（Esc・Backspace・パッドの B・「← もどる」） | 1つ前の画面（原型の `MENU_BACK`）。タイトルと試合の画面では何もしない。LAN の画面で欄に字を打てる間は、Backspace は欄の字を1つ消すだけ（欄が空でももどらない） |
| ロビー・つないでいる最中の LAN の画面 | 戻る・「← せつぞくを切る」 | 「せつぞくを切ります。よいですか？」→ タイトル。ゲストのロビーにはカーソルで選べる項目が無いので、B・Esc では何も起きない（「← せつぞくを切る」をマウスで押す） |
| 試合（1台） | P・パッドの Start・「⏸ ポーズ」 | ポーズ（もう一度でやめる） |
| 試合 | ポーズ中（通信対戦ではいつでも）のパッドの Select | 「設定へもどりますか？」→ タイトル |
| 試合 | 横の板の「設定へ」 | タイトル（確認の画面を出さない。原型の注記 L3377-3380） |
| 試合 | 窓を閉じる | 終わる（どの画面でも） |

試合へ入るとき、出る動物の絵をまだ描いていなければ「じゅんびちゅう」を出してから描いておきます
（README の Design Choice 1.）。描いた絵はマスの大きさが変わらない限り使い回すので、2試合目からは、
新しい動物が出るときだけ出ます。

| `shell/` | `keyboard.py`・`gamepad.py`・`loop.py` | キーの割り当てとメニューのキー・パッドの Start と Back とメニューの押し始め・ゲーム速度（`GameSpeed`） |

`Shell` は窓（`pygame.display`）に触りません。窓を開く・描いた面を窓へ貼る・イベントを受け取るのは
`app/main.py` で、`Shell` は窓の大きさの面に描くだけです。そのため、台本のイベントを順に渡す
通しのテスト（`tests/app/test_shell.py`）が、窓を開かずに書けます。

## 原型に合わせない所

| 所 | 原型 | この版 | 理由 |
|---|---|---|---|
| 通信対戦のラウンドの幕 | ホストがボタンで送る。ゲストには幕が出ない | 全員に幕を出し、決着のあとの待ち（`ROUND_INTERMISSION`＝2 秒）で消える。ボタンは無い | ロックステップでは全端末が同じ tick に次のラウンドへ進む必要がある。ボタンで送ると、押したことを全員に配る約束（中継と TypeScript 版も）を足すことになる。原型のゲストに幕が出ないのは、ゲストが盤面を進めないホスト権威の作りの結果。1台の試合の幕は原型どおりボタンで送る（待ちは使わない。幕が出ている間は試合を進めず、送ると `GameSession.start_next_round` で待ちを切り上げる） |
| 通信対戦の優勝の幕のボタン | ホストに「もういっかい」と「⚙ 設定をやりなおす」。ゲストには幕が出ない | ホストに「もういっかい」（ずれたら消す）、全員に「⚙ 設定をやりなおす」 | 全員に幕を出すので、ゲストにも抜ける道を出す（ゲストの「⚙ 設定をやりなおす」は、横の板の「設定へ」と同じくタイトルへ戻る） |
| 通信対戦のポーズ・ゲーム速度 | ホストが止める・速める（止めると全員の盤面が止まり、配った盤面でゲストにもポーズの幕が出る） | 出さない（曲も等倍。TypeScript 版と同じ） | 止めたこと・速さを全員へ同じ tick で配る約束が無い（中継と TypeScript 版の約束を変えることになる）。この端末だけ止めると、ほかの端末は入力を待って止まり、ポーズの幕ではなく待ちの帯が出る |
| ゲーム速度の進め方 | 経過時間に倍率を掛け、細かく刻んで進める（どの倍率でも1フレームの進みが揃う） | 実時間の tick の数に倍率を掛けた回数だけ進める（1回の長さは変えない。端数は持ち越す）。整数でない倍率では、盤面にいるプレイヤーを描く位置を、1つ前の tick の位置と持ち越した端数の割合で混ぜる（1フレームの進みが倍率ぶんで揃う。そのかわり描く位置はいつも 1 tick 遅れる）。整数の倍率では混ぜない。瞬間移動（跳ぶ技・押しのけ・入れ替わり・延長戦）は混ぜず、ラウンドが替わったら新しい盤面の控えをすぐ取り直す（前のラウンドの位置と混ぜない）。止めている間（ポーズ・幕）は端数を進めず、つまみを動かしても混ぜる割合を替えないので、描く位置は動かない（原型も止めている間は位置を動かさない。新しい倍率の割合は次に進めたフレームから使う） | ルールの層に経過時間を渡さない（リポジトリ共通の約束）ので、1回に進める長さを倍率で変えられない。等倍で混ぜないのは、原型と同じく描く位置を遅らせないため（等倍の見た目と描画の重さの場面の描き方も変えない）。このため、試合の最中に整数と整数でない倍率の間でつまみを動かしたフレームだけは、1フレームの進みが倍率ぶんから外れる（最大 1 tick。`shell/loop.py` の `GameSpeed`） |
| 曲の速さを変えたとき | 0.16 秒先まで予約した刻みを前の速さで鳴らしてから間隔が縮む（頭には戻らない。L999-1007） | 頭に戻さず、いまの1周の中の位置から新しい速さで鳴らし続ける（鳴らし始めた時刻から位置を数え、新しい速さの1周をその位置から始まるように回して鳴らす）。7通りの速さの1周は、起動のときに全部焼いておく（1周で約 20 ms、7通りで約 0.15 秒起動が延びる。つまみを動かす間に焼くと、そのぶんフレームが止まる） | ほぼ合わせた。残る違いは2つ：いま鳴っている刻みの残りも新しい速さで鳴る（原型は予約済みの刻みを前の速さで鳴らしきってから縮む。違いは先読みの 0.16 秒と刻み1つより短い）・鳴らし直す所で鳴っていた音符の残りが切れる。どちらも、焼いた1周を繰り返す作りのため（pygame には音を時刻を指定して予約する仕組みが無い。`audio/music.py`） |
| ロビーの「人間の人数」 | ホストが 1〜4 を選ぶ | 選ばない。始めた時点でつながっている端末が人間、残りが CPU | 人数を設定に足すと、中継と TypeScript 版の約束も変わる。つながっているのに CPU になる端末の扱いも要る |
| ロビーの CPU の強さの行 | CPU の枠だけ | いまつながっていない枠（始めたら CPU になる枠）だけ。その枠の見出しは「⚪ 空き・待機中」のまま、その下に CPU の強さの行を出す | 人間の人数を選ばないので、CPU の枠は「つながっていない枠」で決まる |
| 途中で抜けたプレイヤーの名札と強さ | 「CPU1・（1体目の CPU の強さ）」 | 番号は原型と同じ「CPU1」、強さは試合で実際に使う強さ（設定の枠ごとの強さ）。入れ替わりの通知（原型 L2354）の呼び方は、原型と同じく人間だったときの「2P」のまま（`hud/roster.py` の `Cpu.label`） | この版は段階 9 から枠ごとの強さで CPU を動かしている。名札は動きに合わせる |
| ホストが試合の最中に抜けたとき | ゲストは「ホストとの接続が切れました」でタイトルへ戻る | CPU がホストの枠を引き継いで続く（「ホストとの接続が切れました」はロビーで抜けたときだけ出す） | ロックステップでは全員が手元で試合を進めるので、ホストが抜けても続けられる（段階 9 の作り）。次の試合は始められない（案内の帯に出す） |
| CPU の動物の選び方 | 残りの動物から `Math.random` で | 残りの動物から、試合の種から作った乱数で（重ならない規則は同じ） | 同じ種で同じ顔ぶれになり、テストできる（TypeScript 版と同じ） |
| 読み込みの画面 | 無い | 「じゅんびちゅう」を出す | この版は試合に出る動物の絵を先に描いておく（描かないと初めて出たフレームが遅れる。README の Design Choice 1.） |
| 幕の下のぼかし | 毎フレーム、標準偏差 3px のガウスぼかし（CSS の blur(3px)）。幕の間も、爆風の白い芯が毎フレームちらつく（L4745-4748） | 幕を出したときの盤面と横の板を1回だけ、幅 9px の箱でぼかす（pygame の `box_blur` 半径 4。手本との差の平均 1.2。マス 60 で約 12 ms）。幕の間は盤面と横の板を描かず、ぼかした絵とカードだけを貼る（爆風はちらつかない） | 毎フレームぼかすと、1回の 12 ms だけで描画の重さのしきい値（8.33 ms）を超える。爆風のちらつきを写すには、毎フレーム盤面を描いてぼかし直すことになり、同じくしきい値を超える。ガウスぼかし（pygame の `gaussian_blur` 半径 3。差の平均 0.7）は1回で約 110 ms かかり、幕が出るフレームが止まって見える。測った数と選び方は README の Design Choice 1.（選んだ作り方は `render/overlay/banner.py`） |
| 窓の高さと横の板 | ページ全体が縦に流れる（横の板が画面より高くてもスクロールして見られる） | 窓の高さは盤面と横の板の高いほうを、画面の 9 割で頭打ちにする。横の板がそれより高いときは、横の板だけをマウスのホイールでスクロールする | 窓では盤面を動かすと遊べないので、板だけを動かす。名札4枚・つまみ・パッドの段と Select の行まであると、板はこの Mac の書体で 996px になり（下の「窓の寸法」）、1440×900 の画面では、板の高さに合わせた窓は画面より高くなる |
| 原型の文の一部の語 | 下の「言い換えた原型の文」の語を含む | 熟語に言い換える | リポジトリの文の決まり |
| LAN の行き先 | 開いたページのアドレス | 「たてる」はこの Mac の中継（localhost）、「さんかする」は打ち込んだ名前（`--relay` を付けて起動したらその値を最初から入れておく） | この版はブラウザのページではないので、開いたアドレスが無い |
| 中継につなげなかったとき | 何も出さずにタイトルへ戻る（「接続しています…」が残る） | LAN の画面に留まり、「接続しています…」の行に理由を出す（また押せる） | この版は打ち込んだ名前につなぐので、名前を修正して押し直せるようにした |
| タイトルへ戻ったあとの「接続しています…」 | 残る（次に LAN の画面を開いても出ている） | タイトルへ戻るときに消す | 原型の表示の不具合。残すと、つないでいないのに接続中と出る |
| LAN の画面の、中継の名前の欄 | 無い（開いたページのアドレスにつなぐ） | 「さんかする」でつなぐ中継の名前を打ち込む欄を出す。欄に字を打てる間の Backspace は欄の字を1つ消すだけで、欄が空でももどらない | この版はブラウザのページではないので、開いたアドレスが無い（上の「LAN の行き先」）。Backspace でもどらないのは、消しているうちに1回多く押して、画面を出てしまわないように |
| LAN の画面の注記の2文目 | 表示された URL をブラウザで開いておく | 「たてる」を押す Mac で中継サーバを立てておく | この版はブラウザのページではなく、中継サーバを別に立てて遊ぶ（README の How-to） |
| つないでいる最中の「たてる」「さんかする」 | 出したままで、押すたびにもう1本つなぐ（前の接続を閉じずに上書きする） | 出さない（つないでいる間は「接続しています…」と「← もどる」だけ。戻る・パッドの B・Escape は、原型と同じく「せつぞくを切ります。よいですか？」を開く） | 中継との接続（`app/lan.py` の `LanMatch`）は1本しか持たない。原型の動きは、前の接続が残る不具合。押しても反応しないボタンは出さない（原型の `applyRoleUI` の注記と同じ考え。L4196-4199） |
| 欄の名前が読めない間の「さんかする」 | 無い（押せないボタンが無い。欄も無い） | 薄く描き、押せない（欄の名前が「ホスト名[:ポート]」に読めない間。`--relay` を付けずに起動して LAN の画面を開くと、欄が空なので「さんかする」は薄い） | 原型の `applyRoleUI` の注記が避けるのは、押せそうに見えるのに何も起きないボタン。薄く描けば、押せないことが見て分かる。押せないのは一時の状態（欄に名前を打つと押せる）で、隠すと、欄が空の間は「さんかする」があること（名前を打てば押せること）が分からない |
| `--relay` を付けて起動したとき | 無い（ページを開くと起動の幕からタイトルへ） | 段階 9 と同じく、起動してすぐその中継につなぐ（ロビーから始まる） | 段階 9 の遊び方（README・[10-通信対戦](10-通信対戦.md)）を変えない |
| マウスのホイールの量 | ブラウザの既定 | 1目盛りで 48px（`app/shell.py` の `WHEEL_PX`） | ブラウザの既定（数十 px〜100px ほど）に寄せた。⚠️ 実機のマウスとトラックパッドでは見ていない |
| Option・Command を離したとき | ほかの押しているキーを捨てる（macOS は修飾キーを押している間、ほかのキーを離したことを送らないことがあるので、キーの繰り返しで押し直させる。L3093-3098） | 捨てない | pygame は既定でキーの繰り返しを送らないので、捨てると押したままの向きが戻らない |

### 原型に合わせる作業が残っている所

次の所は原型と違います。原型に合わせる作業が残っているので、上の表には置かず、何が原型と違うかだけを
1行ずつ書きます。

1. 箱の飾りと、マウスで動く見た目：原型は箱（`.card`・`.bcard`・`.cfmBox`・`.go`）と盤面（canvas）にぼかした影（`box-shadow`）を、ロゴの銘板のまわりに 6px の薄い赤の輪（`.logoPlate`）を、ロゴと題の字にぼかした影（`.logo`・`.logoSub`）を付け、押せる物にマウスが乗ると縁が橙になって 1〜2px 浮き（`:hover`。0.12 秒で変わる）、押している間の「はじめる」が沈む（`.go:active`）。この版はどれも描かない（ぼかさない影は写してある。`render/ui/shapes.py`）
2. 盤面の枠：原型は盤面のまわりに 3px の枠（`var(--line)`）を角丸 14px で描き、盤面の四隅を内側の角丸で切る（canvas の CSS。L73-74）。この版は盤面を四角のまま置き、枠を描かない
3. 幕の間の盤面の揺れ：原型は、被弾で決まったラウンドの幕の間も、決着の揺れが残って盤面が揺れ続ける（揺れは update でしか減らない。L4403-4405・L4540-4541）。この版は幕を出したときの絵を止めたまま貼る
4. ゲーム速度が整数でないときの、外周の鍋・飛ぶ葱・粘膜爆弾の飛ぶ間の位置：原型は毎フレーム経過時間 × 倍率で進めるので毎フレーム動く。この版は tick のまま（0.5 倍では2フレームに1回動く）。炎は原型もマス単位で動く
5. 同じく、時刻で決まる絵と粒子（爆弾の脈・点滅・脚の振り・アイテムの揺れ・粒子）：原型は毎フレーム動く。この版は tick ごとに動く（TypeScript 版は時刻を `world.now + alpha` で混ぜる）
6. 横の板の作り直しの間隔：原型は試合の時間で 0.25 秒ごと（`G.elapsed%0.25`。L4406）なので、ゲーム速度で実時間の間隔が変わる（3 倍で約 83 ms）。この版は実時間で 250 ms ごと（落とし穴の残り秒の刻みと、そのときの時計の間隔が、倍率で原型と変わる）
7. 通知の幅：原型は、窓の幅の半分 − 40px を超える文を折り返す（`.toast` は幅を持たず `left:50%`。L151-154）。この版はいつも1行（1024×768 の画面で延長戦の通知が出ると、原型は2行）

名札が退場・葱ボンに替わったときの 0.2 秒の薄れ（`.pcard{transition:.2s}`。L85）は、原型でも見えません
（名札を毎回作り直すので、変化が始まらない。L5497-5502）。写す物が無いので、ここにも置きません。

### 決めたこと（原型の動きから決めた所と、原型にも設計にも答えが無かった所）

項目ごとに、原型と同じ所と、この版で決めた所を分けて書きます。

- **止めている間に押したキーは忘れる**：原型と同じ所は、1台の試合をポーズ・ラウンドの幕・決まった試合で止めている間と、試合の外の画面で、押してすぐ離したキーを毎フレーム忘れること（原型の `loop()` も、止めている間を含めて毎フレーム `pressed.clear()`。L4277-4278）。忘れないと、ポーズ中に押した爆弾のキーで、再開した最初の tick に爆弾を置きます。この版で決めた所は、通信対戦の扱いです。通信対戦は止めないので、入力を待って進めないフレームに押したキーは忘れません（原型の通信対戦に入力を待つフレームは無い。py/AGENTS.md の「通信対戦」）。見分けるのは `MatchRunner.stopped`
- **盤面は盤面の四角で切って描く**：原型と同じ所は、盤面の外を描かないこと（原型の canvas も外を描かない）。この版で決めた所は、その形です。この版は窓の面を盤面と横の板で分け合うので、画面の揺れでずらした盤面と粒子が、盤面と横の板の間のすき間へはみ出さないように、`Renderer` の前に描く面の切り取り（`set_clip`）を盤面の四角にします。描画の重さの場面も同じく切ります
- **音量**：原型と同じ所は、「無音」を押した音を鳴らしてから音量を 0 にする順（ほとんど聞こえない）。この版で決めた所は、音量の当て方です。焼いた音には原型の系統の音量（効果音 0.55・曲 0.15）を掛けてあるので、音の設定は音量 1.0（鳴らす）か 0.0（鳴らさない）を当てます
- **中継との接続が切れたとき**：原型と同じ所は、つないだあと（ロビーに入ったあと）に中継との接続が切れたら、タイトルへ戻して「サーバとの接続が切れました」と出すこと（原型 L3735）。この版で決めた所は、ずれて止まった試合の扱いです。盤面を残して案内の帯に理由を出します（原型にずれは無い）
- **対応していないコントローラーの通知**：原型と同じ所は、繋がっている順で最初のパッドより前に対応していない機器を見つけたら、使っているパッドが無いときに1回だけ「🎮 このコントローラーには対応していません（名前）」を出す条件（原型の `pickPad`）。この版で決めた所は、どの機器を「対応していない」とみなすかで、SDL がジョイスティックとしては見つけたが、ゲームコントローラーの決まった並びにできない機器にしました（名前は SDL の機器の名前）
- **ゲーム速度で描く位置を混ぜる形と、TypeScript 版との違い**（この版で決めた所）：TypeScript 版（`GameSpeed.progress`・
  `Renderer` の `#viewOf`・`PositionHistory`）と同じく、1つ前の tick の位置と混ぜます
  （`shell/loop.py` の `GameSpeed.blend`・`render/views/player.py` の `drawn_position`・1つ前の位置は
  `render/scene/motion.py` が `TrackedMotion.previous` に持たせる）。違いは5つです。
  ① 等倍（整数の倍率）では混ぜない（TypeScript 版は描く時刻が tick の境目からずれるので、等倍でも
  実時間の端数で混ぜる。この版は境目に合わせて描く）。
  ② 割合は持ち越した端数だけ（TypeScript 版は実時間の端数も足し、上限 1 で止めるので、1.5 倍では
  1フレームの進みが揃わないまま残る。この版はどの倍率でも揃う）。
  ③ 瞬間移動は位置の差（縦か横に 0.5 マス以上）で見分けて混ぜない（TypeScript 版は延長戦と入れ替わりの
  イベントで1つ前の位置を捨てるだけで、跳ぶ技と押しのけは混ぜる）。この版も延長戦で開始位置へ
  移った tick と、1つ前の tick に盤面にいなかった（外周から戻った）ときは混ぜない。ラウンドが
  替わったフレームは、どちらも混ぜない（TypeScript 版は描く盤面と控えの盤面が違えば前の位置を
  使わず、この版は幕を送ったときに新しい盤面の控えをすぐ取り直す）。
  ④ 時刻は混ぜない（TypeScript 版は `world.now + alpha` で点滅や身ぶりの時刻も混ぜる）。
  ⑤ 通信対戦では混ぜない（TypeScript 版は通信対戦でも実時間の端数で混ぜる。この版の通信対戦は
  等倍なので、①と同じく境目に合わせて描く）
- **横の板をすぐ作り直す場面**：原型と同じ所は、原型が 4 Hz を待たずに `renderCards` を呼ぶ場面で
  すぐ作り直すこと。この版で決めた所は、その場面の見分け方です。イベントで分かるもの（被弾・
  やられた・外周へ回った・入れ替わった・外周が閉じた・舌が焼き切れた・穴を掘り終えた・落とし穴に
  はまった・とくぎを使った・舌が戻った・延長戦・決着）は `presentation/hud/scoreboard.py` の
  `refreshes_panel` が決めます。ラウンドの始まり（描く盤面が替わった）・ポーズ・ゲーム速度・名札が
  CPU に替わったとき・幕を出したときと外したときは、`app/shell.py` の `Shell` が別に作り直しの印を
  立てます
- **ページのスクロール**：原型と同じ所は、ページが縦に流れること（ブラウザがスクロールする）と、
  マニュアルと更新履歴の長い箱の中をスクロールすること（`overflow:auto`。L227・L232）。この版で
  決めた所は、窓に収まらない画面のスクロールの仕方で、ページ全体をマウスのホイールでスクロール
  します（ホストのロビーは窓 1708×1094 にも収まらない）。長い箱の上では、箱の中をスクロールします
