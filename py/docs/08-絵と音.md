# 絵と音

段階 7 で、原型の手描きの絵と、合成の音を足しました。原型は画像も音のファイルも持たず、
絵は canvas に命令を並べて描き、音は Web Audio に波形と音量の予定を入れてその場で
合成していました。この版は、その**命令と数値を、記録した正解と突き合わせながら逐語に写し**、
**毎フレームの描き方と音の鳴らし方は、pygame-ce で間に合う形に作り直しました**。

| | 逐語に写した所 | Python のやり方で作り直した所 |
|---|---|---|
| 絵 | 描く関数の命令の列（並べる順・値・見た目の乱数を引く順） | 毎フレームは、段に丸めた入力ごとに1回だけ描いて取っておいた絵を貼る |
| 粒子と画面の揺れ | 出し方の式・乱数を引く順・1 tick の動かし方 | ルールの層のイベントと、前の tick との比べから、描く側で作る |
| 音 | 効果音と曲の部品の予定（周波数・音量・削り方の時間の流れ） | 予定を Web Audio の仕様の式で読んで合成し、起動時に焼いておく |

正解は原型です。TypeScript 版の描画も参考にしましたが、原型と違う所は原型に合わせました
（下の「原型に合わせて TypeScript 版と違えた所」）。

---

## 原型を node で読み込んで、正解を記録する

原型（`legacy/animal-bomber.html`）の script を node で読み込み、canvas と AudioContext を
「呼ばれた命令と代入を順に記録する偽物」に替えます（`tools/legacy_oracle/legacy_env.js`）。
`Math.random` も決めた値の列に替え、引いた値を記録します。原型の関数を、いろいろな入力で
呼んで書き出したものが、テストの固定値になります。

| 固定値 | 何を記録したか | 作り直し方（リポジトリのいちばん上で） |
|---|---|---|
| `tests/presentation/legacy_art_ops.json` | 描く関数 276 通りの、canvas の命令の列と引いた乱数（マス 44 と 60。うち 34 通りは段階 8 の外周の鍋と葱） | `node py/tools/legacy_oracle/legacy_art.js py/tests/presentation/legacy_art_ops.json` |
| `tests/presentation/legacy_sound_values.json` | 効果音 36 種と曲の 32 刻みの、部品の繋がりと値の予定 | `node py/tools/legacy_oracle/legacy_sound.js py/tests/presentation/legacy_sound_values.json` |
| `tests/presentation/legacy_particles.json` | 粒子を出す関数 35 通りの、使った乱数・出た粒子・揺れ（うち 9 通りは段階 8 の葱ボンと延長戦） | `node py/tools/legacy_oracle/legacy_particles.js py/tests/presentation/legacy_particles.json` |

どれも何度作っても同じものになります。原型の入力は秒ですが、固定値の入力は tick の数で
割り切れる値にしてあり、この版の描く関数には tick の数から作った試合の状態を渡して比べます
（`tests/presentation/test_legacy_art.py`）。粒子は、原型のその場面にあたるイベントを作って
渡し、原型と同じ乱数の列で同じ粒子が出るかを見ます（`test_scene_particles.py`）。

## canvas と同じ口と、2つの実装

描く関数（`presentation/render/art/`）は、原型の `ctx` と同じ名前の命令を持つ口
（`render/canvas/protocol.py` の `Canvas`）に描きます。受け手は2つあります。

- 記録する canvas（`canvas/recording.py`）：命令を記録する。原型の記録と突き合わせる
- pygame の面に描く canvas（`canvas/surface.py`）：命令をそのまま絵にする。2倍の大きさで
  描いてから、色に不透明度を掛けた形のまま 2×2 を平均して縮める

描く関数を1つ書けば、原型との突き合わせと絵の両方が同じコードから出ます。ただし面に描く
canvas は重く、描く面の全体（マス 60 で 1454×1094）を描くと、2倍の小数の配列が 100MB に
なります。盤面のマスだけでも、マス 44 で1枚に 0.5 秒かかりました。毎フレームには使えません。

## 段に丸めて取っておく絵と、ずれの上限

毎フレームは、取っておいた絵を貼るだけにします（`render/sprites.py`・`render/baked/`）。
脈打ち・揺れ・大きさのように続けて変わる入力は、段に丸めて、段ごとに1回だけ描いて取って
おきます。段の数は、先に「どこまでずれてよいか」を決めてから出しました。

| 入力 | 段の数 | ずれの上限 |
|---|---|---|
| アイテムの枠の脈打ち | 21 | 枠の色で 255 段のうち 2 段 |
| 鼻水で溶けている間（27 tick）のアイテムの枠の脈打ち・絵文字の揺れ | 3・3 | 枠の色で 255 段のうち 19 段（薄れる前の不透明度で）・1px（先に描いておける組み合わせの数に収めるため。`baked/items.py` の `MELT_PULSE_LEVELS`・`MELT_BOB_LEVELS`） |
| 爆弾の脈打ちの倍率 | 21 | 赤い光の半径で 0.30px・中心からいちばん遠い火花の外の縁で 0.38px（マス 60） |
| 脚と腕の振り | 17 | 横向きの脚で 0.41px |
| 炎の火の玉・芯の大きさ | 23・15 | 半径で 0.25px |
| 四角い粒の一辺・爆風のちらつく芯 | 0.5px ごと | 0.25px |
| 体・舌・粒子などの位置 | 整数の px | 0.5px |

ずれの上限は、2つのテストで確かめています。段の幅の半分まで入力を動かしたときに、上限を
超えないこと（`test_quantization_bounds.py`）と、取っておいた絵を、取っておかずに描いた
絵と画素で比べて、差が「丸めの幅」と「段の幅の半分まで動かして描いた絵の差」に収まること
（`test_baked*.py`）。段の数を変えたら、上限のテストも直します。溶けている間の段は、上限の
テストに入れていません（画素で比べるほうには入っています）。

### 薄れる絵は、不透明度ごとの写しを貼る

消える前に点滅するアイテム・薄れる粒子・炎の跡のように、全体を薄めて貼る絵は、貼るたびに
`set_alpha` で薄めると重くなります（段階 0 の測定。README の Design Choice 1.）。整数の
不透明度ごとに薄めた写しを作って取っておき、薄めずに貼ります。

もう1つ、原型の `globalAlpha` は塗る命令ごとに掛かります。命令が重なる絵をまとめて薄めると、
重なった所の色が原型と違います（下の命令の色が透けない）。点滅中のアイテムは塗る命令1つずつの
絵を薄めて重ね、点滅中の体は canvas の不透明度を下げてから描き直して取っておきます。

### 盤面は、マスの絵を足し合わせた1枚にする

盤面の左上が小数の px にあると（マス 44 なら 27.28px）、マスの継ぎ目の画素を、隣り合う
2つのマスが分け合います。マスの絵を1枚ずつ重ねると、その画素に背景が透けて、継ぎ目に線が
出ます（マス 44 で 255 段のうち 37 段）。隣り合うマスの覆う割合は足すと 1 になるので、
マスの絵を色に不透明度を掛けた形で足し合わせて1枚にし、それを貼ります
（`baked/board.py` の `BoardLayer`）。盤面はブロックが壊れたときしか変わらないので、
毎フレームは1回貼るだけです。

## 1枚の絵を組み立てる

`render/renderer.py` の `Renderer` が、取っておいた絵を原型の draw と同じ順に貼ります
（背景 → 画面の揺れ → 床と壁 → アイテム → 爆弾 → 爆風 → プレイヤー → 炎 → 粘膜爆弾 →
粒子）。手本は、描く関数を直接呼んで1枚を描く `render/art/frame.py` の `draw_frame` です。
同じ盤面を両方で描き、見た目の乱数に同じ値の列を差して、画素で比べます
（`tests/presentation/test_renderer.py`）。部品ごとに 8 ビットへ丸めてから重ねるので、縁の
画素は最大 64 段まで違いえますが、縁でない画素は丸めの幅に収まります。

### 落とし穴の、不透明度の戻し忘れ

原型の drawPlayer は、落とし穴にはまったプレイヤーを描くと、外側の `save` を戻さずに帰り
ます。そのフレームのそのあとに描くもののうち、不透明度を自分で決めないもの（あとに描く
プレイヤーとその舌・掘る身ぶり、炎の火の玉）が、そのプレイヤーの不透明度で描かれます。
はまったプレイヤーが点滅していると、あとのプレイヤーまで薄く見えます。

不具合ですが、原型の絵なので写しました。手本の `draw_frame` は命令どおりに戻し忘れ、
`Renderer` はプレイヤーを貼るたびに「描いたあとの不透明度」を受け取り、次のプレイヤーと炎へ
渡します（`baked/players.py` の `PlayerSprites.draw`）。TypeScript 版は戻し忘れません。

### 試合の状態に無い、見た目だけの値

原型は、歩いた距離（walk）・最後に動いた時刻（lastMoveAt）・被弾の揺れ（hurtFlash）・
粘膜爆弾を投げた位置（sx・sy）・炎の通った跡（trail）・粒子・画面の揺れを、プレイヤーや
盤面の物の項目として持ち、update の中で書き換えていました。この版のルールの層はどれも
持ちません。試合の結果に関わらないものを入れると、通信対戦で突き合わせるものが増えるため
です。

描く側の `SceneTracker`（`render/scene/tracker.py`）が、1 tick 進めるたびに、進めたあとの
盤面とその tick のイベント（`SimEvent`）を受け取って数えます。決まりは3つです。

- **盤面が進んだ tick にだけ進める。** 原型の loop は、描くのは毎フレームでも、進めるのは
  遊んでいる間だけです。決着のあとの待ちの間は、粒子も揺れの減りも止まり、揺れが 0.2 を
  超えたまま止まっていれば、止まった盤面が揺れ続けます。この版も同じにしました
- **ラウンドが替わったら全部忘れる**（原型の startRound も粒子と揺れを捨てる）
- **試合の状態は読むだけ。** 描く前と後で状態の要約が変わらないことを、CPU どうしの試合を
  決着まで毎 tick 描いて確かめています（`test_render_match.py`）

粒子と揺れは、原型で出していた場面ごとに、イベントから作ります（`scene/effects.py`）。
イベント1つでは場面が決まらない所は、前後のイベント・盤面・前の tick の控えで見分けます
（`scene/clues.py`）。たとえば、落ちたアイテム（`ItemDropped`）は、すぐ前が被弾で強くなる系の
アイテムなら吐き出したもの（煙を出す）、壊れたブロックから出たものなら煙を出しません。突進が
抱えた悪いアイテム・炎が寿命で消えたことには、ルールの層のイベントがありません。前の tick に
あって消えたアイテムや盤面の物から見つけます。

爆発の揺れは、爆発を何が起こしたか（`Exploded.cause`）で決めます。導火線（連鎖も、粘膜爆弾が
降りて起こした爆弾も）は連鎖の揺れ、突進が起こした爆弾は連鎖の揺れと 7 の大きいほう、降りられ
なかった粘膜爆弾の爆風だけの爆発は揺らしません（原型の explodeChain・updateCharge・slimeBurst）。
前の tick の導火線の残りでは、導火線の残りが 1 の爆弾に突進が当たったときと、同じ tick に鼻水で
爆弾を消したマスで粘膜爆弾が爆ぜたときを取り違えるので、ルールの層のイベントに印を足しました。

## 音：Web Audio の予定を仕様の式で読み、起動時に焼く

音は `presentation/audio/` にあります。流れは4段です。

1. 表（`recipes.py`・`added_recipes.py`・曲は `score.py`）：原型の `SE` と `BGM` の数値と式を
   そのまま書く（半音の表に書き換えない。どこで原型から離れたかを追えなくなるため）
2. 値の動き（`voices.py`）：原型の `tone()`・`noiseBurst()` が Web Audio に入れていた予定。
   固定値と、部品の種類・値の予定・止める時刻まで同じかを確かめる
3. 合成（`synth.py`・`oscillator.py`）：予定を Web Audio の仕様に書かれた式で、標本1つずつ
   読む（値の予定・波形・削る仕組み・ノイズ）
4. 焼く（`bank.py`・`music.py`）：起動時に pygame の Sound に焼いておき、鳴らすときは
   再生するだけ

焼いておくのは、鳴らすたびに合成すると長い音（優勝のファンファーレなど）は1つに 18 ミリ秒
ほどかかり、1フレームに収まらないためです。37 個を焼いて 0.2 秒ほどです。曲は 16 刻みで
1周する繰り返しなので、1周ぶんを焼いて専用のチャンネルで繰り返します。

鳴らす場面はイベントから決めます（`presentation/presenter.py`。[04](04-イベントを戻り値で返す.md)）。

## 原型に合わせて TypeScript 版と違えた所

| | 原型とこの版 | TypeScript 版 |
|---|---|---|
| 爆弾の脈打ち | ラウンドの経過時間に、爆発が近づくほど上がる周波数を掛けて位相を作る | 置いてからの時間で作る（経過時間が長いと、1 tick ごとの位相の飛びが大きく、脈打ちがばらばらに跳ねて見えるため） |
| 秒読みの 0 秒 | 0 秒でも鳴らす | 0 秒の tick に鳴る引き分けの音と重なるので鳴らさない |
| 同じ音を続けて鳴らす | まとめない（1回しか鳴らさない所は、場面を見分けて1回にする） | 0.03 秒以内の同じ音を1回にまとめる |
| 落とし穴の不透明度の戻し忘れ | 写す（上の節） | 戻し忘れない |
| 炎の通った跡 | 炎の絵の一部（1マス進むたびに元のマスを足す） | 4 tick おきに光の粒子を置く |

## 原型と違うまま残した所

| | 原型 | この版 | 残した理由 |
|---|---|---|---|
| マスの継ぎ目 | 塗る命令ごとに覆う割合で重ねるので、継ぎ目に背景が透けて細い線が出るはず | 透けない（手本の `draw_frame` と同じ） | 手本は2倍のまま重ねる。ブラウザの重ね方は、窓も無い所では確かめられない |
| 落とし穴の戻し忘れが、フレームをまたぐ場合 | はまったプレイヤーが同じフレームに2体いて、先に描くほうが点滅していると、フレームを描き終えても不透明度が戻らず、次のフレームから背景まで薄く描かれる（前のフレームの絵が透けて残る） | フレームの中だけ写す | この版はフレームごとに背景から描き直す。窓の大きさを変えるまで続く、原型の不具合 |
| 画面の揺れのずれ | 小数の px | 整数の px に丸める（0.5px まで） | 取っておいた絵を、絵を変えずに貼るため |
| 体・舌・粒子などの位置、続けて変わる見た目の値 | 小数のまま描く | 整数の px・段に丸める（上の表） | 毎フレーム描き直すと間に合わない |
| tick の途中の位置 | 描くたびに、経過時間で進めた位置 | tick の境目に合わせて描き、補間しない | README の Design Choice 7. |
| 粒子の並び | 突進が抱えた悪いアイテムの煙・炎が消えたときの煙は、その場面の処理の中で出す | その tick の粒子の最後に足す | イベントが無く、ほかの粒子とのあいだのどこで出たかが分からない。重なる順が変わるだけ |
| 歩いた距離（脚の振りの位相） | 動けたら、その tick の速さを足す | 同じ。ただし、跳んだ tick・押しのけられた tick・突進が柱で止まった tick に歩いていても足さない。その tick の初めに技で状態がかかった（舌で引き寄せたバナナなど）ときも、前の tick の状態で速さを出す | 前の tick との比べでは見分けられない。脚の振りの位相が1回ぶん違うだけ |
| 文字・絵文字の形 | ブラウザの書体（system-ui）で描く | pygame で Apple Color Emoji を読んで縮める。日本語の書体は使っていない | `canvas/text.py` |
| 音の波形 | ブラウザが帯域を制限した波形・ブラウザの乱数のノイズ | 仕様の式で合成する。標本1つずつは同じにならない | 仕様が実装に任せている所（`synth.py`） |
| 外周の葱ボン・一時停止の幕 | 描く | まだ描かない | 葱ボンはルールだけ段階 8 で入れた（絵と音・知らせは段階 8 のあとの段で写す）、画面の文字は段階 10 |
| 大きい画面での盤面の大きさ | マスを 96 まで広げる | 描く面はマス 60 まで。pygame の SCALED は整数倍でしか広げないので、拡大するのは画面の縦が描く面の 2 倍以上あるときだけ。2560×1440 相当でマス 60（原型は 69）、3840×2160 を等倍で使うとき 60（原型は 96） | マス 96 は描画が間に合わない（README の Design Choice 1.）。整数でない倍率で広げる設定は、実機の窓で見た目と重さを確かめてから決める |
| CPU のとくぎの長押しのゲージ | CPU は長押しを数えない（actHold を増やすのは手で操作するプレイヤーだけ）ので、出ない | CPU が技のボタンを押した tick にも、チキンを持っていれば1フレーム出る | いまは CPU を窓に出していない。段階 10 で CPU を窓に出すときに、CPU のプレイヤーにはゲージを出さない形にする（`art/player.py` の `gauge_progress`） |

⚠️ 窓を開いて見たことも、音を鳴らして聞いたこともありません。テストは SDL の dummy
ドライバで、窓を開かずに描いた絵の画素を見て、音の出口を開かずに焼いた音の配列を見ています。
