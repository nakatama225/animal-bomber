# 葱ボンと延長戦

段階 8 で、倒れたあとの遊び方が2つ入ります。

- **葱ボン**：倒れたプレイヤーは、残り時間が1分より多ければ盤面の外周へ回り、外周を
  動きながら葱を撃ちます。盤面のプレイヤーに当てると入れ替わり、撃った側が盤面へ戻ります
- **延長戦**：時間切れで2人以上残ったときと、残っていた全員が同じ tick に倒れたときに、
  1ラウンドに1回だけ延長戦に入ります

この章で身につける判断は1つです。**状態を閉じた union で持ち、その状態のときだけ意味を
持つ値を、その状態の中にだけ置く。** 持つべきでない値を、型の上で持てなくします。

いまこの版に入っているのは、3つの状態の形・葱ボンのルール・延長戦です。外周にいる CPU の
操縦と、盤面の CPU が飛んでくる葱をよける規則は、まだありません（外周にいる CPU は何も
しない）。外周のプレイヤーと飛んでいる葱の絵、葱ボンの音と知らせも、まだ写していません
（[08-絵と音](08-絵と音.md)）。

---

## 状態を閉じた union で持つ

プレイヤーが試合にどういう形で加わっているかは3つあります。盤面の上で戦っている・外周を
回っている（葱ボン）・退場した。外周を回っている間だけ、外周の上の位置と、次の葱を撃てる
時刻が要ります。

原型は、状態を文字列（`'ALIVE' | 'NEGIBON' | 'OUT'`）で持ち、外周の位置と撃つ間隔を
プレイヤーの別の項目に持っていました。そのため、盤面にいるプレイヤーにも外周の位置と撃つ
間隔が残っていました。読む側は「いまはどの状態か」を確かめてから読むことを、毎回覚えて
おく必要があります。

この版は、状態ごとに型を分け、外周の値は外周の状態（`Negibon`）にだけ持たせます
（`domain/state/player.py`）。

```python
@dataclass(frozen=True, slots=True)
class Alive:
    """盤面の上で戦っている。"""


@dataclass(frozen=True, slots=True)
class Negibon:
    """倒れたあと、盤面の外周を回って葱を撃っている（葱ボン）。"""

    along: float  # 外周に沿った位置
    ready_at: Tick  # 次の葱を撃てるようになる盤面の時刻


@dataclass(frozen=True, slots=True)
class Out:
    """退場した。"""


Life: TypeAlias = Alive | Negibon | Out
```

盤面にいるプレイヤーの状態は `Alive` で、`along` という項目がそもそもありません。外周の
位置を読むには、`match` で `Negibon` の枝に入る必要があります。

```python
life = player.life
match life:
    case Negibon(along=along, ready_at=ready_at):
        ...  # ここでだけ along と ready_at が読める
    case Alive() | Out():
        ...
    case _:
        assert_never(life)
```

`Negibon` の枝の外で `player.life.along` と書くと、型検査（mypy）が失敗します
（`Alive | Negibon | Out` のうち `Alive` と `Out` に `along` が無い）。実行しても、
盤面にいる状態には外周の位置がありません。

```python
>>> from animal_bomber.domain.core.tick import Tick
>>> from animal_bomber.domain.state.player import ALIVE, OUT, Negibon, life_name
>>> lane = Negibon(along=12.5, ready_at=Tick(210))
>>> life_name(ALIVE), life_name(lane), life_name(OUT)
('alive', 'negibon', 'out')
>>> lane.along
12.5
>>> ALIVE.along
Traceback (most recent call last):
  ...
AttributeError: 'Alive' object has no attribute 'along'

```

どれも frozen なので、中身を書き換えずに丸ごと差し替えます（外周を進むたびに新しい
`Negibon` を作る）。盤面の状態（`ALIVE`）と退場の状態（`OUT`）は中身が無いので、全員で
1つを使い回します。書き換えられないので、使い回しても、あるプレイヤーへの変更がほかの
プレイヤーに漏れません。

状態を1つ足すと、状態で分ける `match`（盤面にいるかを見る `is_alive`・状態の名前の
`life_name`・状態の要約の `_hash_life`・TypeScript 版と比べる行の `life_row`）の
`assert_never` で型検査が失敗します。段階 5 の動物（[06-動物の技と閉じた種類](06-動物の技と閉じた種類.md)）
と同じ仕組みです。

## TypeScript 版との対比：判別可能ユニオン

TypeScript 版も同じ3つの状態を union で持ちます（`ts/src/domain/state/Life.ts`）。違うのは、
種類の見分け方です。

| | TypeScript 版 | Python 版 |
|---|---|---|
| 種類の印 | 項目 `kind`（`'alive'`・`'negibon'`・`'out'`）。判別可能ユニオン | クラスそのもの。`kind` の項目は無い |
| 種類で分ける | `switch (life.kind)` で分け、最後に `never` へ代入する | `match` でクラスの形に当て、最後に `assert_never` |
| 書き換えない約束 | 項目を `readonly` にし、`ALIVE`・`OUT` を `Object.freeze` する | `frozen=True` の dataclass |
| 状態の名前（要約と記録） | `life.kind` をそのまま使う | `life_name` が `match` で返す |

TypeScript の型は実行するときには消えるので、実行中に種類を見分けるには、値の中に印
（`kind`）を持たせるしかありません。Python のクラスは実行中も残るので、`match` がクラスで
見分けられ、印の項目は要りません。イベント（[04-イベントを戻り値で返す](04-イベントを戻り値で返す.md)）
と同じ考え方です。その代わり、状態の名前の文字列が要る所（状態の要約・TypeScript 版と
比べる行）のために、名前を返す関数（`life_name`）を1つ置きます。

どちらの版も、「外周の位置を持ってよいのは外周の状態だけ」を型で決めています。持てない
値を、持たないように気をつける必要がありません。

## 盤面の処理は、盤面にいるかだけを見る

動く・爆弾を置く・技・拾う・被弾は、盤面にいるプレイヤーだけを扱います。どれも
`is_alive`（`Alive` なら True）を見て、外周を回っているのか退場したのかは見ません。
外周のプレイヤーを扱うのは、外周の処理だけです。

例外が1つあります。原型は、倒れても伸ばしていた舌を消さず、盤面にいる間しか進めない一方で、
焼けたかの確かめは状態を問わず全員について見ます（L4320-4322・L4395）。倒れたあとに止まった
舌の上へ爆風が来ると焼けて、そのラウンドの舌が短くなります。この版も、振る舞いの性質に
「盤面を離れても止めて残す」（`ActionTraits.stays_off_board`。舌だけが持つ）を足し、
この性質を持つ振る舞いだけは、盤面にいない間は進めずに止め、焼けたかは見続けます
（`systems/actions.py` の2か所）。共通の処理は性質だけを見て、舌という名前は書きません。

## 外周の処理をどこに置くか

外周の処理は、状態の形のほかに4つのモジュールに分けてあります。

| モジュール | 持つもの |
|---|---|
| `domain/rules/lane.py` | 外周の帯の形。帯の上の位置（`along`）と盤面の座標・撃つ向きの対応、倒れた位置にいちばん近い位置、押した向きを帯の上で進む向きに直すこと |
| `domain/systems/negibon.py` | 外周へ回る（`send_to_lane`）・外周を動いて撃つ（`lane_step_for`）・葱で入れ替わる（`swap_places`）・外周を閉じる（`close_lanes_if_due`） |
| `domain/state/actors.py` | 飛んでいる葱の状態（`Leek`。盤面の物の1つ）と、葱を作る `shot_from_lane`・閉じるときに消すかの `ends_with_lanes` |
| `domain/abilities/negibon.py` | 葱を 1 tick 進め、ぶつかったものを調べる（`advance_leek`） |

決め手は、試合を進める処理（`domain/systems/`）の2つの決まりです。盤面の物の種類の名前を
書かない（`tests/boundary/test_closed_kinds.py` が失敗する）。`domain/abilities/` を import
してよいのは、技を呼び分ける `actions.py` と盤面の物を進める `actors.py` だけ（ほかから
import すると、読み込みが循環する）。外周を動いて撃つ処理は `systems/` にありますが、撃つ
瞬間に葱を作る必要があります。葱を作る所を `abilities/` に置くと import の決まりを破り、
`systems/` に置くと名前の決まりを破ります。そこで、葱を作る関数を状態の側
（`state/actors.py` の `shot_from_lane`。返す型は盤面の物の union の `Actor`）に置きました。
状態の側はもともと種類を知っている場所で、`systems/` はどちらの決まりも破らずに呼べます。
外周を閉じるときに飛んでいる葱だけを消すのも、種類を見分けず、状態の側の性質
（`ends_with_lanes`）を見ます。動物の振る舞いが `traits_of` の性質で割り込むのと同じ形です。

葱が飛んで当たる処理は、ほかの盤面の物と同じく `abilities/techniques.py` の
`advance_actor` が振り分けて `abilities/negibon.py` を呼びます。当たって入れ替わるときは
`systems/negibon.py` の `swap_places` を呼びます（技が `systems/` の基本の操作を呼ぶのと
同じ向きで、循環しない）。

1 tick の中では、外周のプレイヤーは盤面のプレイヤーと同じ入力の輪の中で番号の順に動いて
撃ち（撃った葱はその tick に1歩進む）、葱は落とし穴のあと・追いかける炎の前に進み、外周を
閉じるのは tick の最後です（`systems/simulation.py` の番号つきの説明）。どれも原型を測った
答えと比べています（`tests/systems/test_tick_order.py`）。

## 外周の位置は、JavaScript と同じ道筋で巻き戻す

外周の位置は小数で、毎 tick 足して `0` 以上 `72` 未満に巻き戻します。TypeScript 版は
`((t % L) + L) % L` と書きます。Python の `%` は、割る数と同じ符号の余りを返すので、この
式をそのまま写すと答えが違います。

```python
>>> import math
>>> from animal_bomber.domain.rules.lane import LANE_LENGTH, wrap_along
>>> -1e-20 % LANE_LENGTH
72.0
>>> wrap_along(-1e-20)
0.0
>>> math.fmod(math.fmod(-1e-20, LANE_LENGTH) + LANE_LENGTH, LANE_LENGTH)
0.0

```

`math.fmod` は JavaScript の `%` と同じく、割った余りを丸めずに返します。`wrap_along` は
この形で書き、外周の位置を巻き戻す所はどこもこの関数を通します。範囲の内の値でも、`72` を
足すときに丸めて最後の桁が変わることがあるので、止まっている tick にも通します（TypeScript
版も毎 tick 通すため）。値は node で計算した JavaScript の答えと突き合わせています
（`tests/systems/test_negibon.py`）。

## 状態の要約と、TypeScript 版と比べる行

状態の要約（`state/world.py` の `hash_world`）は、状態の名前を混ぜ、外周の状態のときだけ
外周の位置と撃てる時刻を続けます（TypeScript 版の `hashLife` と同じ形）。TypeScript 版と
比べる行（`tests/ts_rows.py` の `life_row`）も同じ並びで、`["alive"]`・`["out"]`・
`["negibon", 位置, 時刻]` です。

葱は、盤面の物の要約（`state/actors.py` の `encode_actor`）の中で初めて小数を持つものです。
比べる行は要約の文字列ごと突き合わせるので、小数は JavaScript の数を文字列にしたときと同じ
書き方にします（整数の値に `.0` を付けない、など）。

TypeScript 版と比べる固定値には、2人を外周から始めて撃ち合う台本を足しました
（`tests/systems/test_simulation_ts.py` の `test_外周から撃ち合う台本も_TypeScript版と同じ結果になる`）。
外周を動いて撃つ・葱が柱と爆弾と爆風で止まる・射程を越えて落ちる・入れ替わる・倒れて外周へ
回る・外周が閉じる、を通ります。

## 原型・TypeScript 版と違うまま残したもの

- 1/60 を小数で引き続けて原型が1フレーム遅れるもの（撃つ間隔・戻った直後の無敵・葱の寿命・
  7:00 の設定で外周が閉じる時刻）は、実数で数えた tick のまま（TypeScript 版と同じ）
- 押した瞬間の取り方：原型はキーが押し下がるたびに次のフレームまでためるので、同じ役のキーの
  重ね押しや1フレームより短い押しでも撃つ。この版は tick ごとに押しているかを比べるので
  撃たない（TypeScript 版と同じ。爆弾と技のボタンも同じ）
- 外周の位置から盤面の座標を出す式は TypeScript 版に合わせた（`1.5 + t`。原型は
  `1 + t + 0.5`）。足す順が違うと最後の桁が違うことがある

## 延長戦：ラウンドの判定も閉じた union で返す

ラウンドが決まったかの判定（`domain/systems/round.py` の `judge_round`）は、3つの答えの
どれかを返します。続ける（`Continue`）・延長戦に入る（`GoToSuddenDeath`。わけと加わる
プレイヤーを持つ）・終わる（`RoundOver`。勝ったプレイヤーとわけを持つ）。プレイヤーの状態と
同じく、答えごとに持つ値を分けた閉じた union です。延長戦に加わるプレイヤーの一覧は、
延長戦に入る答えにだけあります。

| 盤面にいるプレイヤー | 判定 |
|---|---|
| いない | 同じ tick に2人以上倒れていれば延長戦、でなければ引き分け |
| 1人 | そのプレイヤーの勝ち。時間が残っていても待たない |
| 2人以上 | 時間切れなら延長戦、延長戦のあとの時間切れなら引き分け |

延長戦は1ラウンドに1回だけです。試合の設定で切ってあれば（`MatchConfig.sudden_death`）、
延長戦の代わりに引き分けにします。受け取る側（`app/session.py` の `GameSession`）は
`match` で3つとも扱い、最後に `assert_never` を置きます。TypeScript 版は `type` の文字列で
見分ける判別可能ユニオン（`RoundVerdict`）を `switch` で扱います。

延長戦に入るとき（`domain/systems/sudden_death.py` の `enter_sudden_death`）は、盤面を
作り直さずに片付けて使います。壊せるブロック・爆弾・爆風・アイテム・盤面の物を取り除き、
加わるプレイヤーを番号の順に開始位置の表の隅へ移して、体力を爆風1回ぶん・爆弾と火力と
靴を上限にします。作り直さないので乱数を引かず、延長戦に入った試合だけ以降の抽選がずれる
ことがありません。決着ではないので、決着のあとの待ちは挟まず、判定と同じ tick のうちに
入ります。

延長戦に入ると、時間切れの時刻を置き直します。そのため時間切れは、試合の設定の制限時間
ではなく、盤面の `WorldState.ends_at` で見ます（設定の値は延長を知らない）。状態の要約にも、
この時刻と延長戦に入ったか（`WorldState.sudden_death`）を混ぜます。倒れた知らせ
（`PlayerDown`）は倒れた位置（`at`）を運びます。同じ tick のうちに延長戦へ入ると、受け
取る頃にはプレイヤーが開始位置へ移っているためです。

TypeScript 版と比べる試合の台本（`tests/app/test_session_ts.py`）は、時間切れで延長戦に
入る・2人が同じ tick に倒れて延長戦に入る・延長戦も時間切れで引き分けになる、を通ります。
決定性の台本（`tests/determinism/scenario.py` の `play_match(sudden_death=True)`）も延長戦を
通り、hash の種を変えた2つのプロセスで突き合わせます。
