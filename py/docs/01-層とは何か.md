# 層とは何か

原型では、ゲームのルール・画面の描画・実時間の3つが1つの関数の中で混ざっていました。
この版は7つの層に分け、**依存を一方向に固定**しています。

```text
app          … 配線だけ。判断を持たない
shell        … ウィンドウ・キーボード・ゲームパッド・フレームの回し方（実時間を読んでよい）
presentation … 絵・音・画面に出す文
net          … 通信対戦
ai           … CPU の思考
content      … 動物などのデータ
domain       … ゲームのルール（何にも依存しない）
```

上の層は下の層を使えます。逆はできません。

層の数は TypeScript 版と同じ7つで、名前が違うのは1つだけです。TypeScript 版の
`platform`（ブラウザの API を触ってよい層）にあたるものを、この版では `shell` と
呼んでいます。入出力を持たない中身を、入出力を持つ外側で包む形は「functional core,
imperative shell」と呼ばれ、この層はその外側（shell）にあたります。Python 版には
ブラウザという決まった土台（platform）が無く、外側を自分で書くので、こちらの名前にしました。

---

## なぜ一方向なのか

**依存の向きが、その層を単独で動かせるかどうかを決める**からです。

`domain/` が `presentation/` を知らなければ、画面を用意せずに `domain/` を動かせます。
これは次の3つを同時に可能にします。

- 1万試合を画面なしで回してバランスを測る
- 入力の列だけを保存して試合を再現する
- 盤面ではなく操作だけを送って通信対戦する

逆に、ルールの中から描画を1回でも呼んでいると、この3つはすべて
「画面を巻き込んだまま実時間で回す」ことになります。原型がそうでした。

## 境界を、規約ではなく仕組みにする

### TypeScript 版では3つの仕組みが要った

ブラウザの API（`document`・`window`）も、`Math.random()`・`Date.now()` も、
import しなくても最初からどこでも使えます。そのため TypeScript 版は、ルールの層だけ
型定義から DOM を外す設定（型検査）、`Math.random` などの呼び出しを禁じる lint
（ESLint）、層の import の向きを見る検査（dependency-cruiser）の3つを別々に置いています。

### Python では import の検査で足りる

乱数（`random`）も時刻（`time`・`datetime`）も pygame も、**使うには必ず import が
要ります**。ルールの層に入り込む経路は import の1つだけです。だから import を
検査すれば、TypeScript 版で3つの仕組みに分けていたものを1つの考え方で扱えます
（import を使わずに結果を変えてしまう書き方は残ります。下の「import では止められないもの」）。

import そのものを禁じたモジュール（`random`・`time` など、`tests/boundary/banned_names.py` の
`MODULES_BANNED` の 8 つ）は、2つの検査で重ねています。見ているものが少し違います。

| | 何を見るか | 設定 |
|---|---|---|
| ruff の規則 TID251（禁じた import と関数を見つける） | `import random` のような書き方を、1行ずつ見る。`math.sin(x)` のような属性の呼び方も見つける。禁じた理由をそのまま出力に出せる | `pyproject.toml` の `[tool.ruff.lint.flake8-tidy-imports.banned-api]` |
| import-linter | ファイルをまたいだ import のつながりを見る。層の向きと、ルールの層が何を import しているか | `pyproject.toml` の `[tool.importlinter]` |

ruff は行末に `# noqa` と書けば黙ります。import-linter はその注記を読まないので、
ruff を黙らせても import-linter が失敗します（`tests/boundary/test_guards.py` が
これを確かめています）。

`os`・`math` の一部の関数（`MEMBERS_BANNED`）は、import-linter が属性を見られないので
ruff だけで止めています。ここは行末の `# noqa: TID251` で黙らせると、どの検査も失敗しません。

ruff の禁止は**全体に掛けて、使ってよい層（`presentation`・`shell`・`app`）だけを外して**います。
逆向き（禁じる層を1つずつ足す）にすると、新しい層を作ったときに足し忘れて、
禁止が効かないまま進みます。import-linter の禁止（`source_modules`）のほうは、
逆に禁じる層を1つずつ足す形です。`content`・`ai` を作ったときに足し忘れても、
全体に掛かっている ruff のほうが失敗します。

### 禁じた関数、禁じなかった関数

禁じる基準は4つです。乱数の出どころ・実時間の出どころ・描画・環境で結果が違いうる計算。

| 禁止 | 理由 |
|---|---|
| `random` / `secrets` / `os.urandom` / `os.getrandom` | 乱数は `Rng` を引数で受け取る。見た目だけの乱数は描画の層で標準の `random.Random` を使う |
| `uuid` | 識別子を乱数や時刻から作らない。`IdSource` で連番を取る（同じ入力なら同じ識別子になる） |
| `time` / `datetime` / `os.times` | 時間は tick（1/60 秒ごとの固定の刻み）の回数で数える |
| `pygame` / `numpy` | ルールの層は描画と音を知らない。計算は標準の四則演算で書く |
| `math` の三角関数・双曲線関数・指数と対数の関数・累乗と立方根・誤差関数・ガンマ関数、`cmath` | 結果の最後の桁が実行環境で食い違うことが規格上許されている |
| `math.hypot` / `math.dist` | 同じ理由。距離は `math.sqrt(dx * dx + dy * dy)` と書く |

禁じた名前の一覧は `tests/boundary/banned_names.py` の `MODULES_BANNED` と
`MEMBERS_BANNED` が正で、`pyproject.toml` の設定がこれと等しいことを `test_guards.py` が確かめています
（`MEMBERS_BANNED` は ruff だけで見ています）。
`os` と `math` は丸ごとは禁じていません。`os.path` や `math.floor` まで使えなくなるためです。

`math.sqrt` と四則演算は**禁じていません**。こちらは浮動小数点数の規格（IEEE 754）が
正確な丸めを求めているため、同じ入力なら環境をまたいでも同じ値になります。
ここを区別せずに「浮動小数点は危ないから固定小数点にする」と進むと、
必要のない大きな複雑さを抱えることになります。

### import では止められないもの

Python には、import を使わずに結果を変えてしまう書き方があります。起動のたびに
変わるものと、TypeScript 版と食い違うものです。

| 書き方 | 何が起きるか | どう止めるか |
|---|---|---|
| 文字列の集合（`set`）を順に取り出す | 取り出す順が、プロセスを起動するたびに変わる。並びを決める文字列の hash（文字列から計算する整数）が起動ごとに変わるため | 同じ処理を、hash の種を変えた2つのプロセスで走らせて突き合わせる（`tests/determinism/test_hashseed.py`） |
| 組み込みの `hash()` を状態の要約に使う | 同じ理由で、起動ごとに違う値になる | 要約は FNV-1a（バイトを1つずつ混ぜていく短い要約の作り方）で自前に組み立てる（`domain/core/statehash.py`）。`hash()`・`id()` の呼び出しは構文木の検査が見つける |
| `round()` で小数を丸める | 偶数への丸めなので `round(2.5)` が 2 になる（TypeScript の `Math.round` は 3） | ルールの層では丸めを使わない。体力のように丸めたくなる値は整数で持つ。構文木の検査が見つける |
| `**`・`pow()` で小数を累乗する | `math.pow` と同じ C の `pow` を通り、環境ごとに最後の桁が違いうる。指数が整数でも同じで、macOS では `x ** 2` が `x * x` と食い違う値がある | `x * x` と掛け算で書く。整数の定数どうし（`2**32`）以外は構文木の検査が見つける |
| `sum()` で小数を足す | Python 3.12 で合計の出し方が変わり、3.11 と値が違う（`sum([0.1] * 10)` が 3.11 では `0.9999999999999999`、3.12 からは `1.0`） | `for` で1つずつ足す。整数の合計と見分けられないので、`sum()` はどちらも構文木の検査が見つける |

構文木の検査は `tests/boundary/test_builtins.py` にあります。ruff の TID251 は import と
`math.sin` のような属性しか見ないため、組み込みの関数と演算子はこちらで見ます。

1つ目がいちばん厄介です。原因が「順序」なので、症状が出るまで時間がかかり、
出たときには原因から遠く離れた場所で壊れて見えます。そのため検査のほうも、
わざと `set` を順に取り出す処理を走らせて、**2つのプロセスで結果が変わること**を先に確かめています。
これが変わらないなら、hash の種を変えられておらず、突き合わせは何も見ていません。

⚠️ いま突き合わせているのは乱数と状態の要約だけです。1試合ぶんのリプレイが
できた段階で、突き合わせる処理をそれに差し替えます。
