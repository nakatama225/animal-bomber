# 通信対戦（ロックステップ）

段階 9 で、同じ LAN にいる 2〜4 台の Mac で、1つの試合を遊べるようにしました。

この章で身につける判断は1つです。**入力の窓口を1つ足すだけで、通信対戦になる。**
試合の側（`app/session.py` の `GameSession` とルールの層）には、通信のための分岐を
1つも足していません。段階 1 で操作の出どころを窓口1つ（`InputSource`）に絞り、段階 4 で
キーボードとゲームパッドを、段階 6 で CPU を、同じ窓口に繋いできたので、ここで足すのは
通信で届いた操作を流す窓口（`NetworkInputSource`）だけです。

決め方は TypeScript 版（[ts/docs/05-通信対戦](../../ts/docs/05-通信対戦.md)）と同じで、
中継サーバ（[server/](../../server/)）も同じものを使います。この章では、Python で形を
変えた所を中心に書きます。

---

## 盤面を送らず、操作だけを送る

原型の LAN 対戦は、ホストの1台だけが試合を進め、毎フレーム盤面を丸ごとゲストへ配って
いました（ホスト権威）。原型は乱数を 43 か所で1本のまま引いていて、同じ操作から同じ試合に
なる保証が無かったためです。

この版は段階 1 から、同じ種と同じ操作からは必ず同じ試合になるように作ってあります。そこで
**全員が手元で同じ試合を進め、送り合うのは 1 tick ぶんの操作だけ**にしました（ロックステップ）。

| | 原型（ホスト権威） | この版（ロックステップ） |
|---|---|---|
| 試合を進める端末 | ホストだけ | 全員 |
| 送るもの | 盤面の全体を毎フレーム | 1 tick ぶんの操作（1通 50 バイトほど） |
| ホストが抜けたら | 試合を続けられない | 続けられる（抜けたプレイヤーは CPU が受け持つ） |
| 端末ごとの違い | 起きない（盤面を上書きする） | 起きたら見つけて止める |

## 約束の表は、中継と物理的に1つ

メッセージの種類と項目の名前の表（`FROM_PEER`・`FROM_RELAY`・`REPORT_FIELDS`）は、
中継サーバのパッケージ（`animal_bomber_server.protocol`）のものを、そのまま import します
（`net/protocol.py`）。`py/pyproject.toml` で `server/` を直に指して依存にしてあるので、
中継を直せば、こちらにもそのまま入ります。

TypeScript 版は同じ表を `ts/src/net/protocol.ts` にもう一度書き、中継のテストがそのファイルを
文字列として読んで突き合わせます。この版は中継と同じ言語なので、表を写しません。写さなければ、
写したほうだけが古くなることが起きません。

この版が書くのは、表の項目をどの型で持つかと、読むときの確かめです。送るもの4種と届くもの
7種を、frozen な dataclass の閉じた union にしました。型と表が食い違っていないかは、
`tests/net/test_protocol.py` が両向きに見ます。

- 書き出す向き：この版が書き出す項目が、表の項目と同じか
- 読む向き：表の項目名だけで組んだメッセージを読めるか。1つでも欠ければ断るか

片方の向きだけだと、この版が古い項目名で読み書きしていても、もう片方が通ってしまいます。
さらに、本物の中継の部屋（`LockstepRoom`）にこの版のメッセージを流し、届いたもの全種類を
この版で読めることも確かめます。

### Python が黙って読んでしまうものも断る

読めないメッセージは `ProtocolError` で止めます。読み飛ばすと、足りない項目を待ったまま
試合が止まり、原因が「通信が遅い」に見えるためです。TypeScript 版の確かめに加えて、
Python が黙って受け付けてしまうものを断ります。

| 届いたもの | Python がそのまま読むと |
|---|---|
| 整数の項目に `true`・`false` | `bool` は `int` の仲間なので、1・0 として通る |
| 整数の項目に `1.0` | `float` のまま通る |
| `NaN`・`Infinity`・`1e400` | `json` が無限大として読む |
| 負の数の入力のビット | `PlayerInput` が補数として受け付ける（-1 は7つのボタン全部） |
| 1〜4 匹の外の動物 | 盤面を作る所まで進んでから止まる |

試合の設定（`LanSettings`）は、TypeScript 版の `lanSettingsFrom` と同じ形で書き、同じ
下限で読みます。制限時間は 1 tick 以上で、0 や負の値（秒から直すときに負の秒数を渡した、
など）は断ります。開始位置の並びは書かず、付いていても読みません（原型の `setupPlayersLan`
と同じく、プレイヤー番号の順に4隅から始める）。

## 1 tick の進め方（`net/lockstep.py`）

1. tick T を進める前に、人間全員の tick T の入力が届いているかを見る。1人でも届いて
   いなければ、進めずに待つ
2. 届いていれば、自分の操作を読んで **tick T+3 の入力**として送る
3. 全員の tick T の入力で、試合を 1 tick 進める
4. 20 tick ごとに、状態の要約と、試合の乱数を引いた回数を中継へ送る

始めた直後は、最初の 3 tick ぶんの入力を、始まった時点で押している内容で埋めて送ります。
これが無いと、tick 0 の入力は誰も送らないので、全員が互いを待ったまま止まります。何も
押していない入力で埋めないのは、ホストが始める合図に押した Enter（爆弾のキーでもある）が
tick 0 に「離した」として届き、tick 3 に「押した瞬間」として届いて、開始位置に爆弾を置く
ためです。

試合が終わったあとも、盤面を止めたまま tick を数え、何も押していない入力と要約を送り
続けます。やめると、試合を決めた決着が端末ごとに食い違ったときに、中継の突き合わせが
揃わず、ずれに気づけません。

### 試合はこのクラスの中で作る

`LockstepDriver` は、試合（`GameSession`）を作り方（`create_session`）から自分で作り、
人間のプレイヤー全員（自分も含む）に `NetworkInputSource` を繋ぎます。作る側の書き忘れに
任せないためです。自分のプレイヤーにキーボードを直に繋ぐと、自分の手元でだけ操作が早く
試合に入り、試合がずれます。

### 時刻は試合通算の tick

通信と記録の時刻には、試合通算の時刻（`MatchTick`）を使います（[02-時間の刻みと記録](02-時間の刻みと記録.md)）。
盤面の時刻（`world.now`）はラウンドごとに 0 へ戻り、決着のあとの待ちの間は止まるためです。
`LockstepDriver` は自分の `MatchClock` で数え、進めるたびに試合の時刻と揃っているかを
確かめます。3 tick 先の入力を送る所は、`MatchClock.after(3)` で時刻を作ります
（`MatchTick` の値を作ってよい場所を増やさないため）。

## 抜けたプレイヤーは、窓口の中で CPU に替わる

回線が切れたプレイヤーの操作は、端末ごとに届いたところまでが違いえます。中継が、その
プレイヤーの操作を最後に配った tick（`lastTick`）を全員に知らせ、全員がその次の tick から
CPU に替えます。

TypeScript 版は、進める側（`LockstepDriver`）が試合の窓口を繋ぎ替えます（`attach`）。
この版は、**窓口（`NetworkInputSource`）の中で、届いた入力の記録の `replaced_at` を見て
替えます**。記録を流す窓口（`ReplayInputSource`）も同じ判定で替えるので、通信対戦で届いた
入力の記録を1台の試合で流し直しても、本物の端末と同じ tick で CPU に替わります。試合の側に
窓口を差し替える口を足さずに済みます。

CPU は、初めて任せる tick に作ります（`net/input_log.py` の `Replacement`）。本物の端末が
替えるのは `lastTick` の次の tick ですが、そこが決着のあとの待ち（入力を集めない）に当たると、
作るのはもっと後になります。CPU は作るときに盤面を読まず、自分の乱数しか引かないので、
いつ作っても同じ手を指します。

## 段階を閉じた union で持つ（`net/client.py`）

中継につないでから試合が終わるまでの流れ（`LockstepClient`）は、接続中・待っている・試合中・
止まった、の4つの段階を、frozen な dataclass の閉じた union で持ちます（`Connecting`・
`Lobby`・`Playing`・`Failed`）。画面の側は `match` で分け、段階を足すと、扱いを書き忘れた
分岐を mypy が見つけます（[09-葱ボンと延長戦](09-葱ボンと延長戦.md) と同じ形）。

止まった段階は、試合の最中に止まったときに限り、止まる直前の試合（`played`）を持ちます。
ずれや切断で止まっても、盤面と名札を残したまま理由を出すためです。

## ソケットは入出力の層に閉じ込める（`shell/relay_link.py`）

通信の層（`net/`）はソケットを持たず、送る口（`PeerLink`）と、届いた文字列を受け取る関数
だけを知ります。そのため、通信の層のテストは、中継の代わり（`tests/net/fake_relay.py`）で、
同じプロセスの中に何台ぶんでも立てられます。

中継とつなぐ実物は `websockets` の同期版で書き、スレッドを自分では立てません。

- 受け取りは、ライブラリが裏で立てるスレッドが続けていて、中継からの生存確認への返事も
  そこで返します。こちらはフレームごとに、届いているものを待たずに吸い出すだけです
  （`drain`。`recv(timeout=0)`）。描いている間に返事が遅れて、中継に切られることはありません
  （中継は1秒ごとに生存確認を送り、2秒返事が無ければ切ります）
- つなぐときだけは待ちます（長くて 5 秒）。つなぐ前に、出るかもしれない5匹の絵を描いて
  おきます。つないだあとに描くと、その間ほかの端末がこの端末の入力を待って止まります
- 中継は、入れない接続（試合が始まっている・定員いっぱい）を番号 1013 で閉じます。閉じた
  番号を残し、ただ切れたときと見分けて「前の試合が続いているか、定員いっぱいで入れなかった」
  と出します

## 画面のループ（`app/main.py` の `run`）

1台で遊ぶ試合（`app/runner.py` の `LocalMatch`）と通信対戦（`app/lan.py` の `LanMatch`）を、
同じ形（`MatchRunner`）で回します。違いは「次の tick を進めてよいか」と、盤面の外に出す文だけ
です。

- 入力が揃っていない tick は進めず、そのフレームの残りの時間は捨てます。tick は全員の入力が
  揃ったときだけ進むので、時間を捨てても相手と試合はずれず、遅れた端末をほかの端末が待つ
  だけになります
- 押してすぐ離したキーは、読んだ tick のあとで忘れます。進めなかったフレームで忘れると、
  読まれないまま消えます
- 曲は、試合の最中でなくなったら止めます（ずれ・切断で止まったとき）
- 始まる前は盤面の代わりに数行を、試合中は盤面の下に1行を出します
  （`presentation/lan_status.py` が文を作り、`presentation/render/lan_screen.py` が描く）。
  「操作を待っている」は、待ちが 0.5 秒ほど続いたときだけ出します（一瞬の待ちで文が
  ちらつかないように）

⚠️ ロビーで設定を選ぶ画面は段階 10 で作ります。いまは、ホストが Enter を押すと、既定の
設定（4つの枠の動物はうさぎ・かえる・きつね・ぞう、CPU はふつう、3勝で優勝）で始めます。

## 検査

| 確かめること | テスト |
|---|---|
| 約束の表とこの版の型（両向き）・読めないものを断ること・本物の中継が送るもの全種類を読めること | `tests/net/test_protocol.py` |
| 同じ試合になる・3 tick 遅れて使う・待つ・進める速さが違っても同じ・4台・ずれを見つける・決着の食い違い・抜けたプレイヤー・記録の流し直し・同じ接続での次の試合 | `tests/net/test_lockstep.py`（TypeScript 版の `lockstep.test.ts` と同じ場面） |
| 接続中から試合が終わるまでの流れ | `tests/net/test_client.py` |
| 本物の中継とつなぐ・生存確認に返事をして切られない・断られた番号 | `tests/shell/test_relay_link.py` |
| 文字列の hash の種が違う2つのプロセスで、本物の中継を通して試合を通す・抜けたら CPU に替わる | `tests/net/test_relay_peers.py` |
| 画面のループ（始まる前の文・揃わない tick を進めない・押した瞬間を残す・待ちの案内・曲を止める） | `tests/app/test_main.py`・`tests/app/test_lan.py` |

「食い違い 0 件」だけでは何も確かめていないことがあります。1 tick も進まなくても、全員が
何もしなくても、CPU を繋ぎ忘れても、要約は一致するためです。そこで、比べた tick の数・
相手の操作が届いて動いたこと・CPU が動いたことを別に確かめます。抜けたプレイヤーには、
CPU が選ばない押し方（上下左右を全部）をさせておき、CPU に替わった tick を、試合が使った
入力で見分けます（TypeScript 版のレビューで見つかった空振りを避ける形）。

2つのプロセスの検査は、Mac 2台の代わりです。2台は文字列の hash の種
（`PYTHONHASHSEED`）を変えたプロセスで動かすので、ルールの層に set の反復が紛れ込むと、
2台の試合がずれて中継が知らせます（[README の Design Choice の 4.](../README.md)）。

## 遊び方

中継サーバを1台の Mac で立て、各 Mac でこの版を `--relay` を付けて起動します。

```sh
uv --directory ../server run python -m animal_bomber_server   # 中継（8777 番）
uv run python -m animal_bomber.app.main --relay                # 中継を立てた Mac（1P・ホスト）
uv run python -m animal_bomber.app.main --relay <中継を立てた Mac の名前>.local   # ほかの Mac
```

- 中継を立てた Mac が 1P（ホスト）になります（中継は、同じ Mac からつないだ端末を 0 番に
  する）。その Mac で起動しないと、誰も試合を始められません
- 全員がつながったら、1P が Enter で始めます。人間のいない枠は CPU が受け持ちます
- 試合が決まったら、1P がもう一度 Enter を押すと、同じ顔ぶれ・同じ設定のまま次の試合が
  始まります（接続は保ったまま）
- 途中で抜けたプレイヤーの枠は、CPU が引き継ぎます
- ずれや切断で止まったとき、新しく加わる端末があるときは、**全員が窓を閉じてから**起動し
  直します。
  中継は、前の試合にいた端末が1つでもつながっている間は、新しい接続を断ります
- ポートを変えた中継には `--relay <名前>:<ポート>` でつなぎます

⚠️ TypeScript 版（ブラウザ）と、この版を同じ部屋に混ぜないでください。2つは試合の始まりから
盤面が違います（この版は全員が下を向いて始まり、TypeScript 版は下の隅のプレイヤーが上を
向く。`py/AGENTS.md` の「イベント」）。混ぜると、最初の突き合わせ（tick 19）で中継がずれを
知らせて止めます（混ぜて試したことはありません）。

⚠️ 2台の Mac で通信対戦をしたことは、まだありません。確かめたのは、同じ Mac の中の
2つのプロセスと本物の中継までです。
