# 歩き方

原型は「動くもの」を最短で作りました。この版は、TypeScript 版と同じく
**同じゲームを、境界を引き直して作り直したもの**です。移植ではありません。

TypeScript 版との違いは、**同じ問いに Python で自然な答えを出す**ことにあります。
設計の考え方（ルールと画面を分ける、時間の進みを固定する、入力の出どころを1つにまとめる）
は同じでも、それを実現する形は言語ごとに変わります。どこが同じで、どこが変わったかを、
段階ごとにこの docs に残します。

コードから読むなら `src/animal_bomber/domain/` から始めてください。ここには
画面も実時間も通信も出てきません。いまは、ルールの下に敷く部品（乱数・座標・時間の単位・
識別子・状態の要約）と、盤面・プレイヤー・移動・入力・爆弾・爆風・アイテム・被弾・ラウンドの
終わり・動物の技（`domain/abilities/`）・外周の葱ボン・延長戦があります。1 tick 進める入口は
`domain/systems/simulation.py` の `step()`、ラウンドをまたいで試合を進める入口は
`app/session.py` の `GameSession` です。CPU は `src/animal_bomber/ai/` にあり、入口は
`ai/source.py` の `CpuInputSource` です。絵と音は `src/animal_bomber/presentation/` にあり、
1フレームを描く入口は `presentation/render/renderer.py` の `Renderer`、見た目だけの値を
数える入口は `presentation/render/scene/tracker.py` の `SceneTracker` です。通信対戦は
`src/animal_bomber/net/` にあり、試合を進める入口は `net/lockstep.py` の
`LockstepDriver`、中継につないでから試合が終わるまでの流れは `net/client.py` の
`LockstepClient` です。

## 段階ごとの主題

実装は段階に分けて進めています。各段階には**その段階で身につく判断が1つ**あり、
それが次の段階の作業を減らします。

| 段階 | 動くもの | その段階の主題 |
|---|---|---|
| 0 | 骨組み・描画の重さの測定（作る前に測る） | 境界を、規約ではなく検査で守る |
| 1 | 1人が歩く・操作を記録して流し直せる | 固定間隔の時間と、注入された乱数 |
| 2 | 爆弾・誘爆・ブロック破壊 | 処理ごとのモジュール（`domain/systems/`）への分業。`step()` が順序の一覧になる |
| 3 | アイテム・被弾 | 起きたイベントを戻り値で返す。種類の分岐を `match` で網羅する |
| 4 | 2人で遊べる | 操作の出どころを1つの窓口にまとめる |
| 5 | 5匹の動物 | 閉じた形（union）で表し、対応の書き忘れを型検査で見つける |
| 6 | CPU | 判断を、優先順に並べた関数の組に分ける |
| 7 | 絵と音 | 移植でよい所と、設計し直す所の区別（描く命令と音の数値は原型を逐語に写し、毎フレームの描き方と鳴らし方は pygame で間に合う形に作り直す） |
| 8 | 葱ボン | 状態を型で表す |
| 9 | 通信対戦 | ロックステップ。窓口を差し替えるだけで済むことの確認 |
| 10 | タイトル・設定 | 画面に何を出すかと、どう写すかを分ける |
| 11 | 配布 | macOS のアプリにまとめる |

## この実装での約束

3つあります。いずれも**人が気をつけて守る形にしていません**。破ると検査が失敗します。

### ルールの層は画面を知らない

`src/animal_bomber/domain/` では `pygame` を import できません。
書くと ruff と import-linter が失敗します。

### ルールの層は実時間と乱数を自前で取らない

`random`・`secrets`・`uuid`・`time`・`datetime` などを import できません。乱数は `domain/core/rng.py` の
`Rng` を引数で受け取り、時間は tick（1/60 秒ごとの固定の刻み）の回数で数えます。

### 依存は逆流しない

下の層が上の層を import すると、import-linter が失敗します。
層の順番は [`pyproject.toml`](../pyproject.toml) の `[tool.importlinter]` にそのまま書いてあります。

## 検査が効いていることを、どう確かめているか

設定を書いただけでは、それが効いているかは分かりません。設定の書き方を
間違えていても、違反が無ければ検査は緑のまま通ります。**緑のまま通る検査は
何も防いでいません。**

そのため [`tests/boundary/test_guards.py`](../tests/boundary/test_guards.py) は、
テストの中で次の4つを順に行います。

1. 禁じた書き方を含む使い捨てのファイルを、`src/` の下に実際に書き出す
2. 本物の検査コマンド（`ruff` / `lint-imports` / `mypy`）を実行する
3. コマンドが失敗すること、出力に書き出したファイルと違反した規則が名指しされることを確かめる
4. 書き出したファイルを消す

| テスト | 書き出す場所と中身 | 失敗するはずの検査 |
|---|---|---|
| ルールの層で禁じたものを使う | `domain/` に、禁じた名前をすべて1行ずつ import する（`import random`・`from math import sin` など） | ruff（規則 TID251。禁じた名前ごとに、禁じた理由の文も出る） |
| `math.sin(x)` の形で呼ぶ | `domain/core/` に `math.sin(0.5)` | ruff（TID251） |
| ruff を注記で黙らせても | `domain/` に、import を禁じたモジュールをすべて import する（先頭に `# ruff: noqa`） | import-linter（ルールの層の import の禁止。モジュールごとに名指しされる） |
| ルールの層から描画の層を import する | `domain/core/` に `import animal_bomber.presentation` | import-linter（層の向き） |
| 層の一覧に無い場所にモジュールを置く | `animal_bomber/` の直下に空のファイル | import-linter（層の向き。`exhaustive = true`） |
| `match` で種類を1つ書き忘れる（戻り値を返さない形） | `domain/core/` に、2種類のうち1つしか扱わない `match` | mypy（`exhaustive-match`） |
| 操作の記録の時刻に、盤面の時刻を渡す | `net/` に、`world.now` で記録する1行 | mypy（`Tick` と `MatchTick` は別の型） |
| docstring の形を崩す | `domain/core/` に、要約が次の行・要約が2行に折れる・閉じが本文と同じ行、の関数を1つずつ | ruff（D212・D205・D209） |
| 描画の層で乱数と実時間を使う | `presentation/` に `import random`・`import time` | ruff も import-linter も失敗**しない**（禁止が層を選んで効いていること） |

最初のテストは何も書き出さず、3つの検査が**エラーなく終わる**ことを確かめます。
これが無いと、上の表のテストが失敗したとき、原因が書き出したファイルなのか、
もともとコードにあった別の違反なのかを区別できません。

禁じた名前の一覧は [`tests/boundary/banned_names.py`](../tests/boundary/banned_names.py) が
持っていて、`pyproject.toml` の設定がそれと等しいことも確かめます。設定から禁止を1つ消したり、名前を打ち間違えたりすると失敗します。

import を使わない書き方（`round()`・`hash()`・`sum()`・小数の `**` など）は ruff でも
import-linter でも見つからないので、[`tests/boundary/test_builtins.py`](../tests/boundary/test_builtins.py)
がルールの層のファイルを構文木（ast）にして探します。探し方が正しいことは、違反した文字列を
渡して見つかること、正確に決まる計算（`2**32`・`x * x`）は見つからないことで確かめています。

## 動かし方

```sh
uv sync
uv run tools/verify.sh   # ruff → 整形 → mypy → import-linter → pytest（3.12 と 3.11）
uv run python tools/bench_render.py   # 描画の重さを測る（本物の描画の層で描く。窓は開きません）
uv run python tools/bench_pacing.py   # フレームの間の待ち方を比べる（窓は開きません）
```

```sh
uv run python -m animal_bomber.app.main   # 2人で遊ぶ（1P は WASD・Space、2P は矢印・Enter）
```

通信対戦は、中継サーバを1台の Mac で立ててから、各 Mac で起動します（詳しくは
[10-通信対戦](10-通信対戦.md) の「遊び方」）。

```sh
uv --directory ../server run python -m animal_bomber_server   # 中継（8777 番）
uv run python -m animal_bomber.app.main --relay                # 中継を立てた Mac（1P・ホスト）
uv run python -m animal_bomber.app.main --relay <中継を立てた Mac の名前>.local   # ほかの Mac
```

いまは段階 9 まで（通信対戦。段階 8 までの葱ボンと延長戦のルール・外周の CPU・外周の鍋と葱の
絵と音を含む）で、原型の絵と音で遊べます（窓を開いて見たこと・音を鳴らして聞いたこと・2台の
Mac で通信対戦をしたことはまだありません。
葱ボンと延長戦の知らせは、画面の文字と一緒に段階 10 で出します）。CPU はテストで試合を回せますが、画面から CPU を相手に選ぶ所はまだありません
（段階 10）。名札・時計・ラウンドの間の画面も段階 10 で、いまは盤面の上の1行に、ラウンド・
勝ち数・体力を出しています。測った結果と決め方は [README の Design Choice](../README.md) に
あります。ルールの層は REPL から動かせます（[02-時間の刻みと記録](02-時間の刻みと記録.md) の
最後の節）。
