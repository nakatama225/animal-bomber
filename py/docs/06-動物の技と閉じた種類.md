# 動物の技と閉じた種類

段階 5 で、5匹の動物（うさぎ・ぞう・もぐら・きつね・かえる）がそれぞれの技を持つように
なりました。足したのは、動物ごとの数値の違い（速さ・火力・体力・爆弾の数・アイテムの
効き方）と、技のボタンで出す通常技ととくぎ、技を出したあとに動き続けるもの（突進・穴掘り・
舌・落とし穴・炎・跳ねる爆弾・撒く本体・焼けた舌）です。

---

## 種類を閉じる：増やしやすさと、漏れの無さの交換

同じ問いに、TypeScript 版と Python 版は逆の答えを出しています。

| | TypeScript 版 | Python 版 |
|---|---|---|
| 動物の表し方 | 共通の interface（`Ability`）を実装したものを、登録表に1行足す | 列挙（`rules/animals.py` の `Animal`）。種類で分ける所は `match` |
| 6匹目を足すと | 既存のファイルを1行も触らずに済む | `match` を書き足す所が出る。書き忘れると型検査（mypy）が失敗する |
| 扱いの書き忘れ | 実行するまで分からない | 型検査が見つける |

```python
def hold_technique(animal: Animal) -> Technique:
    match animal:
        case Animal.RABBIT:
            return rabbit.start_scatter
        ...
        case _:
            assert_never(animal)  # 種類を足して書き忘れると、ここで mypy が失敗する
```

どちらが正しいかではなく、何を手放して何を得たかの違いです。TypeScript 版は「増やしやすさ」
を取って「漏れの無さ」を手放し、この版はその逆を取りました。種類で分ける `match` は
`domain/abilities/techniques.py`（技と、振る舞い・盤面の物の進め方）と
`rules/animals.py`（数値）、`state/actions.py`・`state/actors.py`（性質と要約）に集めて
あり、6匹目を足すときにルールの層で書き足す場所はそこだけです。ほかに、技の音を当てる
`presentation/presenter.py` にも動物で分ける `match` があります（書き忘れると同じく
mypy が失敗します）。

## 突進の確かめ：共通の処理は種類を見ない

ぞうの突進は、移動・破壊・取得・被弾の4つに同時に割り込みます（柱に当たるまで直進し、
ブロックを壊し、通り道のアイテムを掃き、受ける傷が減る）。いちばん特別扱いを誘いやすい
振る舞いです。それでも、試合を進める処理（`domain/systems/`）には突進という言葉があり
ません。処理が見るのは、振る舞いの性質（`state/actions.py` の `traits_of`）だけです。

```python
@dataclass(frozen=True, slots=True)
class ActionTraits:
    drives_movement: bool  # 移動の入力を受け付けない（この振る舞いが位置を決める）
    damage_cap: int | None  # 受ける傷の上限
    can_place_bomb: bool  # 最中に爆弾を置けるか
    sweeps_items: bool  # 足元のアイテムを、ふつうの拾いでは拾わない
```

これが守られているかは、`tests/boundary/test_closed_kinds.py` が文字列で見張ります
（`domain/systems/`・`domain/query/`・`domain/events.py` に、動物の名前と、振る舞い・
盤面の物のクラスの名前が現れたら失敗）。名前を書かずに種類を見分ける書き方（名前の
文字列を返す `action_name` との比較、`isinstance`・`hasattr` など）も失敗にします。
性質で書けない振る舞いが出てきたら、性質を足します。

## 状態と振る舞いを分ける

TypeScript 版は、突進の残り時間や抱えたアイテムを、振る舞いのクラスの中に隠しています
（`#remaining` など）。この版は、進み具合を値を持つだけの dataclass にして `state/` に
置き、1 tick 進める振る舞いを `abilities/` に置きました。

- `state/actions.py`：`Charge`・`Dig`・`Tongue`（プレイヤーを乗っ取る振る舞い）
- `state/actors.py`：`Pit`・`Foxfire`・`SlimeBomb`・`Scatter`・`BurntTongue`（盤面の物）
- `abilities/`：動物ごとのモジュール（`elephant.py` など）と、振り分け（`techniques.py`）

状態が振る舞いを import しないので、プレイヤーの状態（`state/player.py`）が振る舞いの
型を持っても読み込みが循環しません。中身が見えるので、状態の要約（`hash_world`）に
振る舞いの中身まで混ぜられ、TypeScript 版と比べるテストも中身ごと突き合わせられます。

## 技のボタン：押した長さで分ける

1つのボタンで2つの技を出します。押して離すと通常技、押し続けてしきい値に届くととくぎ
（チキンを1つ使う）。しきい値はぞうだけ 1.5 秒、ほかは 0.5 秒です。

- 通常技は**離した瞬間**に出します（原型は押した瞬間）。押した瞬間に出すと、とくぎを
  出すつもりで押すたびに通常技も出てしまいます
- ラウンドの始まりに押していたボタンは、一度離すまで数えません（`ACTION_LOCKED`）
- 泣いている・落とし穴にはまっている間は技を出しません。離した瞬間に出す形なので、
  押し始め・しきい値に届いたとき・離したときの3か所で見ます（`systems/actions.py`）

技を進めるのと始めるのは分けてあります。全員の振る舞いを進め（1人ずつ、そのすぐあとに
「勝手に設置」）、そのあとでボタンを見て新しく始めます。原型の更新の順と同じで、番号の
大きいプレイヤーの突進が、番号の小さいプレイヤーの置いた爆弾を同じ tick に起こす順まで
揃います。

## TypeScript 版と、tick ごとに比べる

段階 5 の値は、TypeScript 版を原型に合わせ切ったもの（37ac1a7）から写して出しました。
この版にまだ無いもの（倒れたあとの外周＝段階 8、延長戦）は写しの側で止めます。もう1つ、
写しでは全員が下を向いて始まる形にします。この版は原型と同じく全員が下を向いて始まり、
TypeScript 版は下の隅のプレイヤーが上を向いて始まります。段階 5 からは、歩く前に出した
技の向きがこれで決まるので、揃えないと比べられません。そのうえで同じ台本を流して
20 tick ごとに盤面とイベントを比べます（`tests/systems/test_simulation_ts.py`・
`test_techniques_ts.py`・`tests/app/test_session_ts.py`）。技を通す台本は3つ
（とくぎ・舌と撒く・体当たり）で、どれも乱数を引く回数まで一致しています。
原型の値（原型を画面なしで動かして測ったもの）は、動物ごとのテスト
（`tests/abilities/`）が場面ごとに確かめます。

始まりの向きのほかに、TypeScript 版と違えた所が1つあります。アイテムの効果の倍率
（かえるは2倍）を、効く側のプレイヤーから引く形にしました（`systems/items.py` の
`apply_item`）。原型も同じ形で、
突進で悪いアイテムを押しつけられたかえるにも2倍で効きます。TypeScript 版は倍率を
呼ぶ側が渡すので、この場面では倍率が掛かりません。
