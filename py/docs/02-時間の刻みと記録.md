# 時間の刻みと、操作の記録

段階 1 の主題は、時間を固定の刻み（tick）で進めることと、試合の乱数を種から作って
ルールの層へ渡すことです（[00-歩き方](00-歩き方.md) の段階の表）。この2つがそろうと
「同じ種と同じ操作からは、必ず同じ試合になる」が成り立ちます。それを確かめる道筋として、
操作を記録して流し直す仕組みも作りました。通信対戦（段階 9）は、この仕組みのおかげで
操作だけを送れば済むようになります。

## 乱数は種から作り、ルールの層へ渡す

[`create_world(seed, animals)`](../src/animal_bomber/domain/state/world.py) は、種から
乱数（[`core/rng.py`](../src/animal_bomber/domain/core/rng.py) の `Rng`）を作り、その乱数で
盤面の壊せるブロックを置きます。乱数は試合の状態（`WorldState.rng`）に入っていて、
ルールの層は `random` を import できません。そのため、同じ種からは同じ盤面ができます。
TypeScript 版も同じ乱数の作り方と同じ引く順なので、同じ種から同じ盤面になります
（`tests/state/test_board.py` が TypeScript 版の出した盤面で確かめています）。

## 時間は tick で進む

原型の `update(dt)` は、前のフレームからの経過秒数を受け取っていました。そこに倍速の
つまみの値まで掛かっていたので、1回の描画で内部の処理が何回まわるかが実行環境で変わり、
「倍速にすると1回のキー入力が2〜3回として処理される」不具合が出ました。

この版の [`simulation.step()`](../src/animal_bomber/domain/systems/simulation.py) は
経過時間を受け取りません。1回呼ぶと 1 tick（1/60 秒に当たる）進みます。速さは呼ぶ
回数で表し、倍速は回数を増やすだけ、一時停止は呼ばないだけになります。実時間を tick の
回数に換えるのは、ルールの層の外の1か所だけです（段階 1 の後半で作る、フレームを回す輪）。

移動の当たり判定は、速いときに1回の移動を細かく分けます。原型はこの細かさを時間を
進める単位と同じにしていたので、導火線も入力の読み取りも一緒に分かれました。この版では
分けるのは移動の中だけです（[`systems/movement.py`](../src/animal_bomber/domain/systems/movement.py)）。

## 盤面の時刻と、試合通算の時刻

時刻は2種類あり、別の型にしています（[`core/tick.py`](../src/animal_bomber/domain/core/tick.py)）。

| 型 | 数えるもの | 使う所 |
|---|---|---|
| `Tick` | 盤面の時刻（`world.now`）。段階 4 からラウンドごとに 0 へ戻る | 導火線・無敵の残りなど、ラウンドの中のこと |
| `MatchTick` | 試合通算の時刻（試合が始まってから数えた tick） | 操作の記録、通信で送る入力 |

TypeScript 版は初め盤面の時刻で記録していたため、2ラウンド目の記録が「tick が戻って
いる」として止まり、あとで直しました。この版は最初から型を分けてあるので、`world.now` を
そのまま記録の時刻の所へ渡すと mypy が失敗します（`tests/boundary/test_guards.py` で、
その書き方を実際に書き出して確かめています）。`MatchTick(world.now)` と包んで渡すと
mypy は通るので、`MatchTick` を作るのは試合通算の時刻を数える1か所とテストだけにします。

## 操作の記録と流し直し

ルールの層が受け取る操作は、1 tick ぶんのプレイヤーの入力（`PlayerInput`。押している
ボタンの組）だけです。キーボードか、CPU か、通信で届いたか、記録から流しているかを
区別しません。入力を返す窓口（`InputSource`）はどれも同じ形で、`InputGatherer` が
プレイヤーごとの窓口から入力を集めます。

[`net/input_log.py`](../src/animal_bomber/net/input_log.py) の `InputLog` は、入力が
変わった時点だけを記録します。記録する窓口（`RecordingInputSource`）でほかの窓口を包むと
遊びながら記録でき、記録を流す窓口（`ReplayInputSource`）で記録を流し直せます。通信対戦
では、記録を流す窓口を、届いた操作を流す窓口に差し替えます。

`PlayerInput` は `enum.IntFlag` で、押しているボタンの組をビットで持ちます。型そのものが
1バイトに収まる整数なので、TypeScript 版のように真偽値を1バイトに詰める関数を別に書く必要が
ありません。

## REPL で 1 tick ずつ進める

ルールの層は窓も実時間も使わないので、Python の対話の画面（REPL）から読み込んで、1 tick
ずつ進めて中を見られます。描画の層やフレームを回す輪は、窓と実時間が要るのでこうは
いきません。層を分けたので、ルールの層だけを、窓も実時間も無しに動かせます。

この節の `>>>` で始まる行は、検査（`uv run tools/verify.sh`）のたびに pytest が実際に
走らせ、書いてあるとおりの値が出るかを確かめています（`pyproject.toml` の `--doctest-glob`）。

盤面を作り、文字で見ます。`#` は壊せない壁、`o` は壊せるブロック、`.` は通れるマスです。

```python
>>> from animal_bomber.domain.input.player_input import PlayerInput
>>> from animal_bomber.domain.state.world import create_world, hash_world
>>> from animal_bomber.domain.systems import simulation
>>> world = create_world(seed=4649, animals=["rabbit"])
>>> print(world.board)
```

右を押して 1 tick 進めると、うさぎが 3.7 / 60 マスだけ右へ動きます（動物ごとの速さの
倍率は段階 5 で掛けます。原型のうさぎは 1.22 倍です）。

```python
>>> world.players[0].position
Point(x=1.5, y=1.5)
>>> simulation.step(world, {0: PlayerInput.RIGHT})
>>> world.now, world.players[0].position
(1, Point(x=1.5616666666666668, y=1.5))

```

記録を文字列から作り、流し直します。`0:0,8;20,2` は「プレイヤー 0 は tick 0 から右（8）、
tick 20 から下（2）」という記録です。同じ記録を2回流すと、同じ状態の要約になります。

```python
>>> from animal_bomber.domain.core.tick import MatchTick
>>> from animal_bomber.domain.input.sources import InputGatherer
>>> from animal_bomber.net.input_log import InputLog, ReplayInputSource
>>> log = InputLog.decode("0:0,8;20,2")
>>> log.at(MatchTick(19), 0), log.at(MatchTick(20), 0)
(<PlayerInput.RIGHT: 8>, <PlayerInput.DOWN: 2>)
>>> def replay(ticks):
...     world = create_world(seed=4649, animals=["rabbit"])
...     gatherer = InputGatherer([ReplayInputSource(0, log)])
...     for tick in range(ticks):
...         simulation.step(world, gatherer.gather(world, MatchTick(tick)))
...     return world
>>> replay(60).players[0].position
Point(x=2.5, y=1.6233333333333335)
>>> hash_world(replay(60)) == hash_world(replay(60))
True

```

右へ 20 tick 進んだあと、下を押しています。マス (2, 2) は柱なので、下へは柱の手前までしか
進めず、横は通路の中央（x = 2.5）へ寄せられています。
