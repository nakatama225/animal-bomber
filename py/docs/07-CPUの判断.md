# CPU の判断

段階 6 で、CPU（`src/animal_bomber/ai/`）を足しました。CPU は、キーボードやゲームパッドと
同じく **tick ごとに入力（`PlayerInput`）を返すだけ**の窓口（`ai/source.py` の
`CpuInputSource`）です。ルールの層からは、キーボードで遊ぶプレイヤーと区別がつきません。

判断の中身は TypeScript 版の CPU（`ts/src/ai/`）と同じで、どちらも原型の CPU
（`legacy/animal-bomber.html` の `cpuUpdate`・`planCPU`）に合わせてあります。
TypeScript 版と同じ試合を流すと、tick ごとの入力まで一致します（下の「TypeScript 版と、tick
ごとに比べる」）。違うのは、それを Python でどう書いたかです。

---

## 判断の規則は、関数を並べたタプル

原型の判断は、140 行の関数の中に `if` を順に並べたものでした。この版は規則を1つずつ関数に
して（`ai/behaviors.py`）、タプルに並べます（`ai/chain.py`）。

```python
DEFAULT_CHAIN: Final[tuple[Behavior, ...]] = (
    flee,  # 爆風が届くマスにいたら逃げる
    attack_in_line,  # 射線に入った相手を狙う
    collect_item,  # 近くのアイテムを拾う
    hunt,  # 相手に近づく
    break_blocks,  # ブロックを壊しに行く
    wander,  # やることが無ければ歩き回る（かならず計画を返す）
)
```

先頭から順に試し、最初に計画（`CpuPlan`）を返した規則が採られます。**並びの順番がそのまま
優先順位**で、どの規則もほかの規則の存在を知りません。

TypeScript 版は、規則を `CpuBehavior` という interface を実装したオブジェクトにして配列に
並べています。この版の規則は状態を持たないので、クラスにせず関数のままにしました。規則の型は
`Callable[[CpuContext], CpuPlan | None]` の別名（`Behavior`）だけです。

試し方は `for` 文です。`next()` と生成式で「最初に None でないもの」を取る書き方もできますが、
使いません。規則の中で起きた `StopIteration` が、生成式の中では `RuntimeError` に化けます
（PEP 479）。どの規則で何が起きたのかが分からなくなります。

原型で失敗した規則（「袋小路では爆弾を置かない」。開幕はどこも袋小路なので、強い CPU が
40 秒のあいだ1個も置かなくなった）は、並びに関数を1つ差し込むだけで再現できます
（`tests/ai/test_cpu.py` の `test_規則を1つ足すだけで振る舞いが変わる_袋小路では待つと置かなくなる`）。

## 動物ごとの違いは、閉じた `match` で振り分ける

原型の CPU には「もぐらなら」「きつねなら」という分岐が8か所ありました。この版の共通の判断
（`source.py`・`behaviors.py`・`bombs.py`）は動物を知りません。原型の分岐はどれも、次の
6つの差し替える点のどこかに当たります。

| 差し替える点 | 原型の分岐 | 無いとき |
|---|---|---|
| 考える前の技 | 穴を掘る・舌を伸ばす（使った tick はほかに何もしない）・危ないときの突進 | 使わない |
| 歩いたあとの技 | 狐火・粘膜爆弾・撒く | 使わない |
| 爆弾の置き方 | 一列に並べる | 足元に1個 |
| ブロックを壊しに行くときに立つ場所 | 1マス空けた手前に立つ | 壊せるブロックの隣 |
| 壊しに行くときに置くかの見直し | 並べる向きに壊せるブロックが無ければ置かない | 見直さない |
| 振る舞いの最中も考えるか | 突進の最中は考え続ける（掘る・舌の間は待つ） | 待つ |

1匹ぶんの戦い方は、6つの点を持つ凍った dataclass（`ai/tactics.py` の `Tactic`）です。
差し替えない点は `None` のままにします。どの動物の戦い方を使うかは、動物の列挙（`Animal`）を
`match` で振り分け、最後に `assert_never` を置きます。

```python
def tactic_of(animal: Animal) -> Tactic:
    match animal:
        case Animal.RABBIT:
            return RABBIT
        ...
        case _:
            assert_never(animal)
```

TypeScript 版は、戦い方を登録の表に1行足す形です（6匹目を足すのに既存のファイルを触らない）。
この版は、動物を足すとここに扱いを書くまで mypy が失敗します。技の振り分け
（[06-動物の技と閉じた種類](06-動物の技と閉じた種類.md)）と同じ選び方です。

共通の判断のファイルに動物の名前が出てこないことは、`tests/boundary/test_closed_kinds.py` が
見張ります（コメントも含む。戦い方の `tactics.py` だけは外す）。

## 原型の CPU と同じ手を、入力で指す

原型の CPU は操作を経由せず、関数を直に呼んでプレイヤーを動かしていました。この版の CPU は
入力を返します。原型と同じ手になるように、1 tick の中の判断の順も規則も原型に合わせています
（`CpuInputSource._decide` の順は原型の `cpuUpdate` と同じ）。

| 原型の CPU が直に呼んでいたもの | この版の CPU が押すもの |
|---|---|
| `movePlayer`（経路の次のマスの中央へ） | 向き（`ai/follow.py`。着いたと見なす距離・片方の軸だけを押す距離も原型と同じ） |
| `placeBomb` | 爆弾のボタン |
| `foxLineShot`（一列）・`startTongue`（舌） | 技のボタン |
| `useSpecial`（とくぎ） | とくぎを直に出すボタン（`PlayerInput.SPECIAL`） |

とくぎを直に出すボタンは、段階 6 で足した7つ目のボタンです。押した瞬間に、長押しを待たず、
通常技も出さずにとくぎを出します（`domain/systems/actions.py`）。キーボードとゲームパッドには
割り当てていません。原型の CPU は長押しを経ずにとくぎを出していたので、技のボタンを長押し
すると、とくぎの前に通常技が出たり（うさぎが跳ぶ）、ぞうの突進が 1.5 秒遅れたりします。

ルールの層は、入力を 動く → 爆弾 → 技 の順で効かせます。原型の CPU が1フレームの中で
歩く → 置く → とくぎ と呼んでいたのと同じ順です。

### 入力で表せないために残った違い

| | 原型 | この版 |
|---|---|---|
| 操作の反転（悪いアイテム） | CPU には効いていなかった（操作を経由しないため） | 効いてしまうので、CPU が知っていて打ち消す（`compensate_reverse`） |
| とまれない（悪いアイテム） | CPU には効いていなかった | 移動の処理が誰にでもかけるので、CPU も止まれない。入力では打ち消せない |
| きつねの一列の本数 | 手持ち全部で逃げ切れないとき、本数を減らして並べる | 本数は入力に載らないので絞らない。手持ち全部で逃げ切れなければ置かない |
| 同じボタンを続けて押す | 続くフレームで関数を呼べた | ボタンは押した瞬間でしか効かないので、前の tick に押したボタンは次の tick に回す（`CpuContext.can_press`） |
| 判断に使う盤面 | 1フレームの中で、歩いたあと・置いたあとの盤面を見ることがある | tick の始めの盤面だけを見る |

⚠️ きつねの一列のあとの間隔は、この版のルールの層にあって原型にはありません（直すのは
Python 版を一通り作り終えてから）。間隔の最中は一列を並べられないので、CPU は足元に1個置きます。

⚠️ 葱ボン（倒れたあと外周から葱を撃つ）は段階 8 で足します。外周の操縦・飛んでくる葱を
よける規則は、まだこの版にありません。延長戦（段階 8）に入っても、CPU は記憶を捨てません。
記憶を作り直すのは盤面が作り直されたとき（ラウンドが替わったとき）だけで、延長戦は同じ
盤面を片付けて使うためです（原型も、記憶を作り直すのはラウンドの始まりだけ。TypeScript 版と
同じ）。

### 考え直すまでの間隔は tick で数える

原型は、考え直すまでの残りを秒の小数で持ち、毎フレームその秒数を引いていました。小数を
足し引きし続けると、何フレーム目で 0 を切るかが丸めの誤差で前後します。この版は、残りを
tick の整数で持ちます。決めるときに、秒に揺らぎを掛けてから tick に切り上げます
（`math.ceil(秒 × (1 + 揺らぎ) × 60)`。TypeScript 版も同じ）。四捨五入にすると、原型より早く
考え直すことがあります（`test_考え直す間隔は_秒に揺らぎを掛けてから切り上げる`）。

## CPU は盤面を書き換えない

CPU が受け取る盤面は読むだけです。入力を返す前と後で、状態の要約（`hash_world`）が
変わらないことをテストで確かめています。要約には試合の乱数を引いた回数も入っているので、
CPU が試合の乱数に触れていないことも同時に分かります。

CPU は自分専用の乱数（`Rng`）を持ちます。種は試合の種とプレイヤーの番号から作ります
（`cpu_seed`。TypeScript 版の `cpuSeed` と同じ式）。同じ種なら、CPU どうしの試合は何度
やっても同じになります。CPU の判断も set を反復しないことは、hash の種を変えた2つの
プロセスで CPU だけの試合を流して確かめています（`tests/determinism/test_hashseed.py`）。

## 見積もりと実際を、同じ関数にする

CPU は「あと何 tick でこのマスに爆風が届くか」の地図（`domain/query/danger.py` の
`DangerMap`）の上ですべてを判断します。この地図が実際の爆発と食い違うと、CPU は安全だと
思って立った所で倒れます。爆風の届く範囲（`domain/query/blast_reach.py`）を1か所に置き、
爆発の処理と CPU の見積もりが同じ関数を使います。

危ないかは、原型どおり立っているマス（体の中心のマス）だけで見ます。経路は次のマスの中央から
0.15 マス以内に来てから先へ進むので、経路の終わりで立ち止まった体が隣のマスにはみ出すことは
ありません（爆風の当たり判定は中心から 0.14 マス）。

## TypeScript 版と、tick ごとに比べる

`tests/ai/test_cpu_ts.py` は、CPU だけの試合を3つ流し、tick ごとの全員の入力・100 tick
ごとの盤面・その間のイベントを、TypeScript 版から写して出した値（`tests/ai/ts_cpu_values.json`）
と比べます。CPU が乱数を引く順まで同じなので、3試合とも 4000 tick のあいだ入力が1つも
ずれません。写しでは、この版にまだ無い葱ボンを止めています（延長戦は段階 8 で入れたので、
写しも既定どおり入れる。3試合とも、4000 tick のうちには延長戦に入りません）。

原型に合わせた決まり（経路の追い方の距離・置いてよいかの確かめ・動物ごとの技の距離など）は、
`tests/ai/test_cpu.py` が場面ごとに確かめます。決まりを1つずつ書き換えて、どれかのテストが
失敗することも確かめました（46 件のうち 45 件）。失敗しなかった1件は、危ないときは置かない
という確かめを外すものです。危ないときは逃げる規則が先に置く判断を消すので、外しても手が
変わりません。

強さの測定（おに と よわい の勝ち数）は段階 8 で足します。葱ボンと延長戦が無いと、試合の
終わり方が TypeScript 版と違うためです。
