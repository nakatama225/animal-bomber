# legacy — 原型（単一 HTML ファイル）

家族と遊ぶために作った最初の実装です。HTML・CSS・JavaScript がすべて1つの
ファイルに入っています（6,119 行、うち `<script>` が 5,548 行）。

`ts/` と `py/` は、このファイルを設計から作り直したものです。移植ではありません。
ここに原型を残してあるのは、**何を作り直したのかを読み比べられるようにする**ためです。

現在のバージョンは v4.3.0 です。ブラウザで開けばそのまま遊べます。

---

## 中身

| | |
|---|---|
| `animal-bomber.html` | 本体。ゲームのルール・描画・音の合成・LAN対戦のクライアント・画面遷移がすべてここに入っている |
| `animal-bomber-notes.md` | 開発ノート。定数を選んだ理由、実際に踏んだ落とし穴、バージョンの付け方 |
| `test/` | Node で動かすテスト。HTML から `<script>` を取り出して評価する |
| `checklists/` | 実機でないと確認できない項目の一覧。ブラウザで開いて使う |
| `gamepad-stk7043-mapping.md` | ゲームパッドのボタン対応を実機で測った記録 |
| `gamepad-probe.html` | その測定に使ったページ |

LAN 対戦の中継サーバは、このディレクトリではなく [`server/`](../server/) にあります。
Python で書かれており、ゲームのルールを一切持ちません。

## 動かし方

### 1人・2人で遊ぶ

`animal-bomber.html` をブラウザで開くだけです。ビルドも依存パッケージもありません。

### LAN 対戦

同じネットワークにいる別の端末と対戦する場合は、中継サーバを起動します。

```sh
cd server
uv sync
uv run python -m animal_bomber_server
```

起動すると接続用の URL が2種類表示されます。ゲスト側の端末でそれを開くと、
サーバが `legacy/animal-bomber.html` を配信します。**ゲストはホストと同じ
ファイルをダウンロードするため、版のずれが構造的に起きません。**

## テスト

```sh
cd legacy/test
node unit.js      # 255 件：ゲームのルールと画面遷移
node net.js       #  34 件：スナップショットの往復、切断時のCPU引き継ぎ
node sim.js 6     #         CPU同士を6試合走らせてバランスの指標を出す
```

テストは HTML から `<script>` の中身を取り出し、`new Function()` で評価して
内部の関数を取り出す方式です。ビルド手順を持たない単一ファイルに対して
ユニットテストを当てるための仕組みで、経緯は
[`test/README.md`](test/README.md) に書いてあります。

`test/README.md` には、この実装で実際に起こした不具合が 45 件、
再発の条件つきで記録してあります。各テストは過去に壊した箇所を見張るものとして
書かれており、対応する事故の番号がコメントに入っています。

## この実装の構造上の問題

`ts/` と `py/` が何を解こうとしているのかは、ここを読むと分かります。
以下はすべて、この原型を実際に測った結果です。

### 1. ゲームのルール・描画・実時間が1つの関数に混ざっている

`update(dt)` の中から、Canvas への描画、DOM の書き換え、効果音の再生が
直接呼ばれます。`SE.*`（効果音）の呼び出しが 53 箇所、`renderCards()`
（DOM の更新）が 17 箇所あります。

結果として、**ルールだけを取り出して動かす方法がありません**。CPU の強さを
1万試合で測ろうとすると、画面と音を巻き込んだまま実時間で回すことになります。

### 2. 乱数が1本のストリームを共有している

`Math.random()` が 44 箇所にあります。マップ生成・アイテムの抽選・CPU の判断に
加えて、**画面のちらつきや粒子といった見た目だけの処理も同じ乱数を引いています**。

このため、同じ操作を与えても同じ試合になりません。リプレイも、入力だけを送る
通信対戦も成立しないため、LAN 対戦は「1台が計算し、残りは結果を受け取って
描くだけ」という形を採っています。

### 3. 時間の進みが実時間に依存している

`update(dt)` は前のフレームからの経過ミリ秒を受け取ります。しかも
クライアント側の倍速スライダー（0.5〜3倍）がこの `dt` に直接かかります。

1回の描画で内部処理を何回まわすかが実行環境によって変わるため、
「倍速にすると1回のキー入力が2〜3回として処理される」という不具合が
実際に起きました（`test/README.md` の事故 #10）。

### 4. 動物ごとの分岐がコード全体に散っている

動物の特殊能力は、能力を表すフラグ（`jump` / `tongue` / `lineBomb` など）を
使い分ける `if` として、移動・爆弾・被弾・描画それぞれの中に書かれています。
特定の状態を表す文字列との比較も 16 箇所あります。

6匹目を追加するには、散らばった分岐をすべて見つけて手を入れる必要があります。
見落とせば、その動物だけ特定の状況で反応しません。

---

これらは「動くものを最短で作る」ことを優先した結果であり、その判断自体は
目的に照らして誤りではありませんでした。実際にこのファイルは家族が遊ぶ
ものとして成立しています。

困るのは、後から別の要求が来たときです。`ts/` と `py/` は、同じゲームに対して
**境界を先に引いておくと後の作業がどれだけ減るか**を確かめるために書かれています。
