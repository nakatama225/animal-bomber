# animal-bomber テストハーネス

本体は `../animal-bomber.html`（単一HTML・外部依存ゼロ）。
DOM / canvas / WebAudio をスタブして、**ゲームロジックだけを node で回す**。

## 使い方

```sh
cd ~/claude/games/test

# 構文チェック（script タグの中身を抜いて node --check）
python3 -c "
import re
src=open('../animal-bomber.html',encoding='utf-8').read()
m=re.findall(r'<script>(.*?)</script>', src, re.S)
open('extracted.js','w',encoding='utf-8').write(m[-1])
" && node --check extracted.js

# ユニットテスト（164件）
node unit.js

# 試合シミュレーション（優勝まで回す。引数=マッチ数）
node sim.js 6

# 単発の挙動調査（当たり判定などを直接叩く）
node probe.js

# きつねが一列ドン置きで自滅しないか、全マス×全方向を総当たり
node probe-fox-sudden.js

# CPU が往復して戦闘に参加しない問題の観測（強さを引数で指定。既定 futsu）
node probe-fox-cpu.js tsuyo

# CPU の強さ設定が勝率に効いてるか（よわい vs つよい のタイマン）
node probe-cpu-level.js 6

# CPU の自爆率・相手への到達距離（体感を数字にする）
node probe-cpu-strength.js 5

# ⭐ 5匹 × 1レベルを何回もまわして平均を出す（引数: 強さ, 回数）
#    1回の計測は乱数で大きくブレるので、動物どうしを比べるときは必ずこちら
./probe-fox-levels.sh tsuyo 8

# ⭐ 死因の内訳（自爆／他人／ふめい）を動物別に出す（引数: 強さ, ラウンド数）
#    ⛔ 自爆の判定は p.lastHitBy。blastOwner を死亡時に引き直すと、
#       その時点では爆風が消えていて 100% が「ふめい」になる
node probe-death.js oni 60
```

⚠️ **`probe-fox-cpu.js` の既定は `futsu`。** 引数を省くと「ふつう」で測ってしまう。
2026-08-06 の計測がふつうだけだったせいで、「おに では直っていない」ことに
2026-09-23 まで気づかなかった。**強さは必ず明示する。**

⭐ **動物どうしを比べるときは、全レベルを測る。** 2026-09-24 に ふつう と おに だけ見て
「自滅はきつね固有」と結論したが、つよい を足したら ぞうのほうが高かった
（両端だけ見て中間を飛ばすと逆の結論が出る）。

`sim.js` の見どころは **ひきわけ率** と **サドンデス突入ラウンドのひきわけ率**。
サドンデスの発生数は指標にならない（発生しても同時死ならラウンドが空転するだけ）。
**うんこ踏み回数**も出る（1ラウンド2〜4回が平常。CPUはうんこを避けないので、
うさぎのポロポロを強くした時にここが跳ねたら CPU が機能不全になってる）。
**葱ボンの「発射/分」は判定に使わない**（滞在時間で割るので CPU が弱いと勝手に下がる）。
判定は 発射数>0 かつ 命中率>=15%。

## 設計メモ

- `unit.js` は `global.__X` に本体の内部関数を露出させて直接叩く。
  本体の関数名を変えたら export リストも直す（`ReferenceError` で即死するので気づける）。
- `sim.js` は `X.draw()` も毎フレーム呼ぶ。**描画コードの例外は実ゲームだと凍結になる**ので、
  ここで踏み抜くのが目的。外さないこと。
- 倍速はサブステップで回す（`dt` を伸ばすと当たり判定が飛ぶ）。テストも同じ方式で検証してる。

    `ORIG` を変数に持っておいて、戻すときはそれを書くだけにする。

## 注意

**「〜だけ足して」は足すだけにする。**
「1Pに Z、2Pに / を爆弾として足すだけ」の依頼に対して、キー配置を全面的に作り替えて
デグレさせた（2026-08-08）。**変更の範囲を勝手に広げない**。

**CPU の probe は「生存秒」も見る。**
「訪れたマス」は生存時間に比例するので、早死にすると勝手に小さくなる。
一度これを見ずに「往復してるのは probe の測り方のせい」と誤診した。
**生存秒 と 往復/秒 を並べて見る**（`probe-fox-cpu.js` が両方出す）。

**動きがおかしい時は位置を1フレームずつ追う。**
統計（訪れたマス・往復回数）だけでは「何をして往復してるか」は分からない。
1フレームごとに 座標 / mode / 自分の爆弾の位置 / 向き を出すと、
「壊せる物が無い所へ置いて、自分の爆風で押し戻されてる」まで一発で見える。

**CPU の probe は強さを指定して回す。**
既定は `futsu`。作者の報告が「つよい」の話なのに `futsu` を測って「直った」と誤判定した。
`node probe-fox-cpu.js tsuyo` のように**報告された強さで測る**。

**「たまに〜する」は必ず率を測る。**
「つよいでもたまに自爆して死ぬ」を測ったら 100%（死因の全部）だった。
体感の「たまに」は当てにならない。`probe-cpu-strength.js` のように
**分母（全被弾）と分子（自爆）を並べて出す**。

**指標が何を数えてるかを取り違えない。**
`sim.js` のポロポロ占有率は「同時に盤面にある総数＝複数回撒いた累積」で、
1回の範囲の広さではない。1回ぶんは `unit.js` の決定論的な検査で見る。
CPU が強くなって撒く回数が増えるだけで累積は上がるので、閾値は緩め（45%）にしてある。

**確率のからむ CPU テストは、抽選が確実に回る状態にしてから見る。**
`skillReady()` は外れると `a.skillCool` で0.4秒待つので、
リセットせずに60フレーム回すと数回しか引かれず「たまに落ちるテスト」になる。
毎フレーム `a.skillCool = 0` にしてから回す（実測で3連続パスを確認する）。

一括の機械置換（python での範囲 replace）でテストを消し込んだ事故が1回ある。
置換前後で**テスト件数を必ず突き合わせる**。

**画面（DOM）の付け替えはユニットテストで検出できない。**
スタブの `getElementById` は どの id でも要素を作ってしまうので、
id の消し忘れ・書き換え漏れは 全件パスしたまま実ページだけが落ちる。
画面をいじったら**必ずローカルで開いて全画面クリックする**。
補助として「JS が参照してる id が HTML に存在するか」の突き合わせを回す。

**面積・範囲を変える仕様は「盤面に対する割合」で検査する。**
絶対数（○マス置けた）だけ出しても広すぎを判定できない。
`sim.js` の平均値も CPU が滅多に使わない技だと薄まって見えないので、
**ソフトブロック全消しの盤面で1回だけ発動させ、空きマス(245)に対する割合を見る**
決定論的な検査を `unit.js` に置く（`うんこポロポロ 1回の占有率…` がその形）。
新しい検査を入れたら、**わざと壊した値でも落ちるか（逆向き）を必ず確かめる**。
